# Демо этапа 1: от чистой ВМ до восстановленного файла

Сценарий проходит весь путь: сервер Sard из опубликованного образа → вход в
консоль → агент на втором хосте пакетом с сервера → регистрация → репозиторий
→ источник в консоли → бэкап кнопкой → уведомление в Telegram → восстановление
из снимка → сравнение с исходными файлами.

Каждый шаг: **что делать**, **что должно получиться**, **время**, **если не
получилось**. Значения, которые нужно подставить, — в угловых скобках:
`<sard.example.com>`. Подробности по эксплуатации — [docs/operator/](operator/README.md).

> **Время шагов.** Оценки для человека, который выполняет шаги впервые.
> Сценарий прогнан один раз на стенде из контейнеров (сервер в compose, хост
> агента — Ubuntu 24.04 с systemd в контейнере; консоль — тем же REST, что
> использует консоль); время команд того прогона — в таблице «Замеры». На
> чистых ВМ с секундомером его ещё не проходили.

## Что понадобится

| Что | Зачем |
|---|---|
| **ВМ сервера** — Linux amd64 или arm64, 2 ГБ памяти, доступ по SSH, постоянный публичный IP или DNS-имя | sard-server и PostgreSQL в Docker |
| **Хост агента** — Linux с systemd и deb-пакетами (Debian 12/13, Ubuntu 22.04/24.04), доступ по SSH, `sudo` | агент, данные и репозиторий restic |
| **Ноутбук** с SSH и браузером | консоль через SSH-туннель |
| **Telegram** | бот для уведомления (шаг 8) |

Хост агента может быть за NAT (дома): агент сам подключается к серверу, входящие
порты на нём не нужны. Хранилище бэкапов в демо — каталог на диске самого
хоста агента (`/srv/sard-repo`); S3 и SFTP пока прописываются в `repositories` вручную
([хранилища](operator/05a-storage.md)).

## Шаг 0. Подготовка ВМ и имени

**Что делать.**

1. Имя сервера: DNS-запись `A` на IP ВМ сервера (в Cloudflare — только DNS,
   «серое облако»: прокси Cloudflare ломает порт агентов) или просто
   постоянный IP. Дальше это `<sard.example.com>`.
2. Узнайте публичный адрес хоста агента — с него он будет скачивать пакеты:

   ```bash
   curl -fsS https://ifconfig.me; echo      # на хосте агента
   ```

3. Фаервол облака для ВМ сервера: входящие `9090/tcp` — отовсюду (агенты);
   `8080/tcp` — только с адреса хоста агента; `22/tcp` — для SSH.
4. Фаервол на самой ВМ сервера. На образах Ubuntu в OCI iptables по умолчанию
   пропускает только SSH:

   ```bash
   sudo iptables -I INPUT -p tcp --dport 9090 -j ACCEPT
   sudo iptables -I INPUT -p tcp --dport 8080 -s <IP хоста агента> -j ACCEPT
   sudo sh -c 'command -v netfilter-persistent >/dev/null && netfilter-persistent save || true'
   ```

5. Docker на ВМ сервера и синхронизация времени на обеих машинах:

   ```bash
   curl -fsSL https://get.docker.com | sudo sh     # ВМ сервера
   sudo usermod -aG docker "$USER" && newgrp docker
   timedatectl | grep 'synchronized'                # обе машины: yes
   ```

**Что должно получиться.** `docker compose version` печатает версию v2;
`timedatectl` на обеих машинах — `System clock synchronized: yes`.

**Время.** ~10 мин (оценка), в основном установка Docker.

**Если не получилось.** Нет `docker compose` — пакет `docker-compose-plugin`.
Время не синхронизировано — `sudo timedatectl set-ntp true`.
[Требования](operator/01-requirements.md).

## Шаг 1. Сервер из образа

**Что делать.** На ВМ сервера:

```bash
SARD_TAG=v0.0.1-rc.1
SARD_NAME=<sard.example.com>
mkdir -p ~/sard && cd ~/sard
curl -fsSLO "https://github.com/Artur-Abalov/Sard/releases/download/$SARD_TAG/docker-compose.yml"
curl -fsSL -o .env "https://github.com/Artur-Abalov/Sard/releases/download/$SARD_TAG/sard.env.example"
chmod 600 .env
sed -i -e "s/^SARD_DB_PASSWORD=.*/SARD_DB_PASSWORD=$(openssl rand -hex 24)/" \
       -e "s/^SARD_ADMIN_PASSWORD=.*/SARD_ADMIN_PASSWORD=$(openssl rand -hex 16)/" .env
cat >> .env <<EOF
SARD_PKI_SERVER_NAMES=$SARD_NAME
SARD_AGENT_ENDPOINT=$SARD_NAME:9090
SARD_HTTP_PUBLISH=0.0.0.0:8080
SARD_CONSOLE_PUBLIC_URL=http://localhost:8080
SARD_NOTIFY_LANGUAGE=ru
EOF
```

`SARD_HTTP_PUBLISH=0.0.0.0:8080` нужен, чтобы хост агента скачал пакеты с
сервера; доступ к 8080 уже ограничен фаерволом адресом хоста агента (шаг 0).
Консоль всё равно открываем через SSH-туннель (шаг 2).

Telegram (для шага 8): создайте бота у [@BotFather](https://t.me/BotFather)
(`/newbot`), напишите боту любое сообщение и узнайте `chat_id`:

```bash
TG_TOKEN=<токен бота от BotFather>
curl -fsS "https://api.telegram.org/bot$TG_TOKEN/getUpdates" | grep -o '"chat":{"id":-\?[0-9]*'
printf 'SARD_TELEGRAM_BOT_TOKEN=%s\nSARD_TELEGRAM_CHAT_ID=%s\n' "$TG_TOKEN" <chat_id> >> .env
```

Запуск:

```bash
docker compose up -d --wait
curl -fsS http://localhost:8080/api/v1/status; echo
grep '^SARD_ADMIN_PASSWORD=' .env
```

**Что должно получиться.** `docker compose up` заканчивается строками
`Container sard-server-1 Healthy`; статус —
`{"version":"v0.0.1-rc.1","lastVerifiedRestoreAt":null}`. Пароль
администратора сохраните в менеджер паролей.

**Время.** ~3 мин (оценка): скачивание образов ~1,2 ГБ, старт сервера — 13 с
(замер на amd64 после скачивания).

**Если не получилось.** `docker compose logs server` — первая строка
исключения называет переменную ([диагностика](operator/09-troubleshooting.md),
«Сервер не стартует»). `manifest unknown` при скачивании — релиз ещё не
опубликован или пакет в реестре приватный.

## Шаг 2. Вход в консоль

**Что делать.** На ноутбуке:

```bash
ssh -N -L 8080:127.0.0.1:8080 <пользователь>@<sard.example.com>
```

Оставьте туннель открытым, откройте в браузере `http://localhost:8080` и
войдите паролем администратора.

**Что должно получиться.** Главная страница с блоком «Первые шаги»: «Токен
выпущен», «Агент подключился», «Репозиторий инициализирован», «Источник
создан», «Первый бэкап успешен» — пока не отмечены.

**Время.** ~1 мин (оценка).

**Если не получилось.** 403 при входе — консоль открыта не через туннель, а
через прокси с TLS ([TLS и имена](operator/04-tls-and-names.md), «Консоль»).
После перезапуска сервера снова страница входа — так задумано: сессии в памяти.

## Шаг 3. Токен и установка агента пакетом с сервера

**Что делать.**

1. Консоль → «Токены регистрации» → «Создать токен» → подпись `demo-host` →
   создать. Скопируйте токен сразу: он показывается один раз.
2. В окне токена — блок «Установка агента»: архитектура хоста агента
   (`uname -m`: `x86_64` → amd64, `aarch64` → arm64), пакет «deb», скачивать
   через curl.
3. На хосте агента выполните по очереди шаги блока: «Скачайте пакет»,
   «Проверьте контрольную сумму», «Проверьте подпись» (необязательный, нужен
   `minisign`), «Установите агента», «Создайте конфигурацию». У каждого шага
   своя кнопка копирования.

**Что должно получиться.** Проверка суммы печатает `…: OK`; `dpkg -i`
заканчивается подсказкой о следующем шаге; есть `/etc/sard/agent.yaml` с
`address: <sard.example.com>:9090`:

```bash
grep 'address:' /etc/sard/agent.yaml
```

**Время.** ~3 мин (оценка).

**Если не получилось.** Скачивание висит или отказ соединения — порт 8080
закрыт для хоста агента (шаг 0, пункты 3–4) или не задан
`SARD_HTTP_PUBLISH=0.0.0.0:8080` (шаг 1). Сумма не `OK` — файл повреждён,
скачайте снова. Подробно — [установка агента](operations/agent-install.md).

## Шаг 4. Регистрация (enroll)

**Что делать.** На хосте агента — шаг «Зарегистрируйте агента» из консоли
(команда уже с вашим токеном):

```bash
sudo -u sard-agent sard-agent enroll --server <sard.example.com>:9090 --token <токен>
```

**Что должно получиться.** Код выхода 0; в `/etc/sard/tls/` — `ca.pem`,
`agent.pem`, `agent.key`. В консоли токен — «использован».

**Время.** ~1 мин (оценка).

**Если не получилось.** Код выхода называет причину: 3 — токен (истёк,
использован), 5 — доверие (имя сервера не в сертификате, чужой CA), 6 — сервер
недоступен (порт 9090, фаервол). Таблица — [регистрация агента](operations/agent-enroll.md).

## Шаг 5. Репозиторий и копия пароля вне хоста

**Что делать.** В примере конфига нет ни репозиториев, ни секретов: в демо
репозиторий — каталог на хосте агента, его добавляет команда
([настройка хоста агента](operations/agent-host-setup.md)). На хосте агента
шаги консоли «Создайте репозиторий» и «Запустите службу» выглядят так:

```bash
sudo sard-agent repo add main /srv/sard-repo/main
sudo systemctl enable --now sard-agent.service
```

`repo add` создаёт каталог, репозиторий restic с сгенерированным паролем и
drop-in `ReadWritePaths=` для службы.

И сразу — **копия пароля репозитория вне хоста**:

```bash
sudo sard-agent repo password main --reveal
```

Строку сохраните в менеджер паролей как «Sard demo — restic main». Без неё
потеря хоста агента — потеря бэкапов: ключ есть только на нём. Шаг 9
восстанавливает именно по этой копии.

**Что должно получиться.** `repo add` сообщает, что репозиторий создан, и
напоминает сохранить пароль; `systemctl status sard-agent` — `active
(running)`. В консоли: агент `demo-host` «в сети», на главной отмечены «Агент
подключился» и «Репозиторий инициализирован».

**Время.** ~3 мин (оценка).

**Если не получилось.** Агент «висит» при старте — нет `ReadWritePaths` для
`/srv/sard-repo`. Код 7 `LOCK_WRITE` — нет каталога кэша restic. Агент не в
сети — `journalctl -u sard-agent --since -5min` и
[диагностика](operator/09-troubleshooting.md), «Агент не подключается».

## Шаг 6. Данные и источник в консоли

**Что делать.** На хосте агента — данные для бэкапа, доступные на чтение
пользователю службы:

```bash
sudo mkdir -p /srv/demo-data
sudo cp -r /usr/lib/sard /srv/demo-data/programs
sudo sh -c 'head -c 20M /dev/urandom > /srv/demo-data/random.bin'
echo "demo $(date -u +%FT%TZ)" | sudo tee /srv/demo-data/hello.txt
sudo chmod -R a+rX /srv/demo-data
```

Консоль → «Источники» → «Создать источник»: имя `demo-files`, агент
`demo-host`, плагин `files`, репозиторий `main`, конфигурация — путь
`/srv/demo-data` (в JSON: `{"paths": ["/srv/demo-data"]}`). Сохранить.

**Что должно получиться.** Источник в списке; на главной отмечено «Источник
создан».

**Время.** ~2 мин (оценка).

**Если не получилось.** Консоль не принимает конфигурацию — путь должен быть
абсолютным ([плагин files](plugins/files.md)). Нет репозитория `main` в списке —
агент не перезапускался после `repo add` (`sudo systemctl restart
sard-agent`).

## Шаг 7. Бэкап кнопкой

**Что делать.** Консоль → «Источники» → `demo-files` → «Запустить бэкап» →
«Открыть запуск».

**Что должно получиться.** Статус проходит «в очереди» → «выполняется»
(фазы «подготовка», «отправка») → «успешно»; в шаге — снимок, «Всего» несколько
десятков МиБ (программы агента и 20 МиБ случайных данных), журнал шага. В источнике появляется снимок; на главной — «Первый бэкап
успешен».

**Время.** ~1 мин (оценка).

**Если не получилось.** «ошибка» с «log redaction: cannot read secret» — в
`/etc/sard/agent.yaml` описан секрет или скрипт, файла которого нет. «ошибка» с «permission denied» — файлы не читаются
пользователем `sard-agent` (`chmod -R a+rX`). «потерян» — агент пропал во время
шага. Журнал шага в консоли показывает вывод restic.

## Шаг 8. Уведомление в Telegram

**Что делать.** Откройте чат с ботом.

**Что должно получиться.** Сообщение вида «✅ Бэкап выполнен: demo-files» с
агентом, длительностью, объёмом и ссылкой
`http://localhost:8080/runs/<id>` — ссылка открывается через туннель шага 2.
Формат — [уведомления](operations/notifications.md).

**Время.** ~1 мин (оценка); приходит в течение секунд после завершения
запуска.

**Если не получилось.** В логе сервера при старте `Notifications are off` —
переменные Telegram не попали в `.env` (шаг 1) или сервер не перезапущен после
правки (`docker compose up -d`). Бот должен получить от вас хотя бы одно
сообщение, иначе писать вам он не может.

## Шаг 9. Восстановление из снимка в отдельный каталог

Восстановления средствами Sard на этапе 1 нет (OQ-038): в демо — `restic
restore` на хосте агента. Пароль берём **из копии вне хоста** (шаг 5) —
так демо проверяет, что копия рабочая.

**Что делать.** На хосте агента:

```bash
umask 077
cat > /tmp/sard-pass-copy        # вставьте строку из менеджера паролей, Enter, затем Ctrl+D
sudo install -o sard-agent -g sard-agent -m 0600 /tmp/sard-pass-copy /var/tmp/sard-pass-copy
rm /tmp/sard-pass-copy
R="sudo -u sard-agent /usr/lib/sard/restic -r /srv/sard-repo/main --password-file /var/tmp/sard-pass-copy --cache-dir /var/cache/sard/restic"
$R snapshots
sudo install -d -o sard-agent -g sard-agent -m 0700 /var/tmp/sard-restore
$R restore latest --target /var/tmp/sard-restore
```

Вместо `latest` можно указать снимок из консоли (поле «Снимок» в запуске).

**Что должно получиться.** `snapshots` показывает снимок с путём
`/srv/demo-data`; `restore` заканчивается сводкой о восстановленных файлах;
файлы лежат в `/var/tmp/sard-restore/srv/demo-data`.

**Время.** ~2 мин (оценка).

**Если не получилось.** `wrong password or no key found` — в копии не та строка
(лишние пробелы, не тот репозиторий). `unable to create lock` — каталог
`/srv/sard-repo` не принадлежит `sard-agent`.

## Шаг 10. Сравнение с исходными файлами

**Что делать.**

```bash
sudo diff -r /srv/demo-data /var/tmp/sard-restore/srv/demo-data && echo "ФАЙЛЫ СОВПАДАЮТ"
sudo sh -c 'cd /srv/demo-data && find . -type f -exec sha256sum {} + | sort -k2' > /tmp/orig.sha
sudo sh -c 'cd /var/tmp/sard-restore/srv/demo-data && find . -type f -exec sha256sum {} + | sort -k2' > /tmp/restored.sha
diff /tmp/orig.sha /tmp/restored.sha && echo "СУММЫ СОВПАДАЮТ"
```

**Что должно получиться.** `ФАЙЛЫ СОВПАДАЮТ` и `СУММЫ СОВПАДАЮТ`, ни одной
строки различий.

**Время.** <1 мин (оценка).

**Если не получилось.** Различие в `hello.txt` — файл меняли после бэкапа
(восстановлен снимок на момент шага 7). Любое другое различие — дефект: запишите
вывод и [заведите вопрос](open-questions.md).

## Шаг 11. Уборка

На хосте агента:

```bash
sudo rm -f /var/tmp/sard-pass-copy /tmp/orig.sha /tmp/restored.sha
sudo rm -rf /var/tmp/sard-restore
```

Остальное (агент, репозиторий, сервер) можно оставить для следующих бэкапов.
Полное удаление сервера — [переезд и удаление](operator/08-migrate-and-remove.md);
агента — `sudo dpkg -r sard-agent`. Ключ CA сервера сохраните сразу, если
оставляете установку ([данные и бэкап](operator/06-data-and-backup.md)).
