# 0014 — TanStack Router вместо React Router, тесты маршрутов без рендера

- Статус: принято (решение владельца, W1a)
- Дата: 2026-09-27
- Заменяет: выбор React Router в ADR 0001; дополняет ADR 0011 (тесты)

## Контекст
Этап 1 добавляет разделы: агенты, источники, запуски, карточка запуска. Входу по паролю (W1b) нужна точка, которая срабатывает до загрузки данных страницы. React Router 8 в режиме `<Routes>` не даёт ни типизированных путей, ни хука до загрузчиков без перехода на его data/framework-режим. Серверные данные уже идут через TanStack Query.

## Решение
- Роутер — `@tanstack/react-router`. Маршруты описываются файлами в `web/src/routes/`. `@tanstack/router-plugin` в `vite.config.ts` генерирует `src/routeTree.gen.ts`.
- `routeTree.gen.ts` коммитится. Иначе `tsc -b` на чистом клоне не находит дерево маршрутов: typecheck в гейте идёт раньше сборки. Плагин ставит в начало файла SPDX-заголовок (`routeTreeFileHeader`), поэтому license-check не меняется. Файл исключён из oxlint и Prettier. Плагин пересоздаёт его в `dev`, `build` и `vitest`.
- Защита страниц — безпутевой layout-маршрут `_app`. Его `beforeLoad` вызывает `guard()` из `src/auth/guard.ts`, и все разделы, кроме будущей страницы входа, — его дочерние маршруты. Именно `beforeLoad`, а не компонент-обёртка: он выполняется до загрузчиков, поэтому отказ не запускает запросы данных. Сейчас `guard` пропускает всех; сессию и редирект делает W1b.
- `QueryClient` передаётся в контекст роутера (`createRootRouteWithContext`), чтобы загрузчики могли вызывать `ensureQueryData`. `defaultPreloadStaleTime: 0`: свежестью данных управляет Query, а не роутер.
- 404 — `notFoundComponent` корневого маршрута. Навигация — `createLink` над Mantine `NavLink`, поэтому цель ссылки проверяется по дереву маршрутов.
- Devtools Router и Query грузятся через `lazy(import())` под `import.meta.env.DEV`. В production-сборке ветка статически ложна, и импорт выпадает.
- Правило oxlint `only-export-components` получает `allowExportNames: ["Route"]`: файловые маршруты обязаны экспортировать `Route`. Компоненты в файлах маршрутов не объявляются, а берутся из `src/pages/` и `src/Root.tsx`.

## Тесты (дополнение к ADR 0011)
Компонентных тестов по-прежнему нет. Маршруты тестируются без рендера: `router.load()` на `createMemoryHistory` в окружении `node` проверяет совпавшие маршруты, параметры, 404 и вызов `guard` (`src/router.test.ts`). Ни DOM-окружения, ни @testing-library не нужно. Типизация ссылок проверяется при компиляции файлом `src/links.typecheck.tsx` с `@ts-expect-error`.

## Отвергнуто
- Оставить React Router — нет типизированных путей и хука до загрузчиков без смены режима.
- Маршруты в коде (code-based) — больше ручной связки `getParentRoute`, а типы те же.
- Не коммитить `routeTree.gen.ts` — `tsc -b` на чистом клоне падает раньше, чем плагин его создаст.
- Защита компонентом-обёрткой — рендерится после загрузчиков, и запросы уже ушли.
- Тест роутинга с рендером (jsdom + @testing-library) — противоречит ADR 0011 и добавляет две зависимости ради того, что проверяется без DOM.
