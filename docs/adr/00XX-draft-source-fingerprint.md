# 00XX — Отпечаток источника и интерфейс проверки плагина

- Статус: черновик (V2; решения владельца 2026-10-25, `docs/sessions/2026-10-24-v2-source-fingerprint.md`)
- Дата: 2026-10-25
- Основа: `docs/design/sard-restore-verification.md` (V-D3), ADR 0008, 0027, 0066; черновик «Сервер проверки восстановления» (V4)

## Контекст
Уровень 4 проверки восстановления — «восстановились те же данные, а не пустая база»:
отпечаток копии сравнивается с отпечатком источника, снятым в момент бэкапа. V-D3:
плагин снимает отпечаток, ядро сравнивает; один и тот же код снимает его с источника
и с копии. До V2 у плагинов был `sdk.Verifier` (A6a) — проверка восстановленного
каталога целиком внутри плагина; его не реализовал ни один плагин.

## Решение

### Интерфейс плагина (SDK, Apache-2.0)
- `Fingerprint{Facts, Format, Plugin}` из фактов `{Name, Rule, Value}`. Правила два:
  `exact` — копия обязана иметь факт с тем же значением; `info` — показывается, не
  сравнивается. «Непуст» и «SHA-256» — частные случаи `exact`: копию меряет тот же код,
  значения те же («nonempty», hex).
- Канонический вид (`Encode`): JSON, ключи и факты отсортированы, без пробелов, UTF-8,
  не больше 1 МиБ; `DecodeFingerprint` принимает только канонические байты. Хеш —
  SHA-256 канонических байтов, нижний регистр hex. Сервер и верификатор не
  канонизируют сами — хешируют байты как пришли.
- `Fingerprinter.Fingerprint(ctx, host, cfg, FingerprintTarget{Root, Reference})`:
  без `Reference` — источник, с ним — копия; копия меряет факты источника, которые нельзя
  выбрать заново (посчитанные таблицы, хешированные файлы).
- `FingerprintCompleter.CompleteFingerprint` — для отпечатка, который известен только
  после restic (файлы, изменившиеся во время чтения).
- `CopyRestorer.RestoreInto(ctx, RestoreHost, target, req) → RestoredCopy{Config, Root}`
  поверх восстановления TD1: PostgreSQL — `Restore` в новую базу, файлы —
  `RestoreHost.RestoreTree`.
- `Dump.Fingerprint`, `Dump.Release` (освобождает то, что дамп держит для Stream);
  `sdk.Verifier` удалён вместе с путём verify в `pluginhost`.

Сравнение — `agent/internal/fingerprint.Compare` (AGPL, ядро): расхождения словами,
`Unverified` — точные факты источника, которые копия сняла только как `info`. Плагин
своих правил сравнения не пишет.

### Хеш в метке снимка, без перезаписи
Метка `sard.fp=<хеш>` ставится при `restic backup`: `restic tag` после бэкапа создаёт
снимок с новым ID. Значит, хешируемое должно быть известно до restic.
- PostgreSQL: весь отпечаток снимается до `pg_dump` в той же транзакции, метка — на
  основном снимке.
- Файлы: выборку дополняют только после бэкапа (итоги restic, выброшенные файлы).
  Окончательный отпечаток сохраняется **отдельным снимком** `sard-fingerprint.json`
  (`files.part=fingerprint`, `files.main_snapshot=<id>`, `sard.fp=<хеш>`) — тот же
  механизм, что снимок глобальных объектов PostgreSQL. Всё, на что опирается
  верификатор, защищено ключом репозитория, а не сервером (владелец отверг вариант со
  списком выброшенных файлов вне хеша).

### PostgreSQL: одно состояние для отпечатка и дампа
`psql` как сопроцесс (правило 7: без драйвера в агенте): `BEGIN ISOLATION LEVEL
REPEATABLE READ READ ONLY`, `idle_in_transaction_session_timeout = 0`,
`pg_export_snapshot()`, запросы отпечатка под SAVEPOINT (сбой подсчёта не обрывает
транзакцию), `pg_dump --snapshot`; транзакция открыта до `Release` — сразу после
основного снимка. Сессия умерла раньше конца `pg_dump` — бэкап FAILED. Подключение то
же, что у `pg_dump` (`pgclient`, conninfo), поэтому S11 (`require_auth`, `tls_mode`)
меняет одно место. Исключения pg_dump переводятся в регулярные выражения разбором
`processSQLNamePattern`, сопоставляет PostgreSQL. Лимиты `count(*)` — 60 с на таблицу,
10 мин на все (цифр V0 нет); превышение — `info`, не провал.

### Файлы
Контрольные пути проверяются до restic (нет или пуст — FAILED). Выборка — резервуар по
полному обходу, шаблоны `--exclude` по правилам `filter.Match` restic (отрицания не
учитываются: выборка может пропустить файл, но не возьмёт исключённый); до 100 файлов,
до 64 МиБ на файл, до 1 ГиБ чтения, обход до 10 мин. После бэкапа файл с другим размером
или временем изменения переходит в `info`.

### Сервер
- `BackupOutput` 5 `fingerprint`, 6 `fingerprint_sha256`, 7 `total_files`. Сервер
  проверяет: оба поля или ни одного, 64 hex, хеш = SHA-256 байтов, ≤ 1 МиБ, JSON-объект с
  `facts`. Нарушение — недействительный результат, шаг FAILED, снимка нет.
- Отпечаток целиком хранится в `snapshots.fingerprint` (там же хеш и `total_files`):
  V4 уже держит его в задании и передаёт верификатору; V6 покажет расхождения из
  `VerifyOutput.mismatches`. В выводе шага (`run_steps.output`) — сводка: все факты, кроме
  выборки файлов (`sha256:`, `stat:`), которые лишь считаются — пути и хеши содержимого
  потенциально чувствительны, консоль их не показывает.
- Задание V4 копирует отпечаток и хеш из снимка (`INSERT … SELECT`).
- Падение числа файлов или объёма больше чем на 30 % к последнему целому снимку источника —
  предупреждение у шага (`warnings`), запуск остаётся `succeeded`. Правило общее для всех
  плагинов, у которых известны итоги.

### Совместимость
Агент N−1 полей 5–7 не шлёт: сервер считает число файлов неизвестным (0 без отпечатка —
не число), снимок без отпечатка, задание V4 без отпечатка — верификатор проверяет до
уровня 3. buf breaking (FILE) зелёный: поля только добавлены.

## Последствия
- Бэкап PostgreSQL удлиняется на время отпечатка (каталоги и `count(*)` ключевых таблиц);
  замер в журнале сессии.
- У каждого бэкапа файлов — второй снимок в репозитории; удержание (forget) должно
  удалять снимок отпечатка вместе с основным, как и снимок глобальных объектов.
- Отрицания в шаблонах `exclude` сужают выборку.

## Отвергнуто
- Драйвер Go для PostgreSQL — исключение из правила 7 без нужды.
- `restic tag` после бэкапа — новый ID снимка.
- Список выброшенных файлов вне хеша — сервер мог бы скрыть подмену.
- Подробный отпечаток только в репозитории — верификатор и V6 читали бы его из
  репозитория; V4 уже держит отпечаток на сервере.
- Новый статус запуска «с предупреждением» — затрагивает enum, консоль и уведомления.
