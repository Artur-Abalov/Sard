# 00XX — Метрики Prometheus сервера (H1, фаза 3)

- Статус: черновик (H1, фаза 3); решения владельца 1–9 и ответы ОВ1–ОВ10 — шапка `docs/specs/server/server-metrics.feature`
- Дата: 2026-10-21
- Дополняет: ADR 0013 (12-й вызов `system`), ADR 0041 (метрики Micrometer), ADR 0008 (токен метрик — секрет сервера, не ключ репозитория), 00XX-draft-server-retention (счётчик уборки)

## Контекст
Метрики Micrometer были в памяти без экспорта: оператор не видел из Prometheus, что бэкапы идут,
проверки проходят, агенты на связи и сертификаты не истекают. Экспорт не должен открывать консоль
наружу и нагружать базу на каждый опрос. Проверки состояния (`/actuator/health`, `/actuator/info`)
нужны на порту консоли 8080 (Р11): их читают healthcheck образа и сценарии установки.

## Решение
1. **Отдельный слушатель, а не `management.server.port`.** Перенос actuator на другой порт унёс бы
   и `health`, и `info` с 8080, а оставил бы весь actuator доступным по сети с общим стеком Tomcat и
   фильтрами консоли. Слушатель метрик — свой сервер на своём адресе и порту (`sard.metrics.*`,
   `SARD_METRICS_BIND` / `PORT` / `TOKEN` / `STATE_INTERVAL`), у порта 8080 к метрикам нет ни одного
   маршрута. Эндпоинт `prometheus` actuator выключен (`access: none`), экспозиция actuator —
   `health,info`.
2. **JDK `com.sun.net.httpserver`, а не коннектор Jetty/Tomcat.** Модуль `jdk.httpserver` есть в каждой
   JRE образа: ни новой зависимости, ни сервлетного стека, ни маршрута Spring MVC, до которого мог бы
   добраться обратный прокси консоли. Слушателю нужен один путь и один метод; пул из четырёх потоков-демонов.
   Он открывается при запуске жизненного цикла контекста (у веб-сервера своя, более ранняя фаза — порядок
   между ними не обещан и спецификации не нужен) и закрывается вместе с ним; занятый порт останавливает
   старт сообщением с `SARD_METRICS_PORT`.
3. **Токен и адрес.** По умолчанию `127.0.0.1:8081` внутри контейнера, compose порт не публикует.
   Адрес — только IP-литерал (имена не разрешаются). Вне loopback (`127.0.0.0/8`, `::1`; `0.0.0.0` и
   `::` — вне) без токена старт отвергается сообщением с `SARD_METRICS_TOKEN` и `SARD_METRICS_BIND`.
   Токен не короче 32 символов (ОВ7), из одних пробелов — не задан. На loopback без токена слушатель
   отвечает без аутентификации (ОВ2); заданный токен нужен на любом адресе.
4. **Ответы без деталей.** Проверка токена идёт до маршрутизации: без верного токена любой путь и
   метод — `401` с `WWW-Authenticate: Bearer` и пустым телом, одинаковым для отсутствующего и неверного
   токена. С верным: другой путь `404`, другой метод `405`, тоже без тела. Токен сравнивается
   `MessageDigest.isEqual` по байтам (постоянное время; `ArchitectureTest` запрещает сравнение строк),
   у `BearerToken` нет текстового представления, токен не попадает в журнал, метки и actuator.
5. **Состав экспозиции.** Метрики `sard_`, `jvm_`, `process_` (ОВ3); фильтр `MeterFilter` отбрасывает
   остальные имена. Метрик `http_server_requests` и `grpc_` нет: в их метках URI и классы исключений.
   Метки Sard — только `source_id`, `role`, `kind`, `status`, `outcome`, `health`, `channel`, `reason`
   (решение 5 владельца); имён хостов, путей, имён источников и текстов ошибок нет.
6. **Состояние — gauge по тику с кэшем.** Раз в `state-interval` (60 с; первый тик сразу после старта,
   в фоне, не задерживая готовность) `StateRefresh` читает базу и кладёт значения в gauge; scrape читает
   память и в базу не ходит, не блокируется занятым пулом или долгим тиком. Значение старше не больше
   интервала.
7. **Сбой базы — прежние значения и признак устаревания.** Упавший тик не меняет gauge и
   `sard_metrics_state_refresh_timestamp_seconds`, увеличивает `…_failures_total` и пишет один `WARN`
   с классом исключения (текст исключения может содержать SQL — не пишется). Алерт —
   `time() - sard_metrics_state_refresh_timestamp_seconds`. До первого успешного тика метрик состояния
   нет.
8. **`source_id` как метка.** Серий с `source_id` не больше двух на живой источник; удалённый (мягко)
   источник исчезает на первом тике, переименование серии не меняет. Живой источник без успеха —
   значение `0` (ОВ4), в алертах отдельное правило `== 0`. Метрики с фиксированным набором значений
   (`role`, `kind`, `status`, `health`) отдаются всеми сериями нулями сразу: число серий без `source_id`
   не зависит от объёма данных. Метки `agent_id` нет (ОВ9).
9. **Гистограмма длительности по событию.** `RunFinished` несёт `kind` (backup/restore) и `startedAt`;
   `RunDurations` пишет `sard_run_duration_seconds{kind,status}` в момент завершения по часам сервера.
   `verify` — запуск с триггером `verification`. Запуск без `startedAt` (отменён до начала) не
   наблюдается, в `sard_run_finished_total` считается как прежде. Корзины 60, 300, 900, 1800, 3600,
   7200, 14400, 28800, 86400 с (ОВ6). Гистограмма не зависит от базы и тика.
10. **Два пакета.** `metrics` — чистое ядро без фреймворка (`SardMetricNames`, `MetricRunKind`, `RunDurations`,
    `StateGauges`, `StateRefresh`, `StateReader`, `StateSnapshot` с портом `SelfBackupSource`): `scripts/claude/arch-edges.sh`
    считает его доменным (ADR 0064 п.2), там разрешены `java.*`, `kotlin`, Micrometer и запрещены Spring, Hibernate, gRPC,
    jakarta и `com.sun.net.httpserver`. Всё, что тянет фреймворк, — адаптерный пакет `prometheus` (`MetricsConfiguration`,
    `MetricsSettings`, `MetricsListener`, `MetricsEndpoint`, `BearerToken`, `StateLoop`, `StateQueries`). Рёбра только
    `prometheus -> metrics` и `selfbackup -> metrics`; `PackageDependencyTest` следит за ними и за чистотой `metrics`.
    **12-й вызов `TenantSessions.system`.** `prometheus/StateQueries.read` — шесть запросов в одной транзакции только
    для чтения по всем тенантам, число запросов не зависит от числа источников; нативный SQL с `tenant_id`
    (правило 8). Файл в списке `ArchitectureTest` и в ADR 0013. Состояние самобэкапа читается отдельно:
    `SelfBackups.get(tenant, readOnly = true)` через порт `SelfBackupSource` (пакеты `metrics` и
    `selfbackup` не образуют цикла).
11. **Сроки сертификатов.** Ближайшее истечение — минимум `not_after` по текущим (не отозванным и не
    вытесненным продлением) сертификатам неотозванных агентов, истёкший входит. Срок CA — новый метод
    `CertificateAuthority.notAfter()` (реализован в `FileCertificateAuthority` по сертификату CA, в том числе
    импортированному).
12. **Имена в одном месте.** `metrics/SardMetricNames.kt` объявляет каждое имя один раз; существующие
    метрики сохранены без смены имён (`ArchitectureTest`: имя встречается в main ровно один раз,
    построитель метрики не получает литерал).

## Отвергнуто
- **`management.server.port`.** См. пункт 1.
- **Эндпоинт `/actuator/prometheus` на 8080 с токеном.** Метрики были бы на порту консоли, достижимом
  через прокси консоли; владелец требует их отсутствия на 8080 по любому пути.
- **Jetty/Tomcat для слушателя.** Лишняя зависимость и общий с консолью стек ради одного GET.
- **Чтение базы на каждый scrape.** Нагрузка пропорциональна частоте опроса, при недоступной базе —
  отказ scrape.
- **Метрики HTTP-запросов (`http_server_requests`).** Метки с URI и исключениями (пункт 5).
- **Токен из файла (`SARD_METRICS_TOKEN_FILE`).** Отложено владельцем (ОВ10).

## Последствия
- Оператор открывает метрики наружу сам: `SARD_METRICS_BIND`, `SARD_METRICS_TOKEN` и публикация порта в
  `docker-compose.override.yml` ([docs/operator/14-monitoring.md](../operator/14-monitoring.md),
  проверяется `MonitoringDocsTest`).
- Зависимость `micrometer-registry-prometheus` (Apache-2.0, версия из BOM) — `docs/dependencies.md`.
- Тестовые контексты получают свободный loopback-порт метрик (`FreeMetricsPort`), иначе десятки контекстов
  одной JVM спорили бы за 8081.

## Известные ограничения
- **Самобэкап по тенанту по умолчанию.** Состояние и время успеха самобэкапа читаются по
  `TenantResolver.DEFAULT_TENANT_ID`; многотенантное расширение должно задать другой источник
  (`SelfBackupSource`). Время последнего успеха — новейшее из двух системных источников.
- **Счётчики событий обнуляются при перезапуске** (`sard_run_finished_total`, `sard_run_duration_seconds`,
  `sard_notify_*`, `sard_scheduler_fires_total`, `sard_retention_deleted_total`): считать через `rate()`.
- **Слушатель без тайм-аутов чтения.** JDK `HttpServer` не ограничивает чтение запроса, пул — четыре потока с
  неограниченной очередью: медленные клиенты без токена при открытом наружу порту могут занять потоки. Деградирует только
  доступность метрик; защита — сеть оператора и токен.
- **Фикстура `SelfBackupTenant(jdbc, DEFAULT_TENANT_ID).drop()`** в `MetricsStateIntegrationTest` удаляет все строки
  тенанта по умолчанию из 11 таблиц в базе общего контекста `@MetricsServerTest`. Другие классы этого контекста
  (`MetricsScrapeIntegrationTest`) данных этого тенанта не создают, кроме администратора, которого фикстура не трогает;
  риск принят и записан, фикстуру не меняли.
- **E2E `MetricsRetentionTest` не прогонялся** (образов `sard-*:e2e` нет), как и наличие модуля `jdk.httpserver` в
  `eclipse-temurin:25-jre` (образа нет локально, `java --list-modules` не выполнялся): полный JRE его содержит, но это
  не проверено.
- **Токен виден в `docker inspect`** (переменная окружения контейнера); `SARD_METRICS_TOKEN_FILE` отложен (ОВ10).
- Порт метрик — HTTP без TLS; защита — токен и сеть оператора.
- Агенты только отзываются, не удаляются: сценарии спецификации про «удалённого агента» не применимы,
  проверяется отозванный.
- Вне фичи: метрики агента, дашборды Grafana, трассировка, `forget` и `prune` (L1).
- E2E-часы не подменяются (ОВ8): возраст данных задаётся сдвигом времени в базе.
