# 0071 — Нижний предел хранения на хосте и шаг FORGET (L1a)

- Статус: принято (L1a, спецификация `docs/specs/agent/retention-forget.feature` и
  `docs/specs/proto/retention-forget.feature`, утверждена владельцем 2026-10-31)
- Дата: 2026-10-31
- Дополняет [0008](0008-crypto-provider.md) и [0049](0049-agent-config-overlay.md)

## Контекст
Без забывания снимков хранилище и таблица `runs` растут без конца. Сервер — управляющая плоскость
(ADR 0008): захваченный сервер не должен получить способ удалить бэкапы, которые оператор хоста
хочет сохранить.

## Решения
1. **Сервер присылает политику, а не список снимков.** `ForgetTask` не содержит поля «снимки к
   удалению», а ни одно сообщение от сервера к агенту — поля «force», «remove_all», «override»
   и подобного. Агент сам считает, что забыть, по снимкам с меткой `sard.source`.
2. **Нижний предел задаёт оператор хоста, только в основном `agent.yaml`** (`retention_floor.default`,
   `retention_floor.repositories.<имя>`; `keep_last`, `keep_within_days`, `disabled`; встроенный
   предел — 7 снимков и 14 дней). Во фрагменте `agent.d` и внутри определения репозитория ключ —
   ошибка конфигурации: фрагмент пишет `repo add`, в том числе по команде сервера. `disabled`
   допустим только для репозитория, не в `default`: выключить предел для всех случайно нельзя.
3. **Предел действует на хосте, который удаляет**, и на снимки любого источника; он только
   вычёркивает из решения политики. Агент сообщает его с происхождением в Register
   (`RepositoryInfo.retention_floor`).
4. **`keep_within` считается от самого нового снимка, но не позже «сейчас»**, как и в restic
   (проверено на restic 0.19.1): снимок, датированный будущим (сбой часов, подделка), не сдвигает
   границу предела за недавние снимки.
5. **`restic forget` вызывается только со списком полных id**, сначала части, затем основные снимки,
   пачками по 1000, без `--keep-*`, `--group-by`, `--prune`; перед ним `restic unlock` без
   `--remove-all`; живая блокировка ждётся до 5 минут (`--retry-lock 5m`).
6. **Шаг FORGET с чем-либо вне контракта отклоняется** (`plugin`, `config_json`, `tags`, `verify`,
   неизвестные поля `RunStep`, `ForgetTask`, `RetentionPolicy`, `snapshot_id`): для сообщения,
   решающего об удалении, отказ закрыт, а не открыт. Цена: будущее поле `ForgetTask` старый агент
   отклонит, сервер должен проверять версию агента.
7. **Бэкап ждёт исключительную блокировку** (OQ-156): чтение id репозитория перед бэкапом идёт с
   `--retry-lock 5m`; вывод restic «repo already locked, waiting…» отбрасывается перед разбором JSON.
8. **Верификатор отклоняет FORGET шлюзом роли** (V-D7).
9. **Ключ `main_snapshot` зарезервирован** (`sdk.MainSnapshotTag`): снимок с меткой `<плагин>.main_snapshot=<id>`
   агент читает как часть основного снимка, а часть забывается без проверки предела. Поэтому тег шага,
   оканчивающийся на `.main_snapshot`, отклоняется (REJECTED), а плагин не может задать ключ
   `main_snapshot` в `Dump.Tags` и `ExtraFile.Tags`; метку пишет только сам агент.

## Последствия
- Предел надо задавать на каждом хосте с правом удаления (документация L1e).
- Сервер (L1b) не отправляет FORGET агенту без `retention_floor` в Register.
