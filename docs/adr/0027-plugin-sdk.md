# 0027 — SDK плагинов-источников: шаги, два способа бэкапа, валидация, секреты

- Статус: принято
- Дата: 2026-09-29

## Контекст
Агент бэкапит источники через `sdk.Plugin` (CLAUDE.md, шов 6). До A6a
интерфейс был заглушкой: плагин не получал секретов, не мог сказать, как
отдать данные restic, конфиг никто не проверял, а сервер видел у всех
плагинов версию агента и действия BACKUP, RESTORE, VERIFY. Решения
владельца по вопросам A6a — журнал `docs/sessions/2026-09-29-a6a-plugin-sdk.md`.

## Решение
- **Шаги.** `Prepare → Dump → Stream`, каждый получает `sdk.Host`:
  `Secret(name)`, `Progress(done, total)`, `Log(level, text)`. `Verify` —
  отдельный необязательный интерфейс `sdk.Verifier`; действие VERIFY
  объявляется только у плагинов, которые его реализуют. `Version()` —
  собственная версия плагина; встроенные плагины возвращают версию агента.
- **Два способа бэкапа.** `Dump` возвращает либо пути (+ исключения) —
  restic бэкапит их, либо `Filename` — тогда агент вызывает `Stream`, и
  его байты restic сохраняет из stdin одним файлом с этим именем
  (`--stdin --stdin-filename=`). `Stream` получает конфиг: дамп (pg_dump)
  строится из него.
- **Поток и целостность снимка.** EOF на stdin restic считает концом
  полных данных и сохраняет снимок — даже после сбоя дампа (проверено на
  0.19.1). Поэтому обёртка (`restic.BackupRequest.Stdin`) закрывает stdin
  только после успешного `Stream`. При ошибке или отмене restic получает
  SIGTERM, а stdin закрывается лишь после строки
  `signal … received, cleaning up`: restic 0.19 и после SIGTERM ждёт EOF,
  но снимок уже не сохраняет («unable to save snapshot: context canceled»).
  Ошибка потока — ошибка шага; когда restic завершился, конец чтения
  закрывается и продолжающий писать `Stream` получает ошибку.
- **Фазы.** Prepare — PREPARING, Dump — DUMPING, restic (и поток, который
  идёт одновременно с ним) — UPLOADING, Verify — VERIFYING. `Host.Progress`
  относится к текущей фазе.
- **Валидация.** Конфиг проверяется по `ConfigSchema` в агенте
  (`internal/pluginhost`, AGPL) до `Prepare`. Библиотека —
  `github.com/santhosh-tekuri/jsonschema/v6`: полная поддержка 2020-12,
  Apache-2.0, без runtime-зависимостей вне stdlib и `x/text`, уже была в
  тестах. `xeipuuv/gojsonschema` умеет только draft-07, `qri-io/jsonschema`
  — 2019-09. Ошибка — `*sdk.ConfigError` со списком нарушений и JSON
  Pointer каждого поля.
- **Секреты.** Поле с именем секрета помечается в схеме
  `"format": "sard-secret"`. Имя проверяется при валидации: неизвестное —
  нарушение с `Violation.Secret`, `errors.Is(err, sdk.ErrUnknownSecret)`.
  Так шаг отклоняется до побочных эффектов. `Host.Secret` читает файл при
  каждом вызове (ротация без перезапуска) и возвращает байты как есть;
  неизвестное имя — `*sdk.SecretError`. Значения не попадают ни в ошибки,
  ни в логи.
- **Ограничения Register.** `sdk.NewRegistry` отклоняет то, что отклонит
  сервер (S4a, `SnapshotRules.kt`): > 64 плагинов, имя вне
  `^[A-Za-z0-9][A-Za-z0-9._-]{0,127}$`, версию вне `^[!-~]{1,64}$`, схему
  больше 64 КиБ, не один JSON-документ или с `\u0000`.

- **Адаптер к исполнителю** (`pluginhost.Handlers`, вместо
  `app.NoHandlers`). Actions плагина: BACKUP и RESTORE всегда, VERIFY —
  только у `sdk.Verifier`; в Register уходят эти actions и
  `Plugin.Version()`. Ошибки `sdk.ErrInvalidConfig` и `sdk.ErrUnknownSecret`
  оборачиваются в `executor.ErrRejected`, как и теги, которые restic не
  примет (пустой ключ, запятая). Теги шага — `ключ=значение`, по порядку.
  Программу, которой нет на хосте, плагин сообщает ошибкой с `sdk.ErrProgramMissing`
  (оборачивает через `%w`); `pluginhost` узнаёт её через `errors.Is` и дописывает
  подсказку `sudo sard-agent check` (ADR 0063).
  Итог restic → `BackupOutput{snapshot_id, total_bytes, added_bytes,
  repository_id}`; снимок без части файлов — FAILED с выводом.
- **RESTORE и VERIFY.** Снимок восстанавливается в новый каталог
  `<executor.state_dir>/restore/<command_id>` (0700), существующий не
  переиспользуется; `snapshot_id` обязателен. VERIFY проверяет копию
  плагином и удаляет её. Цель восстановления и «последний снимок по тегам»
  — OQ-038.

## Поправки (R2c-3, ADR 0066)
- **Шаги и Host дополнены** необязательными интерфейсами (плагин реализует то, что ему
  нужно): `RestoreRunner` (плагин восстанавливает сам; без него хост выкладывает дерево по
  `PlanRestore`), `RestoreHost` (`Phase`, `Snapshots`, `Dump`, `Journal`), `RestoreError`,
  `Recoverer` (разбор записей журнала при старте), `Extractor` (`PlanExtract` — файлы
  снимка для `sard-agent repo restore` без сервера) и `ProgramChecker` (строка
  `plugin.programs` команды `sard-agent check`; любой плагин может её реализовать).
- **Коды причин плагин задаёт сам** по образцу `^[A-Z][A-Z0-9_]{0,63}$`, стадии — по образцу
  `^[a-z][a-z-]{0,31}$`; в SDK только общие коды (классы хранилища и restic,
  `SNAPSHOT_UNKNOWN`, `CLEANUP_FAILED`). Код вне образца хост заменяет на `PLUGIN_FAILED`.
- **SDK не импортирует `proto/gen/go`** (раньше `imports_test.go` разрешал сгенерированный
  код): SDK зависит только от себя и stdlib. В SDK нет типов конкретной базы данных
  (`PostgresRestore`, `RestorePlan.Postgres`, `pgclient` удалены).
- **«RESTORE и VERIFY».** Восстановление в каталог описывает ADR 0060, восстановление
  самим плагином — ADR 0066.

## Оборотная сторона
- Между строкой restic о SIGTERM и отменой его контекста — один вызов;
  теоретически restic мог бы успеть сохранить обрезанный снимок, если EOF
  пришёл в это окно. На практике сохранение — несколько записей в
  репозиторий, а отмена следует сразу. Если restic изменит текст строки,
  агент не закроет stdin до SIGKILL через `DefaultGrace` (10 с): снимка не
  будет, но останется устаревшая блокировка. Интеграционные тесты с
  закреплённой версией это ловят.
- Правило 7 в CLAUDE.md перечисляет runtime-зависимости агента: stdlib,
  gRPC, protobuf, YAML. Валидатор JSON Schema (и транзитивно `x/text`)
  расширяет этот список; строку CLAUDE.md правит владелец.
- `format` утверждается для всех форматов (`AssertFormat`): «email»,
  «uri» и т. п. в схемах плагинов проверяются строго.
- Сторонний плагин с собственной валидацией в `Prepare` обязан вернуть
  `*sdk.ConfigError` до побочных эффектов, иначе REJECTED обманет сервер.
