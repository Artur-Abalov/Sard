# 0049 — Каталог фрагментов конфига агента `agent.d`

- Статус: принято (A8a); решения владельца — 2026-10-07 (`docs/specs/agent/host-setup.feature`, Р1–Р4, Р10–Р12)
- Дата: 2026-10-07

## Контекст
Прогон демо на ВМ показал, что репозиторий и секрет оператор добавлял
правкой `agent.yaml`. Команды `sard-agent secret` и `sard-agent repo add`
должны менять настройку хоста сами, а агент — читать её. Правка YAML на месте
значит перезапись файла оператора: потерянные комментарии, порядок ключей,
конфликт с пакетным менеджером и с конфиг-менеджментом (Ansible, Salt), который
владеет `agent.yaml`.

## Решение
- **Основной конфиг команды не меняют никогда.** Рядом с ним лежит каталог
  `agent.d` (для `--config /etc/sard/agent.yaml` — `/etc/sard/agent.d`); команды
  пишут в него по одному файлу на репозиторий (`repo-<имя>.yaml`) и секрет
  (`secret-<имя>.yaml`).
- **Читает `config.Load`**, поэтому фрагменты видят старт агента, `repo init`,
  `repo list` и все новые команды. Читаются файлы с суффиксом `.yaml` в
  порядке имён (побайтово); остальные (`.имя.tmp-*`, `*.rpmsave`, `README`)
  пропускаются. Нет каталога — конфиг состоит из одного файла, как раньше.
- **Во фрагменте допустимы только `repositories` и `secrets`.** `server`, `tls`,
  `scripts`, `restic`, `executor` и `service` — ошибка конфига, называющая файл
  и ключ: сервер, сертификаты, исполняемые скрипты и пользователь службы не
  должны меняться файлом, который пишет команда.
- **Порядок.** Репозитории основного конфига, затем фрагментов по порядку
  файлов. Одно имя в двух местах (в том числе дважды в одном файле) — ошибка
  `DUPLICATE_NAME`, называющая оба файла; агент с такой ошибкой не стартует
  (как при любой ошибке конфига, код 1).
- **Происхождение определения** (`Repository.Fragment`, `Config.SecretSource`)
  попадает в сообщения: A1 называет файл фрагмента, `repo show`/`repo list` —
  столбец `defined_in`.
- **Запись.** Каждый файл — временный файл в каталоге назначения (не `/tmp`),
  владелец и права до переименования, fsync, rename, fsync каталога. Фрагмент
  пишется последним: пока его нет, агент нового репозитория или секрета не
  видит. Сбой оставляет прежнее содержимое и не оставляет временных файлов.
- **Права.** `agent.d` — `root:<группа службы>`, `0750`; фрагмент — то же,
  `0640` (служба читает, но не меняет свою настройку); `secrets` и файлы в нём
  — пользователь службы, `0700` и `0600` (A1). Права не зависят от umask.
  Права `agent.d` при старте агента не проверяются (проверка — `sard-agent
  check`, срез A8d).
- **Одновременные изменения.** Изменяющая команда держит `flock` на
  `agent.d/.sard-config.lock` от чтения конфига до записи фрагмента; вторая
  получает `CONFIG_LOCKED` (временная). Блокировка `repo add` ещё и блокировка
  init того же имени (ADR 0030).

## Альтернативы
- *Править `agent.yaml`.* Теряет комментарии, конфликтует с владельцем файла.
- *Один файл `agent.d/managed.yaml`.* Каждая команда перезаписывала бы файл,
  который читают все; параллельные изменения требовали бы слияния.
- *Хранить в БД агента.* Агент остаётся без состояния, кроме журнала шагов.

## Последствия
- `config.Config` помнит, откуда пришло каждое определение.
- Ошибка во фрагменте останавливает агент при старте: оператор видит её в
  `journalctl -u sard-agent`.
- Применение изменения — перезапуск службы по журналу принятых команд
  (ADR 0044); окно между проверкой журнала и перезапуском не закрывается, шаг,
  принятый в это окно, провалится по D13.
