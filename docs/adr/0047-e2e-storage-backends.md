# 0047 — Стенд S3 и SFTP в e2e; `ssh` — зависимость агента

- Статус: принято; решение владельца на контрольной точке 1 F2 (Garage, база Ubuntu, зависание — в реестр)
- Дата: 2026-10-07
- Дополняет: ADR 0020 (база образа агента стенда), ADR 0018 (зависимости пакета)

## Контекст
F2 проверяет бэкап и восстановление через S3-совместимое хранилище и SFTP
сквозными тестами (`test/e2e`). Сейчас e2e есть только для локального
репозитория. MinIO Community Edition архивирован (апрель 2026), для стенда не
годится. Пробы фазы 1 — `docs/sessions/2026-10-07-f2-s3-sftp.md`.

restic `sftp:` запускает внешний `ssh`. В пакете агента его нет, в образе
стенда (`distroless/static`) — тоже. OpenSSH берёт домашний каталог из passwd,
а не из `HOME`, который агент передаёт restic (`cache_dir`). Поэтому ключ и
`known_hosts` пользователя службы лежат в `/var/lib/sard-agent/.ssh/`.

## Решение
- **S3 на стенде — Garage** (`dxflrs/garage`, версия закреплена дайджестом),
  один узел, `replication_factor = 1`, SQLite. Бакет, ключ на запись и ключ
  только на чтение создаёт помощник стенда через `garage` CLI в контейнере
  (`docker exec`). Права задаются на пару «ключ — бакет»
  (`bucket allow --read [--write]`), отдельной политики не нужно.
  Проба: полная цепочка restic побайтово верна; ключ только на чтение,
  неверный секрет и отсутствующий бакет дают понятный отказ меньше чем
  за 1 с.
  Отвергнуто:
  - SeaweedFS: master, volume, filer и S3-шлюз; права — через JSON-файл
    identities, перезапуск шлюза на каждого пользователя.
  - MinIO CE: архивирован.
  Лицензия Garage (AGPL-3.0) не важна: образ только запускается на стенде и
  в поставку не входит.
- **SFTP на стенде — свой образ** `test/e2e/sftp/Dockerfile`: Ubuntu 24.04,
  `openssh-server`, `internal-sftp`, только ключи. Пользователь `sard`,
  пароль `*`: sshd отвергает ключи заблокированной учётной записи.
  Каталоги:
  - `/srv/sftp/repo` — на запись;
  - `/srv/sftp/ro` — только на чтение.

  Открытый ключ пользователя тест кладёт в `/etc/ssh/authorized_keys/sard`.
  Ключ хоста создаёт `openssh-server` при установке; тест читает его открытую
  половину из контейнера, то есть из доверенного канала, и пишет в `known_hosts`
  агента. Сборка за прокси с подменой
  TLS работает так же, как в `deploy/server/Dockerfile`: необязательный
  секрет `build-ca`, `mode=0444`, потому что apt читает его от `_apt`.
- **`ssh` — зависимость агента.** Пакет deb: `Depends: openssh-client`. У
  tar.gz и rpm это записано как требование. Образ агента стенда моделирует
  хост: база — Ubuntu 24.04 с `openssh-client` вместо `distroless/static`.
  Пользователь `sard-agent`, uid 65532, домашний каталог `/var/lib/sard-agent`,
  как в `postinstall.sh`. Раскладка файлов прежняя. Тома, разовые
  контейнеры и uid 65532 из ADR 0020 не меняются. Оболочки в образе тесты не
  используют.
- **Неизвестный ключ хоста не принимается.** Агент не передаёт
  `-o StrictHostKeyChecking` и не пишет `known_hosts`. Под юнитом нет
  терминала, и `ssh` отказывает: `Host key verification failed`. Ключ хоста
  оператор кладёт в `/var/lib/sard-agent/.ssh/known_hosts` сам.

## Последствия
- Отказ хранилища ограничен только таймаутом шага. Сервер таймаут не
  передаёт, у агента максимум — 24 ч (`executor.go`). Пробы:
  - S3, порт закрыт: restic сдаётся сам через 13–14 мин;
  - S3, хранилище заморожено: restic не выходил больше 25 мин;
  - SFTP, сервер заморожен: restic не выходил больше 16 мин.

  Это дефект в реестре (OQ-137), не правка F2.
- В образе стенда появляется оболочка. Тесты по-прежнему не делают
  `docker exec` в агента (ADR 0020), а комментарии «в образе нет оболочки» в
  `test/e2e` правятся.
- Что проверено и что найдено в фазе 3 F2:
  - отказы — `StorageFailureTest`, `StorageOutageTest`, `StorageLockTest`;
  - причина не всегда в сообщении шага — OQ-155;
  - `--retry-lock` не срабатывает из-за `restic cat` — OQ-156;
  - `dpkg -i` не ставит `openssh-client` — OQ-157.

  Обход молчаливого обрыва SFTP — `ServerAliveInterval` в
  `/var/lib/sard-agent/.ssh/config`, `docs/operator/05a-storage.md`.
