# 0038 — Консоль отдаёт sard-server и она входит в образ

- Статус: принято (решение владельца, 2026-10-05, S10; ответы на вопросы О1–О7 —
  в `docs/qa/console-serving.md`)
- Дата: 2026-10-05

## Контекст

ADR 0037 оставил консоль за пределами образа: образ сервера отдавал только API,
а консоль запускалась из исходников (`npm run dev`). Демо этапа 1 должно
открываться на чистой ВМ по адресу сервера, без Node и без отдельного веб-сервера.
Решение владельца, не обсуждавшееся: консоль (`web/dist`) отдаёт сам
`sard-server`, она входит в опубликованный образ (amd64 и arm64), отдельного
обратного прокси (Caddy и т. п.) нет. TLS завершается перед сервером (ADR 0037).

## Решение

- **Набор консоли лежит внутри jar**, на пути классов, в каталоге `console/`
  (не в `static/`: стандартная раздача Spring Boot его не видит и не знает
  правил ниже). `java -jar` самодостаточен, в образе по-прежнему один файл
  `/app/sard-server.jar`.
- **Gradle включает набор только по `-PsardConsoleDist=<каталог>`** (готовая
  сборка `web/dist`). Без свойства jar собирается без консоли, поэтому
  `./gradlew :server:test` и `:server:bootJar` не требуют Node. Свойство задано, а
  `index.html` в каталоге нет — сборка падает с сообщением, называющим свойство и
  каталог.
- **Раздача — сервлетный фильтр** `ConsoleFilter` на `/*`, регистрируется, только
  если набор есть; иначе при старте одна запись INFO, пути консоли отвечают 404, как
  раньше. Расположение набора — внутреннее свойство `sard.console.location`
  (по умолчанию `classpath:/console/`), нужное тестам; оператору оно не предлагается.
- **Правила путей** (`ConsoleRoutes`, чистая функция): `/api`, `/actuator`, `/v3`, `/downloads` (пакеты агента, U1a) и их
  вложенные пути (по сегменту) консоль не трогает. Существующий файл набора
  отдаётся как есть. Любой другой путь, у которого в последнем сегменте нет точки и
  который не под `/assets/`, получает `index.html` (SPA-fallback; GET и HEAD,
  заголовок Accept не учитывается). Отсутствующий файл (точка в последнем сегменте
  или путь под `/assets/`) — 404 без страницы. Остальные методы — 405 с
  `Allow: GET, HEAD`. Точечные и обратные сегменты, `%2e%2e`, NUL — 404: отдаются
  только файлы набора.
- **Кэш:** страница и файлы корня — `Cache-Control: no-cache`; `/assets/*` (имена с
  хэшем содержимого от Vite) — `public, max-age=31536000, immutable`. Сжатия и
  условных запросов нет (Cloudflare перед первой площадкой сжимает сам).
- **Заголовки безопасности** на ответах консоли: `X-Content-Type-Options: nosniff`,
  `X-Frame-Options: DENY`, `Referrer-Policy: same-origin` и CSP
  (`default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; ...`,
  точное значение — в спецификации). `'unsafe-inline'` для стилей нужен Mantine
  (атрибуты `style` и вставляемые элементы `style`), скриптов inline в сборке Vite
  нет. HSTS не ставится. Ответы API не меняются.
- **Версия:** `index.html` содержит `<meta name="sard-version" content="V">`, V —
  `SARD_VERSION` при `npm run build` (по умолчанию `dev`). В образе она берётся из
  того же аргумента сборки, что и версия сервера в `/api/v1/status`.
- **Вход:** консоль отдаётся без сессии, без `Set-Cookie`, не продлевает сессию и
  работает при недоступной базе; фильтры сессии и Origin по-прежнему охватывают
  только `/api/v1/*`.
- **Dockerfile:** стадия `web` на `$BUILDPLATFORM` (Node 24, как в CI) выполняет
  `npm ci` и `npm run build` из того же контекста; стадия `build` получает из неё
  `web/dist` и собирает `bootJar` с `-PsardConsoleDist`. Готовый `web/dist` извне в
  образ не принимается. За TLS-прокси стадия использует тот же необязательный
  секрет `build-ca` (`NODE_EXTRA_CA_CERTS`) и стандартный аргумент `HTTPS_PROXY`.
  `.dockerignore` открывает `web/` (без `node_modules` и `dist`) и один файл вне
  него — `agent/plugins/files/schema.json`, который читает проверка типов тестов
  консоли. `make build` собирает web до jar.
- **CI и релиз:** задание `image` в `ci.yml`, `release.yml` и `make e2e-images`
  собирают образ тем же Dockerfile, отдельного шага сборки web нет. Тесты
  `test/e2e` проверяют консоль в образе, `scripts/smoke-server.sh` — страницу и её
  версию после quickstart и офлайн-архива.

## Рассмотренные альтернативы

- **Отдельный обратный прокси (Caddy, nginx) рядом с сервером.** Второй контейнер,
  второй образ в релизе и в офлайн-архиве, своя конфигурация SPA-fallback и
  заголовков; владелец исключил.
- **Набор консоли каталогом в образе вместо jar.** Образ перестаёт быть одним
  файлом, `java -jar` без образа не отдаёт консоль, версия консоли и сервера может
  разойтись при подмене тома; jar гарантирует одну сборку.
- **Выбор по заголовку Accept (HTML — страница, иначе 404).** Хрупко: прокси,
  `curl` и предзагрузка присылают произвольный Accept; глубокая ссылка после
  перезагрузки должна отдавать страницу всегда. Правило по пути проще и
  проверяется без клиента.
- **Набор в `static/` и стандартная раздача Spring Boot.** Нет SPA-fallback, нет
  своих заголовков кэша и безопасности, 404 для отсутствующих файлов отдаётся
  страницей или Spring-ошибкой по-разному; свой фильтр даёт одну проверяемую
  функцию правил.
- **Готовый `web/dist` как контекст сборки образа.** Образ зависел бы от того, что
  собрал разработчик, а не от коммита; стадия `web` делает сборку воспроизводимой.

## Последствия

- Параметр маршрута консоли с точкой (например, имя вместо UUID) не получит
  `index.html`. Сейчас все параметры маршрутов — UUID.
- `style-src 'unsafe-inline'` ослабляет CSP для стилей; скрипты остаются только
  `'self'`.
- Сборка образа требует сети для `npm ci` (за TLS-прокси — `build-ca` и
  `HTTPS_PROXY`); время сборки растёт на стадию `web`, `npm ci` кэшируется
  слоем и каталогом `/root/.npm`.
- `meta sard-version` раскрывает версию без входа; она и так публична в
  `GET /api/v1/status`, а мета-тег — единственный проверяемый признак того, что
  консоль и сервер из одной сборки.
- Неизвестный путь под `/api/v1/*` отвечает как прежде (404 Spring); приведение
  его к Problem с `code` — отдельная задача.
- ADR 0037: пункт «Консоль в образ пока не входит» заменён ссылкой сюда.
- Маршрутизация идёт по нормализованному пути контейнера (`servletPath` + `pathInfo`), а не по `requestURI`:
  `//api/...` и `/;x/api/...` для фильтров авторизации и диспетчера — те же `/api/...`.
