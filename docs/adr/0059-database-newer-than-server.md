# 0059 — Отказ старта на базе от более новой версии Sard

- Статус: принято (F7, Р31, Р32; решения владельца 2026-10-14)
- Дата: 2026-10-14

## Контекст
Администратор восстанавливает сервер из самобэкапа. Версию Sard он берёт из
`SARD_VERSION` в `.env` снимка ключей, а база в другом снимке может быть
новее: между двумя снимками сервер могли обновить. Flyway по умолчанию
игнорирует миграции, которых у сборки нет (`ignoreMigrationPatterns`
`*:future`), `ddl-auto: validate` лишних столбцов не замечает. Старый сервер
молча стартовал бы на схеме, которой не знает, и мог бы её испортить.

## Решение
- Проверка выполняется при каждом старте, до применения миграций: бин
  `FlywayMigrationStrategy` (`persistence/DatabaseVersionGuard.kt`) смотрит
  `flyway.info()` до `migrate()`.
- Отказ — если в `flyway_schema_history` есть версионная миграция в состоянии
  `FUTURE_SUCCESS` или `FUTURE_FAILED` — то есть версия больше самой большой версии миграций
  сборки. Исключение `DatabaseNewerThanServer`; первая строка начинается с
  `Database startup refused: DATABASE_NEWER_THAN_SERVER:` и называет самую новую
  миграцию базы с описанием, самую новую миграцию сервера, версию сервера
  (как `/api/v1/status`) и `docs/operator/12-server-recovery.md`.
- Ничего не меняется: ни история, ни каталог CA, ни канал соседа; код
  настройки не печатается — проверка раньше всех бинов, которые это делают.
- Неизвестные миграции старше последней известной проверка не трогает: их
  по-прежнему отклоняет валидация Flyway.

## Отклонение от текста Р31
Р31 оставляет неудачные строки (`success false`) Flyway. На деле Flyway
с `*:future` игнорирует и неудачную строку будущей версии, и сервер стартует
(проверено тестом). Сценарий спецификации требует остановки, поэтому неудачная
строка версии больше известной тоже останавливает старт, тем же кодом
`DATABASE_NEWER_THAN_SERVER`; сообщение говорит «recorded as failed».

## Последствия
- Откат на старый образ после обновления перестаёт «работать молча»: сервер
  отказывается, и страница восстановления говорит, что поднять.
- Поведение на чистой базе и на базе своей или более старой версии не
  меняется.
