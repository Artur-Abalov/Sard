# 0047 — Версии релизов: beta, rc и порядок в deb и rpm

- Статус: принято (решения владельца 2026-10-07, журнал `docs/sessions/2026-10-07-r1-release-versioning.md`)
- Дата: 2026-10-07
- Связано: ADR 0018 (упаковка агента), ADR 0037 (установка из консоли), ADR 0039 (образ и релиз), ADR 0043 (подписанные пакеты), ADR 0045 (собрать один раз)
- Меняет: ADR 0018 в части имён файлов deb и rpm; ADR 0037 в части «устарел» (В4) и формата rpm в консоли

## Контекст

- Путь к 0.1.0 — предрелизы `0.1.0-beta.N`, затем `0.1.0-rc.N`. Первый
  предрелиз вышел как `v0.0.1-rc1`: `release.yml` принимал любой тег
  `vX.Y.Z-*`.
- В SemVer `rc1` и `rc10` — буквенно-цифровые идентификаторы, сравниваются
  лексически: `rc10 < rc2`, `rc.2 < rc1`. Числа сравниваются как числа только
  отдельным идентификатором после точки: `rc.2 < rc.10`.
- В deb и rpm предрелиз без тильды новее релиза (`0.1.0-rc.1` > `0.1.0` для
  dpkg). Тильда сортируется раньше всего: `0.1.0~rc.1 < 0.1.0`.
- `package-agent.sh` понимал только `vX.Y.Z`; всё остальное, в том числе
  `v0.0.1-rc1`, получало `0.0.0~dev.<…>` (OQ-143).
- GitHub заменяет `~` в именах файлов релиза на `.`: у `v0.0.1-rc1` ассеты
  `sard-agent_0.0.0.dev.v0.0.1.rc1_amd64.deb`, а подписанный `SHA256SUMS` и
  `manifest.json` называют `sard-agent_0.0.0~dev.v0.0.1.rc1_amd64.deb` —
  `sha256sum -c` по скачанным с GitHub файлам их не находит.
- RPM собирался и подписывался, но нигде не ставился: проверки установки —
  только deb на Debian/Ubuntu, консоль rpm не предлагала (422).

## Решение

**Правило в одном месте — `scripts/release-version.sh`.** Остальные скрипты
и workflow спрашивают его, а не разбирают версию сами.

- Тег релиза: `vX.Y.Z`, `vX.Y.Z-beta.N` или `vX.Y.Z-rc.N`; числа без ведущих
  нулей, `N` от 1. Первая задача `release.yml` (`version`) отказывает любому
  другому тегу, остальные задачи ждут её.
- Из тега `v0.1.0-beta.1`:

  | Что | Версия |
  |---|---|
  | образ | `0.1.0-beta.1` (`latest` и `0.1` — только у релиза) |
  | deb, rpm (внутри пакета) | `0.1.0~beta.1` |
  | бинарник, `manifest.json` `version`, имена файлов | `v0.1.0-beta.1` |

- Не тег релиза (`git describe`, `upgrade-base`, сборка CI по sha) —
  `0.0.0~dev.<описание>`, как раньше: ниже любого релиза.
- **Имена файлов без `~`:** `sard-agent_v0.1.0-beta.1_amd64.deb`,
  `sard-agent-v0.1.0-beta.1.x86_64.rpm` (форма тега, как у tar.gz). Версия с
  тильдой — только внутри пакета; `package-agent.sh` сверяет её с правилом.
- **Порядок проверяется, а не предполагается:** `deploy/release/version-order.txt`
  — цепочка тегов по возрастанию. `scripts/test-release-version.sh` (CI,
  задача `packages`) проверяет `dpkg --compare-versions` и `rpm.vercmp` для
  каждой пары, а сборки `0.0.0~dev.…` (среди них `0.0.0~dev.v0.0.1.rc1`
  выпущенного rc1) — ниже всех. Тест сервера читает тот же файл (признак
  «доступно обновление», SemVer 2.0 с предрелизами).
- **RPM:** ставится и обновляется (`rpm -Uvh`, работает без репозиториев) в
  проверках `install` релиза и в задаче `install-rpm` CI на Rocky 9 в
  контейнере с systemd; консоль предлагает rpm рядом с deb и tar.gz.
- **Программы агента — в `/usr/libexec/sard/`**, а не в `/usr/lib/sard/`.
  Проверка на ВМ Oracle Linux 9 с SELinux enforcing (журнал сессии) показала:
  политика метит `/usr/lib/sard/*` как `lib_t`, systemd не переводит процесс
  из такого файла в домен служб `unconfined_service_t`, агент остаётся в
  `init_t` и не может запустить restic (`permission denied`, отказ скрыт
  `dontaudit`). У `/usr/libexec/*` метка `bin_t` без настройки, переход есть.
  Ссылка `/usr/bin/sard-agent` остаётся. Выпущенный rpm `v0.0.1-rc1` на
  хостах с SELinux службу не запускает.
- **SELinux автоматически не проверяется** (решение владельца 2026-10-07:
  проверки на Oracle Linux и ВМ убраны). В контейнере SELinux выключен при
  любом образе, поэтому `install-rpm` дефект выше не видит; проверка на
  настоящем хосте RHEL-семейства — ручная (`docs/qa/agent-install.md`).

## Последствия

- `v0.0.1-rc1` остаётся единственным релизом старого вида; его пакеты
  (`0.0.0~dev.v0.0.1.rc1`) обновляются любой `0.1.0~…`. Его `SHA256SUMS` на
  GitHub не сходится с именами ассетов — исправлять выпущенный релиз не будем.
- Агент на предрелизе помечается устаревшим относительно более нового
  предрелиза или релиза; агент на git-сборке, `dev` или теге старого вида —
  никогда.
- `${VERSION#v}` в `release.yml` совпадает с `release-version.sh image` для
  тега, прошедшего задачу `version`; новые места берут версию образа у скрипта.

## Отвергнуто

- **`rc1` без точки** — ломает порядок SemVer на сервере (`rc10 < rc2`).
- **Тильда в именах файлов** с переименованием при загрузке на GitHub —
  подписанный `SHA256SUMS` назвал бы не те файлы, что лежат в релизе.
- **`dnf install ./файл.rpm` в консоли** — читает метаданные репозиториев и
  на хосте без интернета падает; U1b требует установки без сети.
- **SELinux в контейнере** — `getenforce` там `Disabled` при любом образе.
