# 0032 — Реализация REST API этапа 1 (S8b)

- Статус: принято
- Дата: 2026-10-01

## Контекст
S8a (ADR 0019) зафиксировал контракт и отвечал на всё 501. S8b реализует его
поверх доменных сервисов; спецификация —
`docs/specs/server/rest-api.feature`, решения владельца — `docs/open-questions.md`
(OQ-049, OQ-051…OQ-068).

## Решение
- **Слои.** Контроллеры (`api/*Controller.kt`) не меняются по смыслу: они
  зовут порты `*Api`; реализации `*ApiImpl` берут тенант у `TenantResolver`,
  зовут домен и переводят его виды в классы контракта. Тенант — только из
  сессии, чужой объект неотличим от несуществующего (404 с тем же телом).
- **Ошибки.** Один `ApiExceptionHandler`: исключения домена и запроса →
  problem+json классов `Problem`, `ValidationProblem`, `RunActiveProblem`,
  `TokenConflictProblem` (поля контракта, `detail` — null). Id в пути не UUID
  — 404; параметр запроса и тело — 422 `validation_failed` с полем (для тела —
  первое поле, на котором остановился Jackson, или пустое имя); отказ базы —
  503 `unavailable`, причина только в журнале (без `Detail:` PostgreSQL, где
  может быть строка с конфигом). `?status=` принимает только значения
  контракта: свойство-редактор в binder, потому что Spring при отказе
  конвертера откатывается к `Enum.valueOf` по имени константы.
- **Страницы.** Ключ — `(время, id)` по убыванию (`PageKey`), непрозрачный
  курсор — base64url от «список|время|id»: курсор чужого списка — 422. Домен
  просит `limit + 1` строк, чтобы знать, есть ли следующая страница. Время
  списков: `registered_at`, `created_at`, `queued_at`.
- **Агент.** Онлайн — по менеджеру стримов (ADR 0026), отозванный — всегда
  офлайн. Отзыв: одна транзакция под блокировкой строки агента (`Runs.start`
  берёт ту же блокировку в разделяемом режиме) отзывает агента и его
  сертификаты и переводит `queued`/`dispatched`/`running` шаги в `lost` с
  сообщением `agent revoked` (их запуски — `failed`); после фиксации
  закрывается открытый стрим с причиной `AGENT_REVOKED`. Отказ базы не
  отзывает и не закрывает.
- **Дубликат.** `agents.duplicate_session_at` пишет слушатель
  `duplicateDetected` (подтверждённый дубликат, ADR 0026, правило 2);
  не снимается; ошибка записи не рвёт стрим.
- **Токены.** Отозвать можно только активный: истёкший — отказ
  `token_expired`, использованный — `token_used` с агентом, отозванный —
  успех без изменений (`revokedAt` прежний).
- **Результаты.** Снимок пишется для любого шага с корректным `BackupOutput`;
  `snapshots.partial` — шаг не `succeeded`. Счётчики файлов — `run_steps.files_*`,
  `0` без итога — «неизвестно». Усечение лога — `LogPage.truncated`.
- **Контракт.** Расширения К1–К13 (docs/specs/server/rest-api.feature)
  внесены в аннотации сервера, экспорт и клиент консоли пересозданы
  (`make openapi`); 503 описан у каждой операции под `/api/v1`.
- **Тесты.** Каждый ответ HTTP-тестов проверяется по документу
  `/v3/api-docs` (`ContractCheck`: статус объявлен, тип содержимого объявлен,
  тело по схеме JSON Schema 2020-12).

## Последствия
- Консоль и `sardctl` получают рабочее API; логика (статус агента, пагинация,
  проверка конфига) остаётся на сервере.
- Отказ базы виден как 503 во всех операциях; журнал хранит причину.
