# 0041 — Журнал принятых команд агента и журнал агента

- Статус: принято (FXa); решение владельца D13 и ответы на вопросы фазы 1 — 2026-10-04; номер присвоен в X2c
- Дата: 2026-10-05

## Контекст
Исполнитель (A4) хранил на диске только результаты (`results/`) и надгробия
(`acked/`). Принятая или выполняющаяся команда жила только в памяти. После
перезапуска агента посреди шага исход зависел от того, дошёл ли до сервера
прогресс: шаг `dispatched` сервер отправлял повторно, и restic запускался
второй раз; шаг `running` терялся (`lost`). Это Д3 из
`docs/qa/t3-defects.md`. По логу агента ни один из этих случаев нельзя было
разобрать (Д4).

## Решение
- **Журнал принятых команд** — `journal/<hex(SHA-256(command_id))>.json`
  в каталоге состояния исполнителя, права 0600, каталог 0700, запись
  атомарная (временный файл → fsync → rename → fsync каталога). В записи:
  `version`, `command_id`, `accepted_at`, `started_at` и больше ничего (ни
  конфига, ни репозитория, ни тегов).
- Запись делается при приёме, до ACCEPTED, и перезаписывается со
  `started_at` при старте обработчика: один лишний fsync на шаг. Удаляется
  после того, как сохранён результат. Если сохранить результат не удалось,
  запись остаётся.
- Если записать команду нельзя, шаг получает REJECTED «cannot record the
  command: …»: ничего ещё не сделано, а запуск без записи вернул бы Д3.
- **D13.** При старте каждая запись без результата и без надгробия
  становится сохранённым FAILED «interrupted: agent restarted before the
  step finished». `started_at` берётся из журнала, если шаг стартовал,
  `finished_at` — момент старта агента. Результат уходит после Hello как
  обычный неподтверждённый (A3), в `running_command_ids` его нет. Повторный
  RunStep получает этот результат через обычную дедупликацию A4. Запись
  рядом с результатом или надгробием — остаток аварии, она удаляется.
- **Совместимость.** Версия — в каждой записи, как у `results/`. Хранилище
  без `journal/` читается как есть. Старый агент не читает `journal/`: при
  откате прерванные шаги снова станут `lost`, результаты не теряются.
- **Журнал агента** (`*slog.Logger`, info): транспорт — соединение,
  потеря (код gRPC), переподключение (попытка, задержка), Hello (числа),
  отправка результата и ResultAck; исполнитель — приём, старт, завершение,
  повтор и ответ на него, прерванные при старте; restic — старт и код выхода
  каждой команды с `command_id` шага (`CLI.ForStep`). Аргументы и вывод
  restic, конфиги и тексты результатов в журнал не пишутся. stderr restic
  идёт только в лог шага (A7c), `restic.Options.OnStderr` удалён.

## Последствия
- restic не запускается дважды для одного `command_id` ни при каком
  совпадении перезапуска агента и повторной отправки шага.
- Если restic успел записать снимок, а агент умер до сохранения результата,
  шаг всё равно FAILED; снимок остаётся в репозитории (связь снимка с шагом —
  Д5).
- Сервер должен принимать FAILED для шага, уже помеченного `lost`. Сейчас
  решение 6 S6a оставляет `lost`; изменение — в FXs.
