# 0045 — Собрать один раз, тестировать собранное

- Статус: принято (решение владельца: «это всё дефекты сборки»)
- Дата: 2026-10-06
- Связано: ADR 0018 (упаковка агента), ADR 0020 (e2e), ADR 0036 (плагин стенда за тегом), ADR 0039 (образ сервера и релиз), ADR 0040 (консоль в jar), ADR 0043 (подписанные пакеты)
- Меняет: ADR 0036 в части «весь e2e на сборке стенда», ADR 0020 в части «CI собирает образы в задаче e2e»

## Контекст

Исследование `ci.yml` и `release.yml` (до этого ADR):

- **CI.** Ни одного `needs:` и ни одного `download-artifact`: каждая задача
  собирала своё. sard-agent собирался четыре раза разными способами:
  `go (agent)`: `build-agent` и `make package`, артефакт никто не читал;
  `image`: снова `make package VERSION=ci`; `e2e`: `GO_TAGS=e2e`;
  `server`: `buildTestAgent` с версией `seam-test`. Jar сервера собирался в
  `image` и ещё раз в `e2e`. Образ, прошедший e2e, был не тем образом, что
  собрала `image`.
- **e2e тестировал не поставляемого агента.** Весь набор шёл на сборке с тегом
  `e2e` (ADR 0036), а не на агенте `make package`.
- **Релиз.** `install` собирал образ сервера из исходников, `image` собирал его
  заново для GHCR. Опубликованный jar не проверялся ничем, кроме наличия
  `SHA256SUMS.minisig`. e2e в релизе не было.

## Решение

**Каждый поставляемый артефакт собирает ровно одна цель Makefile и одна задача
workflow. Тестируют и публикуют этот артефакт; никто не собирает его заново.**

- **Цели Makefile.** У каждой цели один выход:
  - `package` → `DIST`, пакеты агента;
  - `package-stand` → `STAND_DIST`, сборка стенда, только для T3;
  - `server-jar` → `SERVER_JAR_DIR`, jar с консолью из `deploy/server/Dockerfile`.

  Сборка: `server-image`, `e2e-agent-images` и `e2e-assemble` только собирают
  образы из готовых артефактов и ничего не компилируют. `e2e-test` только
  запускает тесты. `e2e-images` и `e2e` — локальная обёртка: собрать всё один
  раз и сразу собрать из этого образы.
- **Dockerfile.** Jar — стадия `server-jar` (`FROM scratch`). Финальная стадия
  копирует jar из неё. `--build-context server-jar=<каталог>` подменяет стадию
  готовым jar, и стадии `web` и `build` не выполняются. Без подмены образ
  собирается из исходников, как раньше: `docker compose build`, `make up`.
- **CI** (`ci.yml`):
  - `packages` — единственная сборка агента: релизные пакеты amd64 и arm64,
    проверки подписи и отказа образа, пакеты стенда;
  - `server-image` — единственная сборка jar; из него образ для amd64 и arm64
    и `docker save` образа amd64 для e2e;
  - `e2e` — `docker load` этого образа; образы агента из тех же пакетов;
  - `server` — seam-тесты запускают агента из пакетов
    (`-PsardTestAgentBinary`, `-PsardTestAgentVersion`), а не собирают своего.

  Версия всех артефактов одного прогона одна: `VERSION=${{ github.sha }}`.
- **Релиз** (`release.yml`):
  - `server-jar` — единственная сборка jar;
  - `install` и новая `e2e` тестируют образ из этого jar и пакетов `build a`;
  - `sign` ждёт обе задачи;
  - `image` публикует образ из того же jar (`build-contexts`) и подписанных
    пакетов.

  Опубликованный образ отличается от протестированного только файлом
  `SHA256SUMS.minisig`, который появляется после тестов. Базовый слой JRE
  тот же тег `eclipse-temurin:25-jre`.
- **e2e на релизном агенте.** `e2e.agentImage` — образ из пакетов `make package`.
  Сборку стенда (`e2e.standAgentImage`) запускают только классы T3, которым
  нужен `e2e-slow`: `T3Agent`, `SlowStreamTest`. Тест
  `RunStepSeamTest.the agent of the suite is the release build without the stand plugin`
  доказывает, что основной агент набора — релизный: он отклоняет `e2e-slow`
  как неизвестный плагин. Сервер стенда раздаёт релизные пакеты, как в продукте.

## Что остаётся сборкой, но не поставляемым артефактом

- `build b` в релизе — вторая сборка для проверки воспроизводимости.
  Сравнивается, не используется.
- `dist-old` в `install` — фикстура: пакет более старой версии для проверки
  обновления.
- Сборка стенда (`GO_TAGS=e2e`) — фикстура T3. Её собирает та же задача и тот
  же скрипт, что и релиз; отличаются только тег и каталог (ADR 0036).
- Компиляция для тестов: `go test`, `:server:check`, `npm run build` в гейте
  web. Гейты проверяют исходники. Поставляемые артефакты из них не берутся;
  консоль в jar собирает стадия `web` Dockerfile.

## Последствия

- `server`, `server-image` и `e2e` в CI ждут `packages`. Цена — время сборки
  пакетов на критическом пути. Зато всё, что проверяет CI, — это то, что
  ушло бы в выпуск.
- `E2E_SERVER_BUILD_FLAGS` переименован в `SERVER_BUILD_FLAGS`: флаги
  относятся к сборке jar, а не к e2e.
- `make package` принимает `DIST` и `ARCHES`; `make image` = `package` +
  `server-jar` + `server-image`.
- Отвергнуто: брать консоль из гейта web (`--build-context console=web/dist`).
  Тогда у CI и релиза были бы разные рецепты консоли, а стадия `web`
  Dockerfile нигде бы не проверялась.
- Отвергнуто: убрать тег `e2e` и замедлять бэкап снаружи (throttling
  хранилища). Это новая зависимость и переделка T3. Вместо этого сборка стенда
  ограничена классами T3, а остальной набор идёт на релизном агенте.
