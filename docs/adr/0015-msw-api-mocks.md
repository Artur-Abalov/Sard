# 0015 — Моки API на MSW с типами из OpenAPI

- Статус: принято (W1a)
- Дата: 2026-09-27

## Контекст
Страницы этапа 1 (W2) делаются раньше, чем REST API этапа 1 появится в OpenAPI (S8). Нужны моки, которые одинаково работают в dev-сервере и в Vitest и не расходятся со схемой: мок, который отвечает не по схеме, скрывает ошибку до встречи с настоящим сервером.

## Решение
- MSW 2: общие обработчики в `web/src/mocks/handlers.ts`. В dev они включаются переменной `VITE_API_MOCKS=1` (service worker), в Vitest — через `msw/node` в setup-файле с `onUnhandledRequest: 'error'`.
- Типизация — `openapi-msw` (`createOpenApiHttp<paths>()` из `src/api/schema.d.ts`). Путь, параметры, статус и тело ответа проверяются по схеме, неверный ответ — ошибка `tsc` (`src/mocks/contract.typecheck.ts`). Своя обёртка повторила бы то же самое: вывод типов по `paths`, статусу и content-type — это и есть весь код `openapi-msw`. Пакет маленький, лицензия MIT, из зависимостей только peer `msw`.
- Скрипт воркера (`mockServiceWorker.js`) не коммитится и не лежит в `public/`. Его отдаёт из `node_modules/msw` плагин Vite с `apply: 'serve'`. Поэтому версия воркера всегда совпадает с установленной `msw`, а в `dist` его нет.
- В `main.tsx` импорт `./mocks/browser` стоит под `import.meta.env.DEV && VITE_API_MOCKS === '1'`. В production-сборке условие статически ложно, и MSW не попадает в бандл. Рендер ждёт запуска воркера, чтобы первые запросы уже шли в моки.
- В dev необработанный запрос к `/api/` выводится ошибкой MSW в консоль, остальные запросы (модули Vite, статика) проходят мимо.
- Клиент API обращается к `location.origin` вместо относительного `/`. В браузере это тот же origin. У `fetch` вне страницы базового URL нет, поэтому setup-файл Vitest подставляет `location` страницы.
- `server.listen()` вызывается на верхнем уровне setup-файла, а не в `beforeAll`: `openapi-fetch` запоминает `globalThis.fetch` при создании клиента, то есть при импорте модуля. Если перехват включить позже, запросы клиента идут в сеть (проверено: `ECONNREFUSED`).

## Отвергнуто
- Собственная тонкая обёртка над `http` из MSW — повторяет `openapi-msw`, её типы пришлось бы сопровождать самим.
- `msw init` в `public/` с коммитом или `postinstall` — сгенерированный файл в репозитории (решение владельца: не коммитим), и он попадает в `dist`.
- DOM-окружение Vitest (jsdom, happy-dom) ради `location` — новая зависимость ради одного базового URL.
- Передавать в клиент `fetch: (r) => fetch(r)` — лишний код в клиенте, когда хватает раннего `listen()` в setup-файле.
