# 0056 — Во встроенном реестре агента только работающие плагины

- Статус: принято (Q2, принцип 5 финализации этапа 1: «не обещать того, чего нет»); решения владельца — 2026-10-12
- Дата: 2026-10-12
- Связано: ADR 0027 (SDK плагинов), ADR 0036 (тег сборки `e2e`), ADR 0051 (плагин postgresql)

## Контекст

Со скелета агент собирал четыре плагина: `files`, `postgresql`, `mysql` и `network`
(MikroTik, Eltex). Два последних были заглушками: `Prepare`, `Dump` и `Stream`
возвращали `sdk.ErrNotImplemented`. Агент объявлял их серверу в Register с действиями
`backup` и `restore`, консоль предлагала их в форме источника, а запуск падал с «not
implemented». README в первом абзаце обещал MySQL и MikroTik/Eltex. Внешнее ревью
2026-10-11 (пункт 7) назвало это обещанием того, чего нет.

## Решение

- Пакеты `agent/plugins/mysql` и `agent/plugins/network` удалены. Встроенный реестр
  (`plugins.Builtin`) — только `files` и `postgresql`; сборка стенда добавляет `e2e-slow`
  (ADR 0036). Протокол Register не меняется.
- Плагин попадает в `Builtin`, только когда он бэкапит и восстанавливает и описан в
  `docs/plugins/<имя>.md`. Заглушку за тегом сборки (`dev`) не держим: это код без
  пользы, который гейт заставлял бы покрывать тестами и мутациями.
- Архитектурный тест `agent/plugins/release_test.go` держит правило:
  - каждый пакет плагина под `agent/plugins/` подключён релизной сборкой или сборкой
    стенда (`go list` без тега и с тегом `e2e`): отложенная заглушка — мёртвый код;
  - у каждого плагина релизной сборки есть `docs/plugins/<имя>.md`.
- README и консоль называют доступными только `files` и `postgresql`. Будущие источники
  перечислены в `docs/roadmap.md` и `docs/roadmap.en.md` с пометкой «план, не обещание»;
  выбирают их первые пользователи (B5, D22).
- Источник, созданный раньше с плагином, которого агент больше не объявляет, особой
  отметки не получает (решение владельца): Register заменяет набор плагинов агента
  целиком, источник остаётся. Ручной запуск получает 409 `unknown_plugin`, срабатывание
  расписания — строку журнала `REFUSED` (`UNKNOWN_PLUGIN`) и алерт после серии пропусков,
  форма правки — предупреждение «агент больше не предлагает плагин». Ошибок 500 нет.

## Последствия

- Агент 0.1.x не объявляет `mysql` и `network`. Источник такого типа в существующей
  базе можно удалить или перевести на другой плагин.
- Новый источник (1С, MySQL, сетевые устройства) появляется вместе с работающим
  плагином, его страницей в `docs/plugins/` и строкой в README.
- Отвергнуто: **оставить заглушки за тегом `dev`.** Сборка, которую никто не выпускает,
  но которую гейт проверяет; пример для авторов плагинов они не давали — SDK на них не
  ссылается. **Отметка «плагин недоступен» на карточке источника.** Меняет контракт API
  ради случая, который даёт только этот переход; владелец решил не делать.
