# 0020 — Сквозные тесты: Testcontainers для JVM, образы из текущего кода

- Статус: принято (T2a)
- Дата: 2026-09-28

## Контекст
Нужны сквозные тесты на настоящих контейнерах: PostgreSQL, `sard-server`, `sard-agent`. Тестам надо и создавать токены на стороне сервера, и выполнять регистрацию как агент. REST создания токена пока отвечает 501 (S8b), команды `sard-agent enroll` нет (A2). В `test/e2e` до этого лежал только README.

## Решение
- **Kotlin/JVM, Gradle-модуль `:e2e` в `test/e2e`, Testcontainers-java.** Testcontainers 2.0.5, BouncyCastle, драйвер PostgreSQL, grpc-netty и `:proto-jvm` уже были в проекте. Новых библиотек нет. Код сервера модуль не импортирует: тесты видят систему снаружи, как агент или оператор. В `settings.gradle.kts` модуль включается, только если `test/e2e/build.gradle.kts` существует: образ сервера копирует без `test/`.
- **Модуль — тесты, не продукт.** В `scripts/gate.sh` не входит, покрытие, CRAP, сложность и мутации к нему не применяются. SPDX-заголовки обязательны, как везде.
- **Образы собирает `make e2e-images` до тестов.** Сервер собирается из `deploy/server/Dockerfile`, агент — из tar.gz `scripts/package-agent.sh` (ADR 0018), поэтому restic в образе тот же и так же проверен по SHA-256 (ADR 0017), а во время теста ничего не скачивается. База образа агента — distroless static, раскладка файлов как в пакете. Тесты получают теги и версию системными свойствами.
- **Одна установка на тестовый класс (`SardEnvironment`)** со своей сетью. Порты хоста случайные, пароль БД случайный. Сервер запускается с `SARD_PKI_SERVER_NAMES=sard-server` и `SARD_AGENT_ENDPOINT=sard-server:9090`: TLS проверяется по имени, которое набирает агент.
- **Логи.** Вывод каждого контейнера копится с момента старта. При падении теста или старта он пишется в `test/e2e/build/e2e-logs/`, а токены, PEM-ключи и зарегистрированные секреты заменяются маской. В CI каталог выгружается артефактом.
- **Единые точки замены.** `EnrollmentTokens.create` пишет строку `enrollment_tokens` строго по `docs/specs/enrollment-token.md`, отпечаток берётся из цепочки TLS; после S8b — `POST /api/v1/enrollment-tokens`. `AgentEnroller.enroll` — минимальный клиент Enroll со сверкой отпечатка; после A2 — `sard-agent enroll` в контейнере агента.
- **Заготовки — классы без тестовых методов** с условием включения и шагами в KDoc. `@Disabled`, `@EnabledIf` и подобные не используются (CLAUDE.md, правило 2).
- **CI:** задача `e2e` на каждый PR. ~~Образ сервера собирается buildx с кэшем `type=gha`.~~ С ADR 0045 задача e2e ничего не собирает: образ сервера — из задачи `server-image`, образы агента — из пакетов задачи `packages`.

## Отвергнуто
- **testcontainers-go.** Язык будущего `sard-agent enroll` значения не имеет: его вызовут внутри контейнера. testcontainers-go тянет Docker-клиент с десятками модулей, а для токенов понадобился бы ещё драйвер PostgreSQL. Кроме того, Go-модуль подпал бы под гейт с покрытием и мутациями.
- **docker compose из `deploy/`.** Фиксированные имена и порты не дают тестам быть независимыми от порядка и от уже запущенных контейнеров. `deploy/docker-compose.yml` остаётся для разработки.
- **Тестовая ручка на сервере для выпуска токенов.** Продакшн-код ради тестов. Запись в БД по спецификации временна и заменяется одним вызовом.
- **Сборка образа агента из исходников в Dockerfile со скачиванием restic.** Тогда в образе был бы не поставляемый пакет, а скачивание шло бы при каждой сборке образа.

## Изменения T2b (2026-10-04)

- **Хост агента — именованные тома, команды — разовые контейнеры (`AgentHost`).** В distroless-образе агента нет оболочки, поэтому `docker exec` сценария не годится. Диск хоста — два именованных тома в `/var/lib/sard-agent` и `/var/cache/sard/restic`: Docker заполняет пустой том каталогом образа с владельцем 65532. Каждая команда оператора — `sard-agent enroll`, `sard-agent repo init`, `restic restore` — и сам агент — отдельный контейнер образа на этих томах с программой в точке входа. Тома создаёт и удаляет `SardEnvironment` (с метками сессии Testcontainers). Отвергнуто: второй образ с оболочкой (тогда тесты проверяли бы не поставляемую раскладку) и запуск команд внутри живого контейнера агента (агенту без файлов TLS не стартовать, а регистрация — первый шаг).
- **Точки замены закрыты.** Регистрация — только `sard-agent enroll` (токен файлом, не в командной строке), Kotlin-клиент Enroll и BouncyCastle из модуля удалены. Токены, источники и запуски — REST S8b. Строки SQL остаются только у швов S6a/S7a, которым нужен источник с плагином, которого у агента нет (REST его отклоняет).
- **Восстановимость доказывается побайтово.** Данные генерируются из фиксированного зерна, эталон снимается при генерации, до копирования на хост; восстановленное дерево выгружается `docker cp` архивом и сравнивается целиком (`TreeDiff`, покрыт своим тестом без контейнеров).
- **Ожидание — `Await`** (опрос с таймаутом), без фиксированных пауз в новых тестах.
