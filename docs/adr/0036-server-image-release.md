# 0036 — Образ сервера и релиз: GHCR, мультиархитектура, офлайн-архив

- Статус: принято (решения владельца, 2026-10-04, X1 контрольная точка 1)
- Дата: 2026-10-04

## Контекст

Демо этапа 1 должно подниматься на чистой ВМ из опубликованного образа, а не из
исходников. До X1 образ сервера только собирался в CI (`image`) и для e2e
(`make e2e-images`), нигде не публиковался, был одноархитектурным, без
HEALTHCHECK и VOLUME; `deploy/docker-compose.yml` собирал образ локально.
Первая целевая площадка владельца — OCI (Ampere A1, arm64) за Cloudflare.

## Решение

- **Реестр — только GHCR**, `ghcr.io/artur-abalov/sard-server`. Публикует
  `release.yml` штатным `GITHUB_TOKEN` (`packages: write`), внешних секретов нет.
  Docker Hub и зеркала для РФ не делаются, пока развёртывание только своё.
  PostgreSQL берётся как есть, `postgres:18-alpine`.
- **Релиз — по тегу `v*`.** Тег `vX.Y.Z[-pre]` даёт образ `X.Y.Z[-pre]`; `X.Y`
  и `latest` — только у релиза без суффикса, предрелиз их не двигает.
  GitHub Release с тегом с `-` помечается предрелизом. Версия в образе
  (`/api/v1/status`, OCI-метка) — тег без `v`.
- **amd64 и arm64.** Стадия сборки jar идёт на платформе сборщика
  (`--platform=$BUILDPLATFORM`): jar не зависит от процессора, Gradle под QEMU
  не запускается. Под QEMU выполняется только `useradd` стадии запуска.
- **Образ:** пользователь `sard` (uid 10001); `VOLUME /var/lib/sard/pki` (ключ
  CA); `HEALTHCHECK` по `/actuator/health` через bash `/dev/tcp` (curl в JRE-образе
  нет), порт — `SARD_HTTP_PORT`; секретов в образе нет; `.dockerignore` —
  белый список того, что читает Dockerfile.
- **Офлайн-архив** — артефакт релиза: `docker save` сервера и PostgreSQL на
  каждую архитектуру (`scripts/offline-archive.sh`), рядом `docker-compose.yml`,
  `sard.env.example` с версией релиза и `SHA256SUMS`.
- **Compose** берёт опубликованный образ, версия — `SARD_VERSION` в `.env`;
  `restart: unless-stopped`; имя проекта и тома прежние (`sard_postgres-data`,
  `sard_sard-pki`), миграции данных нет. Локальная сборка из исходников —
  `deploy/docker-compose.build.yml`, его подключает `make up`.
- **HTTP-порт публикуется на `127.0.0.1` по умолчанию.** По нему идёт пароль
  администратора открытым текстом, пока перед сервером нет TLS
  (`SARD_HTTP_PUBLISH` расширяет). Порт агентов 9090 открыт: это mTLS, и
  проксировать его можно только как TCP.
- **Проверка релиза в CI:** quickstart из README выполняется дословно (меняется
  только `SARD_TAG`) на чистых раннерах amd64 и arm64 с анонимным доступом к
  реестру; офлайн-архив загружается и стартует с `--pull never`;
  `scripts/smoke-server.sh` проверяет health, версию, вход администратора и TLS
  порта агентов с сертификатом от CA сервера.

## Рассмотренные альтернативы

- **Docker Hub рядом с GHCR.** Отложен владельцем: нужны секреты и
  пространство имён, а пользователь пока один.
- **Сборка jar под каждую архитектуру.** Медленно (Gradle под QEMU) и бессмысленно:
  байткод одинаков.
- **Публикация `latest` на каждый тег.** Предрелиз — «мусорная сборка» по
  определению владельца; `latest` должен указывать на релиз.

## Последствия

- Первая публикация создаёт пакет в GHCR. Если пакет не стал публичным
  (наследование видимости от публичного репозитория), анонимный quickstart в
  `release.yml` упадёт, и видимость меняет владелец в настройках пакета.
- Консоль в образ пока не входит: отдача SPA сервером — отдельная задача
  через `/ship-feature` (решение владельца, X1). Пакеты агента в образе — U1a.
- arm64-сборка проверяется в CI (`image`) и в релизе; локально в облачной
  среде Claude Code её не проверить (нет binfmt, Docker Hub отвечает 429).
