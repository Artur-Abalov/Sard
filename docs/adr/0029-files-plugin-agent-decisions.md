# 0029 — Плагин files (A6b): решения на стороне агента

- Статус: принято
- Дата: 2026-09-30

## Контекст
Плагин files (A6b) первым использует SDK (ADR 0027) для бэкапа каталогов и
потребовал нескольких решений, которые ADR 0027 не покрывает или меняет.
Архитектурное ревью A6b потребовало зафиксировать их (правило 8).

## Решение
1. **`pluginhost.RestoreDeferred`.** Плагин files объявляет действие RESTORE
   раньше, чем оно реализовано (Ф5): шаг падает с понятным сообщением, restic
   не запускается, диск не меняется. Интерфейс
   `RestoreNotImplemented() string` живёт в `agent/internal/pluginhost`, а не
   в SDK: это временная особенность встроенного плагина, публичный
   Apache-2.0 контракт не должен получать метод, который сторонним плагинам
   не нужен и который придётся поддерживать. Он переопределяет путь RESTORE
   из ADR 0027 для files (снимок не восстанавливается в
   `<state_dir>/restore/<command_id>`) и сопоставляется неявно, по имени
   метода, а не объявлением в реестре. Условие удаления: настоящее
   восстановление files; тогда интерфейс, проверка в `handler.restore` и
   тесты удаляются.
2. **`sdk.Dump.OneFileSystem`.** Поле расширяет публичный Apache-2.0 SDK
   (аддитивно, обратно совместимо) и соответствует `restic --one-file-system`.
   Допустимо только для дампа по путям. Вместе с `Filename` (потоковый дамп)
   шаг падает: `restic.BackupRequest.validate` возвращает `ErrInvalidRequest`
   для stdin вместе с `Paths`, `Excludes` или `OneFileSystem`, а
   `Source.request` передаёт эти поля и в потоковой ветке, чтобы проверка их
   видела. Такая ошибка — вина плагина, поэтому обработчик не добавляет к ней
   приставку `repository "R":`.
3. **`--retry-lock 5m` у каждого бэкапа каждого плагина** (Ф10). Значение
   зашито в агенте (`lockWait`) сознательно на этапе 1: одно поведение для
   всех, срок ограничен таймаутом шага. Настройка на источник или репозиторий
   отложена до появления потребности.
4. **Ф12: код выхода 0 у restic сильнее отменённого контекста.** Если restic
   завершился успешно и вывел итог, снимок полный: обёртка возвращает итог, а
   не ошибку отмены, шаг — SUCCEEDED с `BackupOutput`. Иначе сервер не узнал
   бы о существующем снимке.
5. **Разбор строки stderr `<path> does not exist, skipping`.** Это не JSON,
   так что путь и причина берутся из текста строки. Формат привязан к
   закреплённой версии restic (`agent/internal/restic/restic-version`).

## Оборотная сторона
- Пункт 5 — известная связанность с текстом restic, того же рода, что строка
  о SIGTERM в ADR 0027 «Оборотная сторона»: смена формулировки в новой версии
  restic не сломает сборку, но путь пропадёт из сообщения. Интеграционные тесты
  с закреплённой версией это ловят; при обновлении restic строку проверять.
- `RestoreDeferred` сопоставляется по имени метода: опечатка молча отключает
  его. Покрыто тестом `TestRestoreOfAPluginThatCannotRestoreYetFailsWithoutTouchingTheDisk`.
- Единое значение `--retry-lock` удлиняет ожидание шага при зависшей
  блокировке до 5 минут для всех плагинов.
