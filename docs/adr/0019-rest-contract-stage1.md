# 0019 — Контракт REST API этапа 1: заглушки на сервере и общие соглашения

- Статус: принято (S8a)
- Дата: 2026-09-27

## Контекст
Страницам этапа 1 (W2) нужен контракт REST API раньше, чем появятся S4, S6 и S7, на которых он будет реализован (S8b). OpenAPI сейчас генерирует springdoc из контроллеров сервера (ADR 0010, 0011). Отдельного файла-спецификации нет. CI сверяет экспорт сервера с `web/src/api/openapi.json`, а `schema.d.ts` — с `gen:api`.

## Решение
- **Контракт — это контроллеры-заглушки.** Полные DTO, перечисления и аннотации springdoc лежат в `server/.../api`. Тело каждого метода — `notImplemented()`: ответ 501 `application/problem+json` с `code: not_implemented`. S8b меняет только тела методов. Источник истины остаётся один, и тест контракта — `ApiContractIntegrationTest` — проверяет, что каждая операция спецификации отвечает 501, пока её не реализовали.
- **Обязательность полей.** Nullability Kotlin до springdoc не доходит: его model resolver читает классы через Jackson 2, а Kotlin-модуль в проекте есть только для Jackson 3. Поэтому `OpenApiCustomizer` `requireConstructorParameters` считает поле обязательным, если у параметра первичного конструктора нет значения по умолчанию. Nullable-поле при этом присутствует и равно `null`. Схема сопоставляется с классом пакета `api` по имени. Необязательное поле тела запроса объявляется с `= null`. `default` в схеме тела не ставится: openapi-typescript делает такое поле обязательным.
- **Перечисления** — `@Schema(enumAsRef = true)`, значения в `lower_snake_case` через `@JsonProperty`, как CHECK схемы (ADR 0013, правило 7). Тест сверяет `StepPhase`, `LogLevel`, `StepAction` и финальные значения `StepStatus` со значениями proto, поэтому расхождение ломает сборку сервера. У статуса запуска нет аналога в proto: он проверяется списком.
- **Перечисления в query** принимают те же значения, что и в JSON (`?status=timed_out`): `WireEnumConverterFactory` сопоставляет строку со значением `@JsonProperty`. По умолчанию Spring ищет константу по имени (`TIMED_OUT`) и отвечает 400.
- **Ошибки** — RFC 9457, `application/problem+json`, `spring.mvc.problemdetails.enabled`. Машинный код — перечисление `ErrorCode`. Для ошибок с дополнительными полями есть отдельные схемы: `ValidationProblem` (`errors[].field`), `RunActiveProblem` (`activeRunId`) и `TokenConflictProblem` (`agentId`).
- **Сессия** — схема `apiKey` в cookie `sard_session`, заданная как требование на корне документа. Публичные операции (`POST /api/v1/session`, `GET /api/v1/status`) объявляют пустое требование. `OpenApiCustomizer` `describeUnauthorized` добавляет 401 каждой операции, которая наследует корневое требование.
- **Пагинация** — курсорная: параметры `cursor`, `limit` (1–200, по умолчанию 50), ответ `{items, nextCursor}`. Логи шага листаются по `seq`: параметр `afterSeq`, ответ `{items, nextAfterSeq, hasMore}`. Это позволяет W2 дочитывать хвост идущего шага опросом.
- **`servers: [{url: "/"}]`.** Консоль и API живут на одном origin. Раньше экспорт вырезал `servers` со случайным портом теста, теперь он задан явно.
- **Если у метода есть хоть одна `@ApiResponse`, springdoc не добавляет ответ 200 по умолчанию.** Поэтому у таких методов стоит явный `@ResponseStatus`. Тест проверяет, что у каждой операции описан ответ 2xx.
- **Линтер спецификации** — `@redocly/openapi-core` (движок `redocly lint`, правила `recommended`) через `npm run lint:api`, в составе `npm run lint`, то есть гейта web. Предупреждения тоже роняют проверку. Отключено одно правило, `operation-4xx-response`: у `GET /api/v1/status` нет входных данных и нет ни одной клиентской ошибки, а у остальных операций есть хотя бы 401.

## Отвергнуто
- **Файл-спецификация как источник истины.** Он развернул бы ADR 0010. В S8b понадобился бы генератор серверных интерфейсов (новая зависимость) или тест «экспорт springdoc совпадает с файлом» — двойная работа.
- **`requiredMode = REQUIRED` на каждом поле.** Около 150 аннотаций, которые повторяют типы Kotlin. Забытая аннотация незаметно делает поле необязательным.
- **`@redocly/cli`.** Тянет redoc, react, styled-components и OpenTelemetry ради одной команды `lint`. `openapi-core` уже стоял транзитивно через openapi-typescript.
- **Выдуманный 4xx у `/status` ради правила линтера.** Контракт описывал бы несуществующий ответ.
