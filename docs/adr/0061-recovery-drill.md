# 0061 — Учения восстановления сервера: «ВМ» в Docker, блоки страницы как написаны

- Статус: принято (F7, Р39–Р41, OQ-218, OQ-221; решения владельца 2026-10-14)
- Дата: 2026-10-14

## Контекст
Страница `docs/operator/12-server-recovery.md` годится, только пока её команды
работают. Ручная проверка (`docs/qa/server-recovery.md`) бывает редко, а
страница стареет с каждым изменением compose, CLI агента или REST. Нужен тест,
который проходит страницу командами из неё самой, на машине, где нет ничего,
кроме того, что есть у администратора в аварии.

## Решение
- **Класс `ServerRecoveryDrillTest`** в `test/e2e`. «ВМ» — привилегированный
  контейнер `sard-recovery-vm:e2e` (`test/e2e/recovery-vm`): Ubuntu, свой демон
  Docker (свои тома, порты и контейнеры), bash, coreutils, curl, compose; ни
  restic, ни psql, ни jq, ни python, ни openssl. Хранилище — Garage стенда F2
  вне обеих ВМ; агенты A1–A3 — контейнеры вне ВМ. Сеть учений `internal`: у
  машин нет выхода в интернет и к реестрам, образы идут `docker load` из
  офлайн-архива, собранного из образов сборки.
- **Старая ВМ** ставится и наполняется кодом теста (мастер F4a, самобэкап в S3,
  агенты, запуски) и уничтожается вместе с томами. **Новая ВМ** получает только
  то, что есть у администратора: адрес и ключи хранилища, пароль репозитория,
  поля карточки, пароль администратора.
- **Блоки страницы выполняются как написаны.** Блок, который выполняют учения,
  помечен строкой `<!-- drill: id -->` перед блоком `bash`. Значения в угловых
  скобках (`<repositoryId>`) подставляются из таблицы учений по имени; неизвестное
  имя или повтор id останавливают учения до выполнения первого блока
  (`DrillPage`). Секреты вводятся на стандартный ввод блока (`read -rs`), в
  командах их нет. Английская страница обязана содержать те же блоки
  (`ServerRecoveryDocsTest`).
- Эмулируются только перевод DNS (сетевой псевдоним имени сервера переходит на
  новую ВМ) и гибель старой ВМ. Блок «повторная регистрация» идёт в оболочке
  хоста агента A3 (`sudo` выполняет команду, `systemctl` и `journalctl` только
  отвечают), после чего учения запускают службу заново, как это сделал бы
  systemd.
- **Время** — от начала первого блока на новой ВМ до health сервера, до online
  всех старых агентов после перевода имени и до успешных запусков самобэкапа;
  размеры дампа и базы. Итог — `test/e2e/build/recovery-drill/result.json` и
  `result.md` (строка таблицы страницы «Сколько это займёт»). Длительность тест
  не утверждает (общий раннер CI); строку в страницу переносит человек.

## Последствия
- Страница и учения меняются вместе: блок меняется — меняются оба языка, иначе
  падает `ServerRecoveryDocsTest`; команда блока перестала работать — падают
  учения.
- Учения долгие (минуты на ВМ, расписание A1 — раз в минуту), поэтому живут в
  шарде e2e, а не в быстром тесте.
- Новых зависимостей нет: чтение JSON ответов REST — собственная маленькая
  `Json`, процессы ВМ запускает `docker exec -i`.
