# 00XX — Онбординг: самобэкап, подтверждение копии ключей и ограничение D8 (черновик)

- Статус: черновик до слияния F4b (номер — при слиянии); решения владельца 2026-10-12, все предложения specifier OQ-201…OQ-210 утверждены («Делай. Со всем согласен»)
- Дата: 2026-10-12
- Дополняет: ADR первого запуска (`00XX-draft-f4a-first-start.md`), черновик ADR самобэкапа (`00XX-draft-self-backup.md`)
- Спецификация: `docs/specs/server/onboarding-self-backup.feature` (К10–К17, Р20–Р30), `docs/specs/web/onboarding-self-backup.feature` (Рк9–Рк18); журнал — `docs/sessions/2026-10-12-f4b-onboarding-self-backup.md`

## Контекст
Сервер Sard не должен начинать собирать бэкапы чужих машин, пока сам не защищён:
есть успешный бэкап его базы и ключей в хранилище вне этой ВМ, а владелец знает,
где взять пароль репозитория (D8). F4a оставил шаги `self_backup` и
`keys_confirmed` заготовками в состоянии `upcoming`; F6 дал механику самобэкапа.
Пароль репозитория и ключи хранилища живут на хосте соседа `sard-self` и до
сервера не доходят (ADR 0008).

## Решение
- **Шаги выводятся из состояния, не хранятся.** `self_backup` — `done`, когда
  оба системных источника тенанта по умолчанию имеют успешный запуск, поставленный
  не раньше `boundAt` текущей привязки; `keys_confirmed` — `done`, когда записан
  шаг в `onboarding_steps`. Онбординг завершён первым подтверждением и не
  отменяется ничем: ни сбоем самобэкапа, ни новой привязкой, ни `admin-reset`
  (шаги завершённого онбординга остаются `done`).
- **Ограничение `restriction` (full / new_agents / none) вычисляется на каждый
  запрос**: `none` — есть шаг `keys_confirmed`; `new_agents` — нет, но в
  `onboarding_marks` есть отметка `upgraded`; `full` — иначе. Отметку один раз
  ставит миграция `V202610121300`: если в базе есть живой обычный агент или
  неудалённый источник администратора. Отдельная таблица, а не строка
  `onboarding_steps`: это отметка установки, а не шаг мастера.
- **D8 — `HandlerInterceptor`**, а не фильтр: он идёт после фильтров Origin (403)
  и сессии (401) и до разбора тела, а исключения из него доходят до
  `@RestControllerAdvice` (503 при недоступной базе, 409 `onboarding_incomplete`).
  Правила — один объект `OnboardingRules`; он же определяет, какие операции
  документирует OpenAPI (409 для не разрешённых мутаций, `anyOf` с собственным
  409 операции). Разрешены: сессия и пароль, мастер, `PUT /self-backup/repository`,
  `POST /self-backup/runs`, `POST /self-backup/keys-confirmation`, расписание
  системного источника, отзыв встроенного агента с подтверждением (OQ-209).
  Планировщик и запуск расписаний ограничение не смотрят.
- **Enroll.** Обычный токен до завершения онбординга — `FAILED_PRECONDITION`,
  причина `ONBOARDING_INCOMPLETE`, токен не расходуется; встроенный токен
  работает (OQ-201). Проверка идёт до транзакции регистрации: внутри неё второй
  запрос к базе на каждую регистрацию ждал бы соединений, которые держат сами
  транзакции (при десяти одновременных регистрациях пул встаёт).
- **Команду `repo add` собирает сервер** (`RepositoryCommands`), без секретов:
  разовый `docker compose run … self-agent repo add …` и перезапуск соседа
  (OQ-204); идентификатор ключа S3 команда спрашивает в терминале, секретный ключ
  спрашивает `repo add` (OQ-205); имя репозитория — первое свободное среди
  репозиториев последнего Register (OQ-210); локальное хранилище — внутри тома
  соседа (OQ-208). Значения проверяются по наборам знаков Р29 и вставляются
  в одинарных кавычках. Отпечаток ключа хоста по формату (`SHA256:` и 43 знака
  base64) не содержит знаков, которые читает оболочка, и идёт как есть.
- **Адрес хранилища без учётных данных** (`location`, 1024 знака, без
  `user:password@` и управляющих символов) хранится при привязке для карточки
  восстановления (OQ-203); подтверждение копии ключей хранится в привязке
  (`keys_confirmed_at`) и считается подтверждением, только если оно не раньше
  `boundAt` — новая привязка снова просит его и даёт предупреждение
  `keys_unconfirmed` после онбординга (OQ-206). Предупреждение не портит
  здоровье самобэкапа.
- **Карточка восстановления** (`recoveryCard`): имя и тип репозитория, адрес,
  id, отпечаток CA, версия, время, ссылка на процедуру тега версии (для версии
  без тега — на `main`); пароля и учётных данных нет (OQ-202).
- **Границы пакетов.** Самобэкап, регистрация и REST спрашивают онбординг через
  свои порты (`OnboardingCompletion`, `RegistrationGate`, `GuardTargets`),
  которые реализует пакет `onboarding`: без этого пакеты `selfbackup`,
  `enrollment` и `onboarding` зависели бы друг от друга по кругу.
- **Консоль** не принимает решений: защитник маршрутов спрашивает состояние
  онбординга при действующей сессии; экран мастера выбирается по шагам сервера;
  привязку после команды консоль делает сама, опрашивая состояние соседа;
  время расписания переводится в cron чистой функцией. Тексты шага копии ключей —
  только ключи `setup.keys.*`.
- **Фикстуры.** Контекст тестов сервера стартует с завершённым онбордингом
  (шаг записан в `TestcontainersConfiguration`); тест первого запуска убирает его
  и возвращает. Скрипты и e2e, не про первый запуск и без `sard-self`, пишут шаг
  в базу так же, как записало бы подтверждение.

## Отвергнуто
- Хранить `self_backup` как строку `onboarding_steps`: состояние расходилось бы с
  запусками при смене привязки и откате сбоев.
- Фильтр сервлетов для D8: он не видит исключений контроллерных советов и
  отвечал бы на недоступную базу сам.
- Перечислять запрещённые операции вместо разрешённых: новая изменяющая операция
  оказывалась бы открытой по умолчанию.
- Сервер принимает идентификатор ключа S3 и секреты в форме мастера: нарушает
  ADR 0008.

## Последствия
- Новая изменяющая операция REST по умолчанию закрыта до конца онбординга;
  открыть её — строка в `OnboardingRules`.
- Сервер без соседа (`SARD_SELF_DIR` пуст) онбординг не завершит; кнопки
  «Пропустить» нет (OQ-207). В журнале и документации — раздел неполадок.
- Расписания источников администратора и системных источников работают до конца
  онбординга; ограничение — про изменения, а не про работу.
- Процедура восстановления (F7) пока ссылка на раздел документации.
- **Исключение из ADR 0008 — ожидает подтверждения владельца (pending owner sign-off).**
  Сервер теперь хранит адрес хранилища самобэкапа (без учётных данных; проверка
  в домене `selfbackup`, а не в REST) и сам составляет команду
  `docker compose run -u 0 --cap-add … self-agent repo add …`, которую владелец
  вставляет в оболочку root на машине сервера. Владелец читает команду до
  запуска; значения ограничены Р29 и заключены в одинарные кавычки; ключ S3 и
  пароль репозитория через сервер не проходят. Параграф-исключение дописан в
  ADR 0008 так же, как исключение F5 (пароль роли `sard_self`), и не считается
  решением, пока владелец не подтвердит его.
