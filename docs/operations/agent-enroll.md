# Регистрация агента: `sard-agent enroll`

Команда `sard-agent enroll` (A2b) выдаёт хосту собственную идентичность —
ключ, сертификат и бандл CA сервера — по одноразовому токену из консоли.
Сценарии и решения владельца — `docs/specs/agent/agent-enroll.feature`;
код выхода закреплены там же (В3) и продублированы ниже. Формат токена —
`docs/specs/enrollment-token.md`. Ключ CA сервера и его резервное
копирование — `docs/operations/pki.md`.

## От чьего имени запускать

Команда неинтерактивна и ничего не создаёт, кроме файлов `tls.*` (и, под
`sudo`, их последнего каталога), поэтому её запускают через `sudo`:

```bash
sudo sard-agent enroll --server <адрес> --token <строка из консоли>
sudo systemctl enable --now sard-agent
```

Под `sudo` (поправка A8a, ADR 0048) файлы `tls.*` получают владельцем и
группой **пользователя службы** (`sard-agent`, или `service.user` основного
конфига): ключ — `0600`, сертификат и бандл — `0644`, при любой umask. Права и
владелец выставляются временному файлу до переименования, так что ни в один
момент целевой путь не принадлежит root; то же при `--force`. Иначе служба
отказалась бы стартовать (проверка A1: секретные файлы не должны быть
доступны никому, кроме владельца, и должны ему принадлежать).

- **Пользователь службы** выполняет команду как раньше (команда из консоли,
  которая запускает её от его имени, продолжает работать): файлы остаются его.
- **Любой другой пользователь** — отказ `PRIVILEGES_REQUIRED` (код 2) с
  подсказкой `sudo sard-agent enroll …`, до источника токена: токен не
  расходуется, сервер не вызывается.
- **Под `sudo` пользователя службы на хосте нет** — `SERVICE_USER_UNKNOWN`
  (код 2); пользователей LDAP и SSSD команда не видит (поиск по `/etc/passwd`
  и `/etc/group`).

Пакеты deb и rpm при первой установке создают каталог `/etc/sard/tls`
(владелец `sard-agent`, права `0700`), куда указывают пути `tls.*` из примера
конфига, а `/etc/sard` отдают группе `sard-agent` (`root:sard-agent`, `0750`);
обновление пакета эти каталоги не трогает. После установки из архива tar.gz
или при других путях `tls.*` создавать каталог вручную не нужно: под `sudo`
команда сама создаёт **отсутствующий последний каталог** каждого файла
`tls.*` (владелец и группа — пользователь службы, `0700`, при любой umask).
Отсутствующий промежуточный каталог — ошибка записи (код 7: сообщение
называет ключ `tls.*` и первый отсутствующий каталог), ничего не создаётся,
токен цел. Существующий каталог не меняется. Каталог, который создал
неудавшийся запуск, команда удаляет, если в нём нет других файлов. От
пользователя службы каталоги не создаются: отсутствующий — код 7, токен цел.

Пути `tls.*` и `server.address` берутся из `/etc/sard/agent.yaml`
(`--config` по умолчанию); `--server`, если задан, обязан совпасть с
`server.address` — это лишь проверка согласованности с командой из
консоли, конфиг им не пишется. Регистрация не пишет строку аудита и не
трогает службу: до неё служба не запущена, а итог успеха говорит её
запустить или перезапустить.

## Коды выхода (В3)

| код | класс             | когда |
|---|---|---|
| 0 | успех             | идентичность записана; также `--help` |
| 1 | ошибка агента     | `CSR_INVALID`, `HOSTNAME_INVALID`, непредусмотренный ответ сервера |
| 2 | использование     | флаги, источник токена, конфиг, формат токена, конфликт адреса; `PRIVILEGES_REQUIRED` (запуск не от root и не от пользователя службы), `SERVICE_USER_UNKNOWN` |
| 3 | отказ по токену   | `TOKEN_UNKNOWN`, `TOKEN_USED`, `TOKEN_EXPIRED`, `TOKEN_REVOKED` |
| 4 | идентичность есть | ключ или сертификат уже есть на хосте, `--force` не задан |
| 5 | доверие           | отпечаток CA сервера, имя хоста, прочие ошибки TLS, `TOKEN_FOREIGN_CA` |
| 6 | временная         | сервер недоступен, таймаут, `INTERNAL_RETRYABLE`, прерывание, идёт другая регистрация |
| 7 | запись            | каталог `tls.*` непригоден для записи или его родитель отсутствует, сбой записи файлов или смены владельца |

Та же таблица — в `sard-agent enroll --help`.

## Что делать при каждом коде

- **4 (идентичность есть).** На хосте уже есть `tls.cert_file` или
  `tls.key_file`. `--force` регистрирует новую личность (старый агент
  остаётся в консоли офлайн — отозвать его вручную); перерегистрация с
  сохранением личности пока не реализована.
- **6 (временная).** Токен цел, команду можно повторить тем же токеном.
  Если сообщение говорит «token may have been spent» — токен, возможно,
  уже использован (ответ не получен, но запрос мог дойти); при отказе
  `TOKEN_USED` при повторе нужен новый токен.
- **3, 5 (отказ по токену / доверие).** Токен не расходуется отказами по
  токену и доверию (кроме доставленного до сервера иска — проверяется на
  сервере); нужен новый токен из консоли для 3; для 5 — проверить адрес и
  токен (не перепутан ли сервер).
- **7 (запись).** Если хотя бы один из путей `tls.*` — каталог, символьная
  ссылка или что-то ещё, кроме обычного файла (или отсутствующего пути),
  команда отказывает до обращения к серверу: токен цел, сообщение называет
  ключ конфига (`tls.ca_file` и т. п.). Если же сбой произошёл после того,
  как сервер уже выдал сертификат (например, путь стал непригодным между
  проверкой и записью), сообщение называет `agent_id` — токен уже
  израсходован, нужен новый; выданный `agent_id` можно отозвать в консоли,
  если он не нужен.

## Проверить после успеха

```bash
openssl x509 -in /etc/sard/tls/agent.pem -noout -subject -ext subjectAltName
stat -c '%a %U %G' /etc/sard/tls/*
```

Ключ — `0600`, сертификат и бандл — `0644`, владелец и группа — пользователь
службы (обычно `sard-agent`); других файлов в `/etc/sard/tls` нет.
