# Ключ CA сервера: где лежит и почему его бэкапить отдельно

sard-server сам является удостоверяющим центром для своих агентов (ADR 0014).
Все сертификаты агентов подписаны ключом CA, а агенты доверяют серверу только
потому, что его сертификат подписан тем же CA.

## Где лежит

| Что | Где |
|---|---|
| Каталог | `sard.pki.dir`, переменная `SARD_PKI_DIR`; по умолчанию `/var/lib/sard/pki` |
| Docker Compose | том `sard-pki`, смонтирован в `/var/lib/sard/pki` (`deploy/docker-compose.yml`) |
| Ключ CA | `<dir>/ca/ca.key` — PKCS#8 PEM, права `0600` |
| Сертификат CA | `<dir>/ca/ca.crt` — то, что агент получает как CA-бандл |
| Ключ сервера | нигде: живёт в памяти, выпускается при старте и перевыпускается сам за 30 дней до конца срока |

Каталог и `ca/` — `0700`, ключ — `0600`, владелец — пользователь сервера (в образе `sard`, uid 10001).
С более широкими правами сервер не стартует. CA создаётся при первом старте, если
каталог пуст.

Имена в сертификате сервера — `SARD_PKI_SERVER_NAMES` (через запятую, DNS-имена и IP).
Агенты должны обращаться к серверу по одному из них.

## Почему бэкапить отдельно от базы

- **Потеря ключа CA означает повторную регистрацию всех агентов.** Новый CA — это
  новый отпечаток: старые сертификаты агентов перестают проверяться, а агенты
  перестают доверять серверу. Каждый хост придётся зарегистрировать заново с
  новым токеном.
- **Ключ CA — секрет, а база — нет** (ADR 0008: в базе нет ключей бэкапов и
  учётных данных). Бэкап базы можно отдать в более широкий доступ, бэкап ключа CA — нельзя:
  с ним можно выпустить сертификат любого агента.
- **Разные сроки хранения.** Базу откатывают на вчерашний снимок; ключ CA не
  меняется годами (срок CA — 10 лет).

## Как бэкапить

Агент-сосед `sard-self` читает этот каталог (том `sard-pki:ro`) для
самобэкапа (F6) — `docs/operations/self-agent.md`. Ручной способ ниже
остаётся в силе.

```bash
# Docker Compose: остановка сервера не нужна — файлы пишутся один раз при первом старте.
docker run --rm -v sard_sard-pki:/pki -v "$PWD":/backup alpine \
  tar -C /pki -czf /backup/sard-pki.tgz ca
```

Архив хранить там же, где остальные секреты уровня «корень доверия»: сейф,
KMS или офлайн-носитель. Не рядом с бэкапами базы.

## Восстановление

Распаковать `ca/` в пустой `sard.pki.dir`, выставить владельца (uid сервера) и
права `0700` на каталоги и `0600` на файлы, затем запустить сервер. Отпечаток CA
тот же, агенты продолжают работать без повторной регистрации.

```bash
openssl x509 -in ca/ca.crt -pubkey -noout | openssl pkey -pubin -outform DER | sha256sum
```

Эта команда печатает отпечаток — его же содержат токены регистрации.
