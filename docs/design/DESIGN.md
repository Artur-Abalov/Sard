# Sard — дизайн-система веб-интерфейса (v0.1, черновик)

Этот документ — источник правды для внешнего вида веб-UI Sard. Токены лежат в `tokens.css`, логотип — в `logo.svg`. Если что-то здесь противоречит готовой UI-библиотеке, побеждает этот документ.

## Продукт и пользователь

Sard — open-source оркестратор бэкапов. Пользователь — админ или DevOps, который следит за бэкапами разнородной инфраструктуры (PostgreSQL, MySQL, 1С, файлы, MikroTik/Eltex, S3). Второй зритель — руководитель ИТ или аудитор, который смотрит отчёты.

Главный вопрос, на который отвечает каждый экран: **можно ли прямо сейчас восстановиться из бэкапов, и если нет — где порвалась нить?**

## Принципы

1. **Состояние важнее декора.** Интерфейс — это приборная панель. Цвет, размер и порядок служат тому, чтобы проблемный источник было видно за секунду.
2. **Проверенное восстановление — главная метрика.** «Последнее проверенное восстановление N ч назад» показывается крупнее всего: на дашборде глобально, в карточке источника — для источника.
3. **Молчание — это тоже сигнал.** Если отчёт не пришёл вовремя, это отдельный статус «Нет отчёта», а не «ОК». Никогда не показывать успех по умолчанию.
4. **Плотно, но спокойно.** Админ смотрит на десятки источников: компактные таблицы, базовый размер 14px, без пустых больших карточек.
5. **Одна смелая деталь.** Янтарная «нить» (`--sard-accent`) — единственный яркий цвет бренда. Всё остальное — графит и светлый шёлк.

## Цвет

Используйте только роли из `tokens.css` (`--sard-bg`, `--sard-surface`, `--sard-text`, `--sard-accent` и т. д.), а не сырые hex-значения. Тёмная тема по умолчанию, светлая — по системной настройке или `data-theme="light"`.

- `--sard-accent` — основная кнопка на экране (одна), фокус, выбранный пункт навигации, янтарный узел в логотипе. Не использовать для статусов.
- Фон страницы `--sard-bg`, панели `--sard-surface`, утопленные области (логи, код, терминал) `--sard-bg-sunken`.
- Тени только у всплывающих элементов (меню, диалоги, тосты). Панели отделяются рамкой `--sard-border`, не тенью.

## Статусы источников

Статус всегда показывается **иконкой + текстом + цветом**, никогда только цветом.

| Статус | Токен | Иконка | Текст | Когда |
| --- | --- | --- | --- | --- |
| Проверено | `--sard-status-verified` | щит с галочкой | «Проверено 3 ч назад» | Последний бэкап восстановлен в проверке успешно |
| Бэкап есть | `--sard-status-ok` | галочка | «Бэкап 2 ч назад, не проверен» | Бэкап прошёл, проверки восстановления ещё не было |
| Нет отчёта | `--sard-status-stale` | часы | «Нет отчёта 26 ч» | Агент не отчитался к ожидаемому времени |
| Ошибка | `--sard-status-failed` | крестик в круге | «Бэкап упал: нет места на диске» | Бэкап или проверка завершились ошибкой |
| Пауза | `--sard-status-paused` | пауза | «На паузе» | Источник выключен пользователем |

Сортировка по умолчанию — от худшего к лучшему: Ошибка → Нет отчёта → Бэкап есть → Проверено → Пауза.

## Типографика

- **IBM Plex Sans** — весь интерфейс. Заголовки экранов 20–26px / 600, текст 14px / 400, подписи 12–13px.
- **JetBrains Mono** — только то, что пользователь может скопировать или сравнить: имена хостов, источников, команды, пути, хэши, размеры, длительности, время.
- **Unbounded** — только логотип и маркетинговый сайт. В интерфейсе продукта не используется.
- Регистр — как в предложении. Без капса в подписях, кнопках и заголовках таблиц.
- Числа в таблицах — табличные цифры (`font-variant-numeric: tabular-nums`), выравнивание по правому краю.

## Раскладка

```
┌──────────┬──────────────────────────────────────────────┐
│ ◈ sard   │  Дашборд                        [Запустить ▾]│
│          │                                              │
│ Дашборд  │  Последнее проверенное восстановление        │
│ Источники│  3 ч назад          2 ошибки · 1 нет отчёта  │
│ Сценарии │                                              │
│ Проверки │  ┌ Требуют внимания ───────────────────────┐ │
│ Хранилища│  │ ✗ media-s3   Бэкап упал: таймаут сети   │ │
│ Агенты   │  │ ◷ 1c-buh     Нет отчёта 26 ч            │ │
│ Отчёты   │  └─────────────────────────────────────────┘ │
│          │  ┌ Все источники ──────────── таблица ─────┐ │
│ Настройки│  │ ...                                     │ │
└──────────┴──────────────────────────────────────────────┘
```

- Боковая навигация 220px, слева. Контент выровнен по левому краю, максимум 1440px.
- Дашборд: сверху главная метрика и счётчики проблем, ниже блок «Требуют внимания» (только если есть проблемы), затем полная таблица источников.
- Карточка источника: статус и время последней проверки сверху, затем история запусков (таблица), затем сценарий (YAML, моноширинный, только чтение с кнопкой «Изменить»).
- Мобильная версия: навигация сворачивается в нижнюю панель или меню, таблица превращается в список строк со статусом и именем.

## Компоненты

- **Кнопки.** Основная — `--sard-accent` с `--sard-on-accent`, одна на экран. Вторичная — рамка `--sard-border-strong`. Опасная (удаление, перезапись базы) — текст `--sard-status-failed`, всегда с подтверждением. Скругление `--sard-radius-md`.
- **Бейдж статуса.** Иконка 14px + текст 13px, фон — цвет статуса с прозрачностью 12–16%, скругление `--sard-radius-sm`.
- **Таблица.** Строки 40px, разделители `--sard-border`, без зебры. Наведение на строку — лёгкий фон `--sard-bg-sunken`. Первая колонка — статус, вторая — имя источника моноширинным.
- **Логи и YAML.** Блок `--sard-bg-sunken`, JetBrains Mono 13px, горизонтальная прокрутка внутри блока.
- **Фокус.** Видимое кольцо 2px `--sard-focus` с отступом 2px на всех интерактивных элементах.
- **Анимации.** Только в ответ на действие пользователя (раскрытие, подтверждение), 150ms. Никаких анимаций появления секций.

## Тексты в интерфейсе

- Названия по тому, что видит пользователь, а не по устройству системы: «Уведомления», а не «Webhook-конфигурация»; «Проверка восстановления», а не «verify job».
- Кнопка называет действие: «Запустить бэкап», «Проверить восстановление», «Сохранить сценарий». Тост повторяет то же слово: «Бэкап запущен».
- Ошибки говорят, что случилось и что делать, без извинений: «Бэкап упал: на диске агента осталось 0 байт. Освободите место или смените хранилище».
- Пустые состояния зовут к действию: «Источников пока нет. Подключите первый — например, PostgreSQL».
- Время — относительное («3 ч назад»), точное значение во всплывающей подсказке.

## Чего не делать

- Не показывать зелёный статус, если данных о проверке нет.
- Не использовать янтарный акцент для предупреждений и янтарь/оранжевый рядом без иконки.
- Не делать одинаковые карточки с тенью для всего подряд; не ставить градиенты.
- Не использовать капс-надписи над заголовками и стрелки «→» в текстах кнопок.
- Не использовать Unbounded внутри приложения.

## Логотип

`logo.svg` — шестиугольная паутина, линии берут `currentColor`, янтарный узел — «место, где паутина почувствовала движение». Рядом пишется `sard` строчными (Unbounded 700). Минимальный размер знака — 20px. На светлом фоне узел `--sard-amber-700`.
