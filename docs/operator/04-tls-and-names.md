# 4. TLS и имена

У сервера два порта с разными правилами:

| Порт | Что | TLS |
|---|---|---|
| 9090 | агенты, gRPC | взаимный TLS сервера Sard: сертификат сервера и агентов выпускает его собственный CA ([ключ CA](../operations/pki.md)) |
| 8080 | консоль, REST, раздача пакетов агента | нет: обычный HTTP |

## Порт агентов: имена сертификата

Сертификат порта 9090 сервер выпускает сам при каждом старте на имена из
`SARD_PKI_SERVER_NAMES` (DNS-имена и IP через запятую). Агент проверяет, что
адрес, который он набирает (`server.address` в `/etc/sard/agent.yaml`),
есть в сертификате, и что сертификат подписан CA, отпечаток которого пришёл
в токене регистрации.

- `SARD_AGENT_ENDPOINT` — адрес, который консоль подставляет в команду
  регистрации и в конфиг агента. Его хост обязан входить в
  `SARD_PKI_SERVER_NAMES`, иначе сервер не стартует.
- Добавить имя: дописать его в `SARD_PKI_SERVER_NAMES` и
  `docker compose up -d` — сертификат перевыпускается при старте, CA тот же,
  агенты продолжают работать.
- Убрать имя, по которому подключены агенты, — значит отключить их: сначала
  поменяйте `server.address` у агентов и перезапустите их.

Проверка имён в сертификате:

```bash
echo | openssl s_client -connect <sard.example.com>:9090 -alpn h2 2>/dev/null \
  | openssl x509 -noout -ext subjectAltName
```

## Порт агентов: только напрямую или TCP-проброс

Порт 9090 публикуется напрямую (`SARD_GRPC_PUBLISH`). Допустим только
TCP-проброс (DNAT, `socat`, балансировщик в режиме TCP/L4). **Прокси, который
завершает TLS** (nginx `http`, Traefik HTTP-роутер, Cloudflare с проксированием
— «оранжевое облако»), ломает проверку клиентских сертификатов агентов: агенты
не подключатся. В Cloudflare имя для агентов — запись только DNS («серое
облако»).

## Консоль

HTTP-порт по умолчанию слушает только `127.0.0.1:8080`: по нему открытым
текстом идёт пароль администратора и cookie сессии. Варианты на этапе 1:

1. **SSH-туннель (рекомендуется).** Ничего не открыто наружу:

   ```bash
   ssh -N -L 8080:127.0.0.1:8080 <пользователь>@<sard.example.com>
   ```

   и в браузере `http://localhost:8080`.
2. **Доверенная сеть.** `SARD_HTTP_PUBLISH=0.0.0.0:8080` (или адрес
   внутреннего интерфейса) — только если сеть до браузера ваша: пароль идёт
   без шифрования.
3. **HTTPS через обратный прокси — на этапе 1 не работает.** Сервер сверяет
   заголовок `Origin` со схемой и `Host` своего соединения и заголовкам
   прокси (`X-Forwarded-Proto`) не доверяет: за прокси, завершающим TLS, вход
   и любые изменения отвечают 403 `origin_rejected`, а cookie остаётся без
   `Secure` (OQ-031, ADR 0021). То же — Cloudflare в режиме прокси (OQ-142).

Сессии консоли живут в памяти сервера: перезапуск сервера разлогинивает.

## Раздача пакетов агента

Хосты агентов скачивают пакеты с сервера по HTTP-порту
(`/downloads/agent/`, без сессии); команды в консоли строятся от
`SARD_AGENT_DOWNLOADS_URL` (пусто — `http://<хост SARD_AGENT_ENDPOINT>:8080`).
С портом 8080 на `127.0.0.1` команды установки с другого хоста не работают
(OQ-144). Варианты:

- открыть 8080 для хостов агентов: `SARD_HTTP_PUBLISH=0.0.0.0:8080` и
  ограничить доступ облачным фаерволом адресами хостов агентов; пакеты по HTTP
  защищены проверкой `SHA256SUMS` и подписью minisign (шаги в консоли);
- выключить раздачу (`SARD_AGENT_DOWNLOADS=false`) и ставить пакеты из GitHub
  Releases ([установка вручную](../operations/agent-install.md)).
