# 17. Верификатор: проверка восстановления

Верификатор — агент с ролью `verifier` на отдельной машине. Он берёт снимок
источника из того же репозитория, восстанавливает его у себя и сравнивает
копию с отпечатком, который снял источник при бэкапе. Результат — запись
проверки в консоли: «пройдено», «провал», «не можем проверить», «сбой
инфраструктуры» или «отменена». Устройство — в
[docs/design/sard-restore-verification.md](../design/sard-restore-verification.md),
песочница — в [ADR 00XX](../adr/00XX-draft-verifier-sandbox.md).

## Что делает проверка

Стадии идут по порядку, первая непрошедшая останавливает проверку; уборка
идёт всегда.

| Уровень | Стадия | Что проверяет |
|---|---|---|
| 0 | `snapshot` | снимок есть в репозитории |
| 0 | `fingerprint_tag` | отпечаток из задания совпадает с хешем в теге снимка: серверу не верим |
| 0 | `work_volume` | рабочий том смонтирован `noexec`, места хватает |
| 1 | `restic_check` | `restic check --read-data-subset=N%` без блокировки |
| 0 | `sandbox` | для баз: контейнер нужной версии запущен, расширения источника в образе есть |
| 2 | `restore` | снимок восстанавливается (`restic restore --verify` или `pg_restore` в песочнице) |
| 3 | `start` | копия открывается в своём приложении |
| 4 | `fingerprint` | отпечаток копии, снятый кодом плагина, совпадает с отпечатком источника |
| 0 | `cleanup` | копия, контейнер и его тома удалены |

Уровень 5 — все стадии пройдены и время восстановления измерено.

Верификатор ничего не пишет в хранилище: все команды restic идут с
`--no-lock --no-cache`, репозиторий может быть смонтирован только на чтение.

## Машина

- **Не машина источника.** Сервер передаёт идентификаторы машин источника;
  верификатор отказывается проверять снимок своей машины, что бы ни прислал
  сервер.
- **Docker или Podman** для баз (PostgreSQL). Рекомендуем Podman без root:
  пользователь `sard-agent` в группе `docker` равносилен root на этой машине.
  Агент ищет сначала `podman`, затем `docker`; что нашёл, видно в
  `GET /api/v1/verifiers` (поле `sandbox`). Для файлов песочница не нужна.
- **Место:** копия занимает до двух объёмов источника плюс 1 ГиБ запаса
  (`space_factor`, `space_headroom`). Сервер не выдаёт задание верификатору,
  у которого места меньше.

Podman без root для службы — диапазоны подчинённых uid и gid пользователя
`sard-agent` (`/etc/subuid`, `/etc/subgid`):

```bash
sudo usermod --add-subuids 100000-165535 --add-subgids 100000-165535 sard-agent
sudo systemctl restart sard-agent
```

## Установка

1. Поставьте пакет агента, как на источник ([05-agents.md](05-agents.md)).
2. В консоли создайте токен регистрации с ролью **verifier** и зарегистрируйте
   агент той же командой `sudo sard-agent enroll`, что и источник.
3. На **источнике** выпустите верификатору свой ключ репозитория — пароль
   источника на верификатор не переносится:

   ```bash
   sudo sard-agent repo key add <repo> --for verifier --to-file /root/<repo>-verifier.key
   ```

   Перенесите файл на верификатор и удалите его на источнике.
4. На **верификаторе** опишите тот же репозиторий с этим ключом и учётными
   данными хранилища **только на чтение** (S3 — ключ с правом чтения на
   бакет, SFTP — пользователь без права записи):

   ```bash
   sudo sard-agent repo add <repo> <address> --password-from-file /root/<repo>-verifier.key
   ```

   Учётка с правом записи — предупреждение `repository.readonly` при каждом
   старте и в `sard-agent repo check` ([09-troubleshooting.md](09-troubleshooting.md)).

## Рабочий том

Копии лежат в `/var/lib/sard-agent/verify`, по каталогу на задание. Том
должен быть смонтирован `noexec`: восстановленный файл клиента не должен
исполниться. Без флага проверка — «не можем проверить».

Юнит пакета делает это сам: `StateDirectory=sard-agent sard-agent/verify` и
`NoExecPaths=-/var/lib/sard-agent/verify`. Без systemd — отдельный раздел или
tmpfs в `/etc/fstab`:

```text
/dev/<раздел>  /var/lib/sard-agent/verify  ext4  noexec,nosuid,nodev  0  2
```

Каталог — владелец `sard-agent`, права `0700`. Демон Docker или Podman монтирует
каталог задания в песочницу по тому же пути, поэтому агент и рантайм должны
видеть один и тот же путь (агент не в контейнере или том смонтирован по тому
же пути).

## Песочница

Для снимка PostgreSQL агент запускает официальный образ `postgres` той же
мажорной версии, что у источника, по digest из списка релиза:

| Версия | Образ |
|---|---|
| 14.24 | `postgres@sha256:8ab94f61668dc73bbab4dc13273ff2fc37e635536af62aef5306a49a9682a446` |
| 15.19 | `postgres@sha256:baa22e6286bf832cb147b8bb5aa9d8bc999846d69c21d11bf63f58fbeed1fa48` |
| 16.15 | `postgres@sha256:9e2cf6287f25c3151f4c9421ccce2b17f3e60061c111a29165e0d2cdd9ff0a97` |
| 17.11 | `postgres@sha256:b8faeff7712663c2773a190181e1246e37e364b887611c04658c28b44e2408fe` |
| 18.6 | `postgres@sha256:898c60cb390d1085bc97bdd6a1ae968757421df394b071848b52b1c09c89d6a5` |

Контейнер `sard-verify-<задание>` с меткой `sard.verify.job`: без сети
(`--network none`), от uid агента, с лимитами CPU, памяти и процессов, данные —
в каталоге задания. Пароль сервера в песочнице случайный на каждую проверку и
передаётся через окружение, не в командной строке. `psql` и `pg_restore`
выполняются внутри контейнера (`exec`). После проверки контейнер удаляется
вместе с томами; при старте агент удаляет всё с меткой `sard.verify.job` и все
каталоги рабочего тома, оставшиеся от прерванных проверок.

Расширение, которое есть у источника и которого нет в образе, —
«не можем проверить: the image has no extension …». Бэкап при этом не
считается плохим.

### Закрытый контур

Без доступа к Docker Hub загрузите образы заранее по digest:

```bash
docker pull postgres@sha256:<digest>          # на машине с интернетом
docker save postgres@sha256:<digest> -o postgres-<версия>.tar
docker load -i postgres-<версия>.tar           # на верификаторе
```

и запретите загрузку (`verify.pull: false`). Образа нет и загрузка
запрещена — «не можем проверить». Свой реестр или зеркало — список
`verify.images` вместо списка релиза.

## Настройки

Раздел `verify` конфигурации агента; читает его только верификатор.

| Ключ | По умолчанию | Назначение |
|---|---|---|
| `work_dir` | `/var/lib/sard-agent/verify` | рабочий том, `noexec` |
| `check_percent` | `10` | доля данных, которую читает `restic check`, 1..100 |
| `space_factor` | `2` | место под копию: размер источника × это число… |
| `space_headroom` | `1073741824` | …плюс столько байт |
| `stage_limits.prepare` | `10m` | подготовка и уборка |
| `stage_limits.check` | `2h` | `restic check` |
| `stage_limits.restore` | `4h` | песочница, восстановление и открытие копии |
| `stage_limits.fingerprint` | `1h` | отпечаток копии |
| `pull` | `true` | загружать недостающий образ по digest |
| `images` | список релиза | `[{name, version, digest}]`: свой реестр, зеркало |
| `sandbox.cpus` | `"2"` | CPU песочницы |
| `sandbox.memory` | `"4g"` | память песочницы |
| `sandbox.pids` | `1024` | процессы песочницы |

```yaml
verify:
  check_percent: 25
  stage_limits: {restore: 8h}
  pull: false
  images:
    - {name: registry.example.com/postgres, version: "17.11", digest: "sha256:<digest>"}
```

## Исходы

| Статус | Значит | Кому |
|---|---|---|
| пройдено | копия восстановилась, открылась и совпала с источником | — |
| провал | повреждён pack, снимок не восстанавливается, копия не открывается или отличается от источника (в записи — перечень отличий) | владельцу бэкапа |
| не можем проверить | нет отпечатка, нет места, нет `noexec`, нет образа или расширения | администратору верификатора |
| сбой инфраструктуры | стадия вышла за свой срок или верификатор пропал; сервер повторяет до трёх попыток | администратору верификатора |
| отменена | администратор отменил проверку (см. ниже); ни провал, ни «не состоялась»: в счётчики обзора не входит, сообщения не шлёт | — |

## Отмена проверки

Администратор отменяет открытое задание проверки на вкладке «Проверки» источника (кнопка «Отменить проверку») или
запросом `POST /api/v1/verification-jobs/{jobId}/cancel`; отмена запуска-попытки (`POST /api/v1/runs/{runId}/cancel`)
отменяет то же задание. Задание в очереди закрывается сразу. Для идущего задания сервер шлёт верификатору команду
остановиться (`CancelStep`); задание закрывается записью «отменена», когда верификатор подтвердил, а если он не вернулся за
60 с (окно потери) — записью «отменена» без подтверждения. Повторной попытки после отмены нет, и отмена не засчитывается в
три попытки. Если вердикт верификатора пришёл раньше отмены, итогом остаётся он (отмена отвечает `409 run_finished`).
Отменённое задание цикла не создаёт нового до следующего момента цикла; «Проверить сейчас» работает сразу.

После отмены агент удаляет контейнер песочницы и каталог задания под своим сроком уборки (`stage_limits.prepare`), не
связанным ни с отменой, ни со сроком задания: у задания, перешедшего свой срок, уборка всё равно получает полный срок.
Если уборка не уложилась, запись «отменена» остаётся, а контейнер и каталог убирает перезапуск агента. **Агент предыдущей версии (N−1) контейнер после отмены не удаляет:** он остаётся до перезапуска агента,
при старте агент удаляет всё с меткой `sard.verify.job`. Проверить: `podman ps -a --filter label=sard.verify.job`. Обновите
верификатор до версии сервера, чтобы контейнеры убирались сразу.
