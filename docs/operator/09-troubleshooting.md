# 9. Диагностика

## Где смотреть

```bash
cd ~/sard
docker compose ps                                  # состояние и health контейнеров
docker compose logs --tail=200 server              # лог сервера
docker compose logs --tail=50 postgres
curl -fsS http://localhost:8080/actuator/health    # {"groups":[...],"status":"UP"}
curl -fsS http://localhost:8080/api/v1/status      # версия
```

На хосте агента:

```bash
systemctl status sard-agent
journalctl -u sard-agent --since '-1h'
```

Секреты (пароли, токены, ключи) в логи не пишутся ни сервером, ни агентом.

## Сервер не стартует

Причина — первая строка исключения в `docker compose logs server`.

| В логе | Что сделать |
|---|---|
| `CA startup refused: … CA origin is not recorded` (`CA_ORIGIN_NOT_RECORDED`) | в каталоге CA лежит CA, о происхождении которого база ничего не знает: том CA и том базы взяты из разных установок или базу восстановили из старого дампа. Тома базы и каталога CA восстанавливают из бэкапа одного момента или переустанавливают вместе: `docker compose down -v` (данные установки пропадут), затем чистый запуск и мастер |
| `CA startup refused: CA directory is empty … the database says the CA is in use` (`CA_MISSING`) | том CA пуст, а база уже выдала сертификаты агентам или шаг CA мастера выполнен. Верните CA из бэкапа: каталог с `ca/ca.crt` и `ca/ca.key` — в `SARD_PKI_IMPORT_DIR` ([раздел 8](08-migrate-and-remove.md)). Бэкапа нет — тома базы и каталога CA переустанавливают вместе: `docker compose down -v` (данные установки пропадут), агенты регистрируются заново |
| `Database startup refused: DATABASE_NEWER_THAN_SERVER` | база новее сервера: в ней применена миграция, которой у этой версии нет. Типично после восстановления из самобэкапа, когда `.env` из снимка ключей старше снимка базы. Поднимите `SARD_VERSION` в `.env` до версии из сообщения (или до версии из карточки) и запустите снова: при отказе ничего не изменено ([раздел 12](12-server-recovery.md), шаг 4) |
| `SARD_AGENT_ENDPOINT host '…' is not covered by any of …` | добавить хост в `SARD_PKI_SERVER_NAMES` или поправить `SARD_AGENT_ENDPOINT` |
| `SARD_AGENT_ENDPOINT is not a valid host or host:port` | без схемы и пути: `sard.example.com:9090` |
| `… SARD_TELEGRAM_CHAT_ID is not set` (или `BOT_TOKEN`) | задать обе переменные Telegram или очистить обе |
| `SARD_TELEGRAM_BOT_TOKEN is not a bot token (digits:secret)` | токен из @BotFather целиком |
| `SARD_AGENT_DOWNLOADS_URL must be an absolute http or https address …` | `https://имя` без пути-запроса-фрагмента, или пусто |
| `CA import refused: IMPORT_SOURCE_MISSING` | `SARD_PKI_IMPORT_DIR` указывает на несуществующий путь или файл: проверьте монтирование в `docker-compose.override.yml` |
| `CA import refused: IMPORT_FILE_MISSING` | в источнике нет `ca/ca.crt` или `ca/ca.key`; сообщение называет ожидаемый путь (файлы лежат в подкаталоге `ca`) |
| `CA import refused: IMPORT_FILE_UNREADABLE` | сервер (uid 10001) не может прочитать файл или каталог: `chown -R 10001:10001` |
| `CA import refused: IMPORT_PERMISSIONS_TOO_OPEN` | права шире владельца: `chmod 700` на источник и `ca`, `chmod 600` на оба файла |
| `CA import refused: CA_CERT_INVALID` | `ca.crt` — не ровно один сертификат X.509 в PEM (пустой файл, два сертификата, ключ вместо сертификата) |
| `CA import refused: CA_KEY_INVALID` | `ca.key` — не незашифрованный PKCS#8 PEM (`BEGIN PRIVATE KEY`); `openssl pkcs8 -topk8 -nocrypt` |
| `CA import refused: CA_KEY_UNSUPPORTED` | ключ не ECDSA P-256; CA Sard другого типа не бывает, проверьте, тот ли это архив |
| `CA import refused: CA_KEY_MISMATCH` | ключ от другого сертификата: файлы из разных архивов |
| `CA import refused: CA_NOT_SELF_SIGNED` | сертификат подписан другим CA (промежуточный); нужен корневой CA Sard |
| `CA import refused: CA_NOT_A_CA` | у сертификата нет `basicConstraints CA:TRUE` |
| `CA import refused: CA_KEY_USAGE` | `keyUsage` сертификата без `keyCertSign` |
| `CA import refused: CA_NOT_YET_VALID` | сертификат ещё не действует по часам сервера: проверьте время на машине |
| `CA import refused: CA_EXPIRED` | срок CA истёк, импортировать нечего: агентов регистрируют заново с новым CA |
| `CA import refused: IMPORT_WRITE_FAILED` | не удалось записать в `SARD_PKI_DIR` (диск полон, том только для чтения); в каталоге CA ничего не осталось |
| `CA import refused: CA_ALREADY_PRESENT` | в `SARD_PKI_DIR` уже другой CA, чем в источнике (сообщение называет оба отпечатка): уберите `SARD_PKI_IMPORT_DIR` или очистите том, если это ошибочный старт |
| права каталога PKI шире владельца | восстановление ключа CA с неверными правами: повторить команду `chown`/`chmod` из [раздела 6](06-data-and-backup.md#восстановление) |
| ошибка подключения к базе, `password authentication failed` | `SARD_DB_PASSWORD` в `.env` не совпадает с паролем, с которым том базы создан впервые: том помнит первый пароль |
| `set SARD_… in .env` от `docker compose` | обязательная переменная пустая: `SARD_VERSION`, `SARD_DB_PASSWORD` |

## Консоль: первый запуск и вход

| Что видно | Что сделать |
|---|---|
| вход отвечает `setup_required` (409), консоль открывает `/setup` | пароля администратора ещё нет: найдите код настройки (`docker compose logs server \| grep "SARD SETUP CODE"`) и пройдите мастер ([раздел 2](02-install.md), шаг 5) |
| мастер: «кода нет» или «код истёк» | `docker compose restart server` печатает новый код (старый действует до рестарта) |
| ввод кода отвечает `setup_completed` (409) | администратор уже задан: войдите паролем. Пароль потерян — [восстановление доступа](10-security.md#восстановление-доступа) |
| `too_many_attempts` (429) при вводе кода или пароля | пять неудач за 15 минут блокируют адрес на 15 минут; ждите время из сообщения |
| мастер на шаге CA: «заменить CA импортом нельзя» | агенту уже выдан сертификат или шаг CA нажат: CA меняют только переездом ([раздел 8](08-migrate-and-remove.md)) |

## Консоль: самобэкап и копия ключей

| Что видно | Что сделать |
|---|---|
| изменение отвечает `onboarding_incomplete` (409), консоль ведёт на `/setup` | не пройдены шаги самобэкапа и копии ключей: пройдите их ([раздел 2](02-install.md), шаги 5 и 6). На обновлённой установке отказ только у выпуска токенов (`new_agents`) |
| агент при `enroll` пишет «unforeseen reason from the server» с `ONBOARDING_INCOMPLETE` | то же, для новых агентов: токен остался неиспользованным, повторите после завершения мастера |
| подтверждение копии ключей отвечает `first_backup_pending` (409) | оба системных источника должны успешно забэкапиться после последней привязки: запустите самобэкап сейчас и дождитесь успеха |
| мастер или `repository-command` отвечает `self_agent_missing` (422) | нет живого встроенного агента `sard-self`: `SARD_SELF_DIR` пуст или соседа нет в compose; запустите `docker compose up -d self-agent` и повторите. Без соседа онбординг не завершить |
| мастер ждёт репозиторий больше 30 секунд | команда не выполнена или `repo add` завершился ошибкой: `docker compose logs self-agent`; после `repo add` нужен `docker compose restart self-agent` |
| первый бэкап `failed` | сообщение шага в консоли: хранилище недоступно, неверные ключи, нет прав. Исправьте и нажмите «Повторить» |

## Агент не подключается

Агент остановился с `reason CERT_UNKNOWN` (в логе сервера — тенант и пояснение
«в базе записи нет»): сервер с вашим CA не нашёл запись о сертификате агента,
то есть база не восстановлена или старше его регистрации. Восстановите базу и
выполните на хосте `sudo systemctl restart sard-agent`
([раздел 8](08-migrate-and-remove.md)).

Что с хостом агента, показывает одна команда, выполненная на нём:

```bash
sudo sard-agent check
```

Она печатает по строке на проверку (`OK`, `WARN`, `ERROR`, `SKIP`) и под
каждой строкой не `OK` — подсказку `hint:` с готовой командой или ссылкой на
раздел ниже. Команда ничего не меняет на хосте. Коды выхода: `0` — всё в
порядке, `8` — есть предупреждения, `1` — есть ошибки, `2` — команда не
выполнена. Ручные проверки порта, имени, времени, сертификата и ключей не
нужны: каждую делает своя строка (`server.reachable`, `server.tls`,
`clock.skew`, `tls.*`, `repository.*`). Проверка одного репозитория:
`sudo sard-agent repo check <имя>`; со считыванием части данных —
`--read-data 5`.

Коды выхода `sard-agent enroll` и что с каждым делать —
[регистрация агента](../operations/agent-enroll.md). Отозванный в консоли агент
получает отказ при подключении (`check` покажет `CERT_REVOKED` в
`server.accepted`); он регистрируется заново новым токеном
(`sudo sard-agent enroll --force`).

## Консоль

| Симптом | Причина |
|---|---|
| после перезапуска сервера снова страница входа | сессии в памяти сервера, перезапуск их сбрасывает — так задумано |
| вход отвечает 403 `origin_rejected` | консоль открыта через прокси с TLS или с переписанным `Host` — не поддерживается на этапе 1; SSH-туннель ([раздел 4](04-tls-and-names.md)) |
| вход заблокирован после нескольких неверных паролей | блокировка перебора; ждать или перезапустить сервер |
| команды установки агента не работают с другого хоста | порт 8080 на `127.0.0.1` (OQ-144), [раздел 4](04-tls-and-names.md), «Раздача пакетов агента» |

## Запуск бэкапа

- **Шаг FAILED, сообщение кончается «run `sudo sard-agent check` on the host».**
  Причина в хосте агента: хранилище недоступно, ключ или доступ отвергнуты,
  неверный пароль репозитория, нет файла пароля или нет `pg_dump`. Выполните
  эту команду на хосте: строка с ошибкой и её подсказка называют причину
  ([разделы проверок](#проверка-хоста-агента-sard-agent-check)). Прочие отказы
  шага (например, нет каталога источника) этой строки не получают.
- **Шаг FAILED, «permission denied».** Агент работает от `sard-agent` и видит
  только то, что этому пользователю можно читать ([плагин files](../plugins/files.md)).
- **Шаг «потерян».** Связь с агентом пропала во время шага: агент перезапущен,
  хост выключен, сеть.
- **Агент завис при старте с локальным репозиторием.** Каталог репозитория не
  добавлен в `ReadWritePaths` службы ([репозиторий агента](../operations/repo-init.md)).
- **Нет уведомления в Telegram.** В логе сервера при старте —
  `Notifications are off`, если переменные не заданы; бот должен быть
  добавлен в чат и иметь право писать.

## Проверка хоста агента: sard-agent check

Раздел на каждую проверку `sudo sard-agent check` (идентификатор без точек —
якорь, на который ведёт `hint:`): что значит строка и как чинить.
Проверки одного репозитория (`repository.*`) выполняет и
`sudo sard-agent repo check <имя>`. Идентификаторы не меняют смысла между
версиями.

### `service.user`

Пользователь службы (по умолчанию `sard-agent`, параметр `service.user`)
не существует на хосте. Создайте его или укажите существующего в
`/etc/sard/agent.yaml`; пакет агента создаёт пользователя при установке. Пока
проверка не пройдена, строки `repository.*` и `secret.readable` пропускаются.

### `config.load`

Основной файл `/etc/sard/agent.yaml` или фрагмент в `/etc/sard/agent.d` не
читается или не разбирается. Сообщение называет файл и причину: синтаксис YAML,
неизвестное поле, каталог или файл, который не может прочитать пользователь
службы (проверка судит по правам так, как их увидит служба). Исправьте файл;
проверки, которым нужен конфиг, пропускаются, пока он не читается.

### `config.names`

Одно имя репозитория или секрета объявлено в двух местах (`DUPLICATE_NAME`);
сообщение называет оба файла. Оставьте одно определение: `sudo sard-agent repo
remove <имя>` убирает фрагмент, созданный `repo add`.

### `config.references`

Файл, на который ссылается конфиг (`tls.*`, `password_file`, `env_file`,
`secrets.*`, `scripts.*`, `restic.path`), не существует. Сообщение называет
путь, подсказка — как его создать: `sudo sard-agent secret set <имя>` для
секрета, `sudo sard-agent enroll` для сертификатов.

### `files.permissions`

Права или владелец файла нарушают правила. Ошибка: секретный файл (ключ TLS,
пароль, `env_file`, секрет) не принадлежит пользователю службы или доступен
группе и прочим; каталоги `secrets` и `tls` — то же. Служба откажет в запуске.
Предупреждение: основной конфиг, `agent.d` или фрагмент доступен на запись не
только root. Подсказка содержит готовые `chown` и `chmod` для каждого файла.

### `restic.binary`

Ошибки `RESTIC_NOT_FOUND` (нет файла по `restic.path` или поставляемого
`/usr/libexec/sard/restic`), `RESTIC_UNUSABLE` (не запускается),
`RESTIC_TOO_OLD` (версия ниже минимальной). Предупреждение: версия не ниже
минимальной, но не равна поставляемой с агентом. Переустановите пакет агента
или уберите `restic.path` из конфига.

### `tls.identity`

Нет сертификата или ключа агента либо ключ не соответствует сертификату.
Зарегистрируйте агента заново: `sudo sard-agent enroll --server <адрес> --token
<токен>` ([регистрация агента](../operations/agent-enroll.md)). Пока проверка не
пройдена, `server.*` пропускаются.

### `tls.chain`

Сертификат агента выдан не тем CA, что лежит в `tls.ca_file` (бандл, записанный
при регистрации). Файл CA заменили или он от другой установки сервера:
`sudo sard-agent enroll --force` с новым токеном.

### `tls.expiry`

Строка судит по доле срока самого сертификата. Сертификат истёк или ещё не
действует — ошибка. Остаётся не больше 30/365 срока (для года — 30 суток), а
продление не прошло — предупреждение «has not been renewed»: агент обычно
продлевает сертификат сам с двух третей срока, поэтому предупреждение значит,
что продление не удаётся. Причину назовёт `sudo sard-agent status`, строка
`renewal_last_error`. Если сертификат истёк, зарегистрируйте агента заново
новым токеном (`sudo sard-agent enroll --force`; у агента будет новый id). Если
сертификат ещё не действует, проверьте время на хосте (`clock.skew`). Строка
описывает ту пару файлов, которую выберет служба при старте, в том числе
`agent.key.new` и `agent.pem.new`. Подробно — в
[разделе 13](13-agent-certificates.md).

### `tls.role`

Всегда пропущена («agent role is checked once V1 is available»): проверка роли
агента появится позже. Действий не требует.

### `server.reachable`

Имя из `server.address` не разрешается или порт сервера (по умолчанию 9090)
закрыт. Проверьте адрес в `/etc/sard/agent.yaml` (он должен быть одним из
`SARD_PKI_SERVER_NAMES`, [раздел 4](04-tls-and-names.md)), DNS, облачный фаервол
и фаервол хоста сервера ([раздел 1](01-requirements.md)). Время ожидания —
`--connect-timeout` (10 секунд).

### `server.tls`

Рукопожатие mTLS не состоялось. Сообщение различает случаи: сертификат сервера
не от CA агента, имя в нём не совпадает с `server.address`
([раздел 4](04-tls-and-names.md)), сервер не принял сертификат агента (отзыв,
`sudo sard-agent enroll --force`), сервер не ответил за время ожидания.
Между агентом и портом сервера не должно быть ничего, что завершает TLS.

### `server.accepted`

Сервер не принял агента. Ошибка с причиной из ответа сервера: `CERT_REVOKED`,
`AGENT_REVOKED`, `CERT_UNKNOWN` (в базе записи о сертификате нет), `CERT_EXPIRED`,
`CERT_IDENTITY_MISMATCH`, `CERT_MISSING`: зарегистрируйте агента заново
(`sudo sard-agent enroll --force`); для `CERT_UNKNOWN` сначала проверьте, что
база сервера восстановлена не из слишком старой копии
([раздел 8](08-migrate-and-remove.md)). «The server could not tell…» — сервер
временно не может ответить (например, недоступна его база), повторите позже.
Предупреждение «the server is older than this agent» — сервер не знает проверки;
обновите сервер.

### `clock.skew`

Часы хоста расходятся с часами сервера больше чем на минуту. Включите
синхронизацию: `sudo timedatectl set-ntp true`; проверьте `timedatectl`
(«System clock synchronized: yes»). Большой сдвиг ломает проверку
сертификатов.

### `repository.storage`

Хранилище репозитория недоступно (`BACKEND_UNAVAILABLE`): имя не
разрешается, порт закрыт, нет маршрута, TLS хранилища не проходит (сертификат
не доверенный, `x509`) или не ответило за `--connect-timeout`. Проверьте адрес
(`sudo sard-agent repo show <имя>`), сеть и фаервол, сертификат хранилища.
Последующие шаги репозитория пропускаются.

### `repository.credentials`

Хранилище ответило, но не приняло агента: `S3_KEY_REJECTED` (неверный ключ S3),
`STORAGE_ACCESS_DENIED` (нет прав на чтение, запись и удаление),
`BUCKET_NOT_FOUND`, `SSH_KEY_NOT_AUTHORIZED` (добавьте открытый ключ
пользователя службы в `authorized_keys` на сервере SFTP), `HOST_KEY_MISMATCH`
(ключ сервера SFTP изменился: сверьте отпечаток и обновите `known_hosts`),
`ENV_FILE_MISSING` и `SECRET_FILE_REJECTED` (файл `env_file` отсутствует или
права шире `0600`: `sudo chmod 0600 <файл>`). Значения ключей в вывод не
попадают. Ключи S3 меняет `sudo sard-agent secret set <имя>`.

### `repository.initialized`

В хранилище нет репозитория (`REPOSITORY_NOT_INITIALIZED`): адрес указывает не
туда или репозиторий не создан. Выполните `sudo sard-agent repo add <имя>
<адрес>` для создания либо исправьте адрес.

### `repository.password`

Файл пароля отсутствует (`PASSWORD_FILE_MISSING`), его права шире `0600`
(`SECRET_FILE_REJECTED`) или пароль не открывает репозиторий
(`WRONG_PASSWORD`). Пароль хранится на хосте и серверу не передаётся; если файл
потерян, а копии ключа нет, данные репозитория не восстановить. Верните файл из
копии ключей ([раздел 6](06-data-and-backup.md)) либо задайте верный пароль
повторным `sudo sard-agent repo add <имя> <адрес>`.

### `repository.id`

Идентификатор репозитория в хранилище не совпадает с тем, что агент объявил
серверу при регистрации: по этому адресу теперь другой репозиторий. Проверьте
адрес и перезапустите службу: `sudo systemctl restart sard-agent`. Предупреждение:
служба не смогла прочитать идентификатор при старте или не объявила это имя
(репозиторий добавлен после старта) — тот же перезапуск. «Пропущено», если
служба ещё не регистрировалась: `sudo systemctl start sard-agent`.

### `repository.keys`

Ключи restic репозитория (V3). Предупреждение «no recovery key» — нет ключа,
выпущенного для восстановления: потеря этого хоста вместе с файлом пароля
означает потерю бэкапов. «no recovery key; only one key» — ключ вдобавок
единственный. Выпустите ключ восстановления и храните его вне инфраструктуры:
`sudo sard-agent repo key add <имя> --for recovery`; список ключей —
`sudo sard-agent repo key list <имя>`. Шаг не делается с `--offline` и
пропускается, если не прошёл `repository.id`.

### `repository.locks`

Блокировки restic в репозитории. Пока бэкап или проверка идёт, блокировки
нормальны (строка `OK` называет их число, хосты и возраст). Предупреждение —
блокировка старше 24 часов. Своя, процесс жив: проверьте процесс (`ps`). Своя,
процесса нет: `sudo sard-agent repo unlock <имя> --remove-stale` (снимает только
зависшие блокировки этого хоста; отказывает, если `restic unlock` задел бы
чужую). Чужая: снимите на том хосте той же командой, этот агент её не снимает.

### `repository.integrity`

Только с `--read-data`: `restic check` читает долю данных (`--read-data 5` —
5 процентов). Ошибка — найдено повреждение (число ошибок в сообщении);
сделайте новый бэкап в другое хранилище и разберитесь с источником
повреждения. Ошибка «needs to create a lock» — учётная запись только для
чтения на источнике: на нём проверка с такой учёткой не поддерживается. На
верификаторе `restic check` идёт без блокировки (`--no-lock`), как и его
проверки восстановления, и учётки только на чтение хватает. Предупреждение
«locked by another process» — идёт бэкап или восстановление: повторите
команду, когда он закончится.

### `repository.readonly`

Только на верификаторе. Учётные данные хранилища должны только читать:
верификатор ничего не пишет в репозиторий. Проверка просит у хранилища
блокировку restic; её получает лишь учётка с правом записи, и restic сразу её
снимает. `OK` — хранилище отказало в блокировке. Предупреждение — учётка может
писать: утечка таких данных с верификатора позволила бы испортить бэкапы.
Выдайте верификатору учётку только на чтение (S3 — ключ с правом чтения на
бакет, SFTP — пользователь без права записи, локальный каталог — монтирование
только на чтение) и подключите её заново: `sudo sard-agent repo add`. Та же
строка WARN пишется в журнал агента при каждом старте верификатора.

### `secret.readable`

Секрет из `secrets.*` отсутствует, пуст, не обычный файл или не читается
пользователем службы. Сообщение называет путь и причину, но не значение.
`sudo sard-agent secret set <имя>` создаёт секрет заново.

### `plugin.declared`

Информационная строка: плагины и версии, которые агент объявит серверу.
Действий не требует.

### `plugin.programs`

Программы плагина на хосте. Для `postgresql`: `pg_dump` ищется в `PATH` агента,
`psql` и `pg_dumpall` — рядом с ним, `pg_restore` — для ручного восстановления.
Нет `pg_dump` — строка пропущена («PostgreSQL client tools are not installed»):
если на хосте нет источников PostgreSQL, это нормально, иначе установите
клиент (`postgresql-client` на Debian и Ubuntu, `postgresql` на RHEL) или
задайте `pg_dump_path` в источнике ([плагин postgresql](../plugins/postgresql.md)).
Нет `psql` или `pg_dumpall` рядом с `pg_dump` — ошибка (клиент установлен не
полностью), нет `pg_restore` или разные старшие версии — предупреждение.

### `restore.locations`

Всегда пропущена: проверка мест восстановления появится позже. Действий не
требует.

### `selinux.labels`

Только при SELinux в режиме enforcing: метка файла агента не совпадает с меткой
по политике. Выполните то, что назвала подсказка: `sudo restorecon -Rv <путь>`.

### `selinux.denials`

Только при SELinux в режиме enforcing: за последние 24 часа политика отказала
`sard-agent` или `restic`. Список: `sudo ausearch -m avc -ts yesterday`. Нужен
пакет `audit`; под пользователем службы строка пропущена («needs root»).

### `service.running`

Служба `sard-agent` не запущена (ошибка): `sudo systemctl start sard-agent`,
причина — в `journalctl -u sard-agent`. Предупреждение — служба перезапускалась
после сбоев (`NRestarts` больше нуля): смотрите журнал. Без systemd строка
пропущена.

### `service.steps`

Число шагов в работе по журналу агента (`state_dir/journal`). Предупреждение —
журнал не читается: права каталога `state_dir` и диск.
