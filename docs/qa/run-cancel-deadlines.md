# QA: отмена запуска, сроки шагов, ожидание агента, перезапуск сервера (J1)

Спецификации: `docs/specs/server/run-cancel-deadlines.feature`,
`docs/specs/web/run-cancel-deadlines.feature`. Статус — утверждено
2026-10-27 (решения владельца переданы координатором). Части помечены фазой;
проходится часть фазы, которая сдаётся. Часть 6 (J1f, отмена проверки
восстановления) ждёт V6.

## Стенд

- `make up` — PostgreSQL и sard-server; консоль на `http://localhost:8080`.
- Агент `qa1` зарегистрирован, онлайн; репозиторий `qa` (локальный) и
  репозиторий `sftp` на контейнере SFTP (`docs/operator/05a-storage.md`).
- Источник `big` (files) агента `qa1` — каталог не меньше 5 ГиБ случайных
  данных, чтобы бэкап шёл несколько минут. Источник `big-sftp` — тот же
  каталог в репозиторий `sftp`.
- Вход: `curl -c jar -H 'Content-Type: application/json' -d
  '{"username":"admin","password":"<пароль>"}' http://localhost:8080/api/v1/session`;
  далее каждый запрос — `curl -b jar …`. Изменяющие запросы — без `Origin`.
- `RUN=<id>` — id запуска из ответа `POST /api/v1/sources/{id}/runs`.

## Часть 1. Перезапуск сервера (J1d)

1. Запустить бэкап `big`; дождаться `outcome = running` в
   `GET /api/v1/runs/$RUN`.
   Ожидается: `status running`, `outcome running`.
2. `docker compose -f deploy/docker-compose.yml restart sard-server`.
   Ожидается: сервер поднялся, в журнале агента — переподключение.
3. Ждать до конца бэкапа, читать `GET /api/v1/runs/$RUN`.
   Ожидается: `status succeeded`; шаг ни разу не был `lost` (в журнале
   сервера нет строки потери шага этого запуска).
4. Повторить шаги 1–3, но держать сервер остановленным 5 минут
   (`stop`, пауза, `start`), пока бэкап на агенте идёт или закончится.
   Ожидается: `status succeeded` после возвращения агента.
5. Запустить бэкап `big`, остановить агента (`systemctl stop sard-agent`) и
   сервер; запустить сервер, агента не запускать 3 минуты.
   Ожидается: через 2 мин после старта сервера (плюс интервал тика) шаг
   `lost`, `outcome lost`.
6. Задать `SARD_RUN_START_GRACE=0s`, запустить сервер.
   Ожидается: сервер не стартует, сообщение называет
   `sard.run.dispatch.start-grace`. Вернуть значение.

## Часть 2. Отмена (J1a)

7. Остановить агента `qa1`. Запустить бэкап `big`.
   Ожидается: `status queued`.
8. `curl -b jar -X POST http://localhost:8080/api/v1/runs/$RUN/cancel`.
   Ожидается: `200`, `status cancelled`, `outcome cancelled`,
   `cancellation.requestedBy "admin"`, `cancellation.result "cancelled"`.
9. Запустить агента; посмотреть журнал агента (`journalctl -u sard-agent`).
   Ожидается: шаг этого запуска агенту не приходил (нет строки
   `step accepted` с его `command_id`).
10. Запустить бэкап `big`, дождаться `running`, выполнить отмену (шаг 8).
    Ожидается: `200`, `status running`, `outcome cancelling`,
    `cancellation.result "pending"`.
11. Сразу запустить источник ещё раз (`POST /api/v1/sources/{id}/runs`).
    Ожидается: `409 run_active` с `activeRunId` отменяемого запуска.
12. Ждать до 1 минуты, читать запуск.
    Ожидается: `status cancelled`, `outcome cancelled`, шаг `cancelled`; в
    журнале агента — `cancelled by the server`.
13. Повторить отмену того же запуска.
    Ожидается: `409 run_finished`, запуск не изменился.
14. Запустить бэкап, дождаться `running`, отменить дважды подряд.
    Ожидается: оба ответа `200`, `cancellation.requestedAt` одинаков.
15. Запустить бэкап, дождаться `running`, остановить агента, отменить.
    Ожидается: `outcome cancelling`. Через 60 с плюс интервал тика —
    `status cancelled`, `outcome cancel_unconfirmed`, шаг не `lost`.
16. Запустить агента.
    Ожидается: на странице запуска виден поздний итог агента
    (`lateStatus`), `outcome` по-прежнему `cancel_unconfirmed`.
17. Запустить восстановление снимка `big` в новый каталог, дождаться
    `running`, отменить.
    Ожидается: `status cancelled`, `restoreOutcome nothing`; каталога
    восстановления на хосте агента нет.
18. До J1f: отменить запуск проверки восстановления (если есть активный).
    Ожидается: `409 run_not_cancellable`.
19. Отменить с заголовком `Origin: https://evil.example`.
    Ожидается: `403 origin_rejected`.
20. Бот Telegram настроен; повторить шаг 10–12.
    Ожидается: сообщения об отменённом запуске в чате нет.

## Часть 3. Сроки шагов (J1b)

21. `GET /api/v1/run-defaults`.
    Ожидается: `backupTimeoutMinutes 360`, `restoreTimeoutMinutes 720`.
22. `PUT /api/v1/sources/{id}` источника `big-sftp` с
    `backupTimeoutMinutes 2`.
    Ожидается: `200`, поле сохранено.
23. То же с `backupTimeoutMinutes 0`, затем `1441`.
    Ожидается: оба раза `422 validation_failed`, ошибка у
    `backupTimeoutMinutes`.
24. Запустить бэкап `big-sftp`; посмотреть журнал агента.
    Ожидается: в строке принятия шага срок 2m0s (или сообщение агента при
    превышении называет 2m0s).
25. Через 20 с после начала бэкапа отключить контейнер SFTP от сети
    (`docker network disconnect …`).
    Ожидается: не позже 2 мин + 60 с + тик — `status failed`,
    `outcome timed_out`, `timeoutSeconds 120`; в Telegram — «Бэкап прерван
    по таймауту», строка «Срок выполнения: 2 мин» и обе подсказки.
26. Вернуть SFTP в сеть, сбросить срок источника в `null`, запустить бэкап.
    Ожидается: в журнале агента срок 6h0m0s.
27. `PUT /api/v1/run-defaults` с `backupTimeoutMinutes null`.
    Ожидается: `422`, ошибка у `backupTimeoutMinutes`.

## Часть 4. Ожидание офлайн-агента (J1c)

28. Запустить сервер с `SARD_RUN_AGENT_WAIT_MAX=2m`. Остановить агента
    `qa1`. Запустить бэкап `big`.
    Ожидается: `outcome waiting_for_agent`, `agentWaitUntil` — время запуска
    + 2 мин.
29. Ждать 2 мин + тик.
    Ожидается: `status agent_unavailable`, `outcome agent_unavailable`,
    `agentUnavailableSince` — время остановки агента; в Telegram одно
    сообщение «Бэкап не выполнен — агент был недоступен» со временем
    последней связи.
30. Сразу запустить источник вручную.
    Ожидается: `201` (источник свободен).
31. Задать источнику расписание каждые 5 минут (`PUT …/schedule`), агента
    не запускать, ждать 3 срабатывания.
    Ожидается: в `GET …/schedule/fires` три `run_created`, ни одного
    `skipped_active`; запуски по очереди становятся `agent_unavailable`.
32. Запустить агента.
    Ожидается: очередной запуск по расписанию уходит агенту и даёт
    `succeeded`.
33. Остановить агента, запустить восстановление снимка.
    Ожидается: `agentWaitUntil` = время запуска + `SARD_RUN_AGENT_WAIT_MAX`;
    по истечении — `agent_unavailable`.
34. Запустить сервер с `SARD_RUN_AGENT_WAIT_MAX=0s`.
    Ожидается: сервер не стартует, сообщение называет
    `sard.run.agent-wait.max`.

## Часть 5. Консоль (J1e)

Каждый шаг — на русском и на английском (переключатель языка), против
сервера и с моками (`cd web && npm run dev` с MSW).

35. Открыть страницу идущего бэкапа.
    Ожидается: кнопка «Отменить»; нажатие открывает один диалог; закрытие
    диалога ничего не отправляет (вкладка Network).
36. Подтвердить отмену.
    Ожидается: один `POST …/cancel`; запуск «отменяется», кнопки нет; затем
    «отменён», с текстом «отменил admin» и временем.
37. Открыть историю источника с идущим запуском.
    Ожидается: кнопка «Отменить» у активного запуска, у завершённых нет.
38. Отменить идущее восстановление.
    Ожидается: диалог предупреждает, что частично восстановленное будет
    удалено.
39. Открыть запуски из частей 3 и 4.
    Ожидается: «Провал: превышен срок (2 мин)» с двумя подсказками и
    ссылкой на форму источника; «Не выполнен: агент был недоступен» со
    временем последней связи; ждущий запуск — «Начнётся при подключении
    агента, ждём до <время>». В списках (история, обзор) то же слово со
    временем и «Провал: превышен срок (N ч)» — `RunSummary` несёт
    `agentWaitUntil` и `timeoutSeconds`.
40. Обзор и история источника.
    Ожидается: отменённый и «агент был недоступен» не окрашены цветом
    ошибки.
41. Форма источника: поля сроков пусты, подсказка «6 ч» и «12 ч»; ввести
    `0` и сохранить.
    Ожидается: ошибка у поля, форма открыта.
42. «Настройки»: изменить срок бэкапа по умолчанию на 8 (поля в целых
    часах, 1–24; REST остаётся в минутах), сохранить, обновить страницу.
    Ожидается: показано 8; подсказка формы источника — «8 ч». Если по REST
    задано не целое число часов (90), поле пусто, подсказка — «Сохранено:
    1 ч 30 мин», значение не меняется, пока не введены целые часы.

## Часть 6. Отмена проверки восстановления (J1f, ждёт V6)

Набросок: шаги уточняются по спецификации V6 до начала J1f.

43. Дождаться идущего запуска проверки восстановления, отменить его по REST.
    Ожидается: `200`, `outcome cancelling`; затем `status cancelled`; новой
    попытки этого задания проверки нет.
44. Открыть страницу идущей проверки в консоли.
    Ожидается: кнопка «Отменить» есть; после подтверждения — один
    `POST …/cancel`.
45. Бот Telegram настроен; повторить шаг 43.
    Ожидается: сообщения об отменённой проверке нет.
