# QA: проверка восстановления в консоли и уведомлениях (V6)

Спецификация: `docs/specs/server/verification-console.feature`,
`docs/specs/server/verification-notifications.feature`,
`docs/specs/web/verification-console.feature`.

Статус: черновик, вместе со спецификацией ждёт утверждения владельцем
(предложения ОВ1–ОВ11). Шаги с пометкой `(ОВN)` проверяют предложение и
меняются вместе с решением владельца.

Здесь вручную проходятся сценарии с тегами `@qa` и `@qa-only` и сквозной путь
«цикл проверок → верификатор → сервер → консоль и Telegram». Точные тексты,
границы, гонки двух серверов и сбои базы проверяются тестами `@unit`,
`@server`, `@vitest`, `@mocks` с теми же названиями.

Ожидаемый результат указан после «→» в каждом шаге. Любое расхождение — дефект.

## Стенд

- Сервер Sard (`make up`), консоль `cd web && npm run dev`
  (<http://localhost:5173>).
- ВМ-источник SRC (`src1`): агент роли source, PostgreSQL 17 с базой `qa`
  (таблица `public.orders`, 1000 строк), каталог `/srv/www` с файлами.
- ВМ-верификатор VRF (`vrf1`): агент роли verifier, Podman, том работы с
  `noexec` — как в «Стенде» `docs/qa/restic-keys.md`.
- Хранилище S3 с учётками `RW` и `RO`, как в `docs/qa/restic-keys.md`.
- Telegram: бот и чат, как в шаге 2 «Подготовки» `docs/qa/run-notifications.md`
  (`SARD_NOTIFY_LANGUAGE=ru`, `SARD_CONSOLE_PUBLIC_URL=http://localhost:5173/`).
- Переменные: `API=http://localhost:8080/api/v1`, сессия администратора в
  `$QA/jf` (`curl -b $QA/jf`), `PSQL` — psql в базу сервера, как в
  `docs/qa/files-plugin.md`.

Во всех шагах «секретов нет» значит: в ответе, в странице (сохранить как HTML)
и в сообщении Telegram нет пароля репозитория, ключей `RW` и `RO`, значений
секретов агента (проверка — поиск строки).

## Часть 0. Моки (VITE_API_MOCKS=1)

1. `cd web && VITE_API_MOCKS=1 npm run dev`, открыть обзор.
   → блок «Проверка восстановления» со счётчиками «проверено за сутки»,
   «провалы», «не состоялась», «давно не проверялись», «ещё не проверялись» и
   отдельной группой «не проверяются»; счётчик провалов — цвет и значок
   ошибки, «не состоялась» — предупреждения, они различаются.
2. Открыть запись проверки моков со статусом failed и расхождениями.
   → итог «провал»; расхождения словами, например «таблица public.orders: в
   источнике 1 204 311 строк, в копии 1 204 310» и «контрольный путь
   /srv/data пуст»; таблица отпечатка с колонками поле, exact/info, источник,
   копия; у совпавших — «совпало», у info — «не сравнивается» (ОВ7).
3. Открыть записи моков cannot_verify, infrastructure_failure, no_verifier.
   → каждая — роль предупреждения, ни одна не красная; у cannot_verify —
   подсказка по стадии и вывод стадии (ОВ5); у infrastructure_failure —
   ссылка на верификатор; у no_verifier — причины по каждому верификатору
   словами.
4. Переключить язык на EN и повторить шаги 1–2.
   → все подписи на английском, числа «1,204,311»; ключей i18n на экране нет.

## Часть 1. Нет верификатора

5. Отозвать VRF в консоли (карточка агента → «Отозвать»). Создать источник
   `qa-pg` (postgresql, база `qa`, репозиторий `pg`, без `key_tables`) и
   `qa-www` (files, `/srv/www`, репозиторий `www`, без `control_paths`);
   включить у обоих проверку; выполнить по бэкапу.
6. Открыть обзор.
   → вверху постоянная подсказка «Проверка восстановления не работает: нет
   верификатора», без кнопки закрытия (ОВ4).
7. Раскрыть инструкцию.
   → шаги: выпустить токен с ролью «верификатор»; поставить агента; на `src1`
   — `sudo sard-agent repo key add pg --for verifier` и
   `sudo sard-agent repo key add www --for verifier`; на верификаторе —
   шаблон `sudo sard-agent repo add …` с `<address>` и `<file>` и пометкой
   об учётке только на чтение. Полей ввода нет. Секретов нет.
8. `curl -fsS -b $QA/jf $API/verification-setup | jq -r 'del(.verifierRepoAdd)' | grep -ciE 'password|secret'`
   → `0`, без сообщения об ошибке от curl — иначе проверка не состоялась (слово «password» допустимо только как имя флага `--password-from-file`
   в шаблоне `verifierRepoAdd`; значений паролей и секретов в ответе нет).
9. Подождать такт цикла проверок (`sard.verification.interval`).
   → в чат пришло **одно** сообщение «⚠️ Проверка восстановления не работает:
   нет верификатора» со строкой «Источников с включённой проверкой: 2» и
   ссылкой `http://localhost:5173/`.
10. Подождать ещё два такта.
    → новых сообщений «нет верификатора» нет (ОВ11в).

## Часть 2. Первая успешная проверка

11. Зарегистрировать VRF заново токеном роли verifier (кнопка «Выпустить
    токен» в инструкции открывает выпуск с выбранной ролью «верификатор»);
    выполнить на `src1` и VRF команды из инструкции с учёткой `RO`.
    → подсказка «нет верификатора» исчезла с обзора; сообщения о выходе из
    состояния в чате нет.
12. Открыть страницу верификаторов.
    → VRF «в сети», id двух репозиториев, свободное место в ГиБ, «podman
    <версия>», «выполнено 0», «по своей вине 0».
13. В карточке `qa-pg`, вкладка «Проверки»: подсказка «Задайте ключевые
    таблицы, сейчас проверяются 10 самых больших» со ссылкой на
    редактирование; у `qa-www` — подсказка про контрольные пути и
    отмонтированный диск. Список верификаторов источника — VRF подходит.
14. Нажать «Проверить сейчас» у `qa-pg`, выбрать «последний снимок».
    → задание в очереди со сроком; вкладка обновляется сама, без
    перезагрузки; через несколько минут — запись «пройдено» уровня 5.
    Сообщений в чате нет (успех молчит).
15. Нажать «Проверить сейчас» ещё раз, пока задание идёт.
    → сообщение «Проверка этого источника уже в очереди или идёт».
16. Открыть запись.
    → стадии по порядку со статусом и длительностью; у `restore` и `start` —
    digest образа; вывод моноширинным; снимок, верификатор, время
    восстановления; таблица отпечатка exact/info. Секретов нет.
17. Обзор и список источников.
    → у `qa-pg` «проверено N минут назад — время восстановления измерено»; у
    `qa-www` — «ещё не проверялось»; «проверено за сутки 1».

## Часть 3. Провал и снова прошла

18. На хранилище перенести один файл из `data/` репозитория `pg` в
    сторону (учёткой `RW`, сохранить копию локально). Нажать «Проверить
    сейчас» у `qa-pg`.
    → запись «провал» с ролью ошибки, стадия «целостность хранилища»; на
    обзоре «провалы 1».
19. В чате.
    → одно сообщение: «❌ Проверка восстановления провалилась: qa-pg»,
    «Стадия: целостность хранилища», «Снимок: <8 знаков>», «Верификатор:
    vrf1», «Причина: …», «Проверка: `<id>`», ссылка
    `http://localhost:5173/verifications/<id>` открывает эту запись.
20. Ещё раз «Проверить сейчас».
    → вторая запись «провал»; нового сообщения нет (ОВ11а).
21. Вернуть файл шага 18 на место; «Проверить сейчас».
    → запись «пройдено»; в чате одно сообщение «✅ Проверка восстановления
    снова прошла: qa-pg» с уровнем и временем восстановления.

## Часть 4. Не состоялась и давно не проверялся

22. На VRF `sudo systemctl stop podman.socket; sudo mv /usr/bin/podman
    /usr/bin/podman.qa`; «Проверить сейчас» у `qa-pg`.
    → запись «не можем проверить», роль предупреждения, стадия `sandbox` с
    подсказкой и выводом (ОВ5); сообщения в чате нет. Вернуть podman.
23. Настройки → «Проверка восстановления».
    → расписание, пояс, следующий цикл, «не проверялся дольше 2 дней» (ОВ1).
    Ввести 0 и сохранить → ошибка у поля порога. Ввести 1 и сохранить →
    сохранено; после перезагрузки страницы — 1.
24. `$PSQL "update restore_verifications set verified_at = verified_at - interval '3 days' where source_id = '<id qa-pg>'"`;
    подождать такт.
    → в чате одно «⚠️ Восстановление не проверено дольше 1 дн.: qa-pg» с
    «Последняя успешная проверка: …» и «Последний итог: не можем проверить»;
    на обзоре «давно не проверялись 1». Ещё два такта → новых сообщений нет.
25. «Проверить сейчас» у `qa-pg` до успеха.
    → одно сообщение «✅ Проверка восстановления снова прошла: qa-pg» (ОВ11б);
    счётчик «давно не проверялись» — 0. Вернуть порог 2.
26. Выключить переключатель «Проверять восстановление» у `qa-www`.
    → метрика «проверка выключена»; на обзоре «не проверяются 1» (ОВ3).
    Остановить сервер API (`$DC stop server`) и переключить снова → переключатель
    вернулся в прежнее положение, показана ошибка. Запустить сервер.

## Часть 5. Отчёт

27. Вкладка «Проверки» `qa-pg` → «Отчёт».
    → период — последние 30 дней (ОВ2); таблица проверок, сводка итогов,
    провал части 3 с датой исправления; внизу дата формирования и версия Sard,
    совпадающая с версией на обзоре; нет меню и цветных фонов. Секретов и
    вывода стадий нет.
28. Выбрать конец периода раньше начала.
    → ошибка у поля конца периода.
29. Печать (Ctrl+P), A4, книжная.
    → все колонки на странице, строки не разрезаны, шапка таблицы на каждой
    странице, навигации консоли нет. Повторить при языке EN.

## Часть 6. Самобэкап

30. На установке с завершённым самобэкапом и верификатором с ключом к его
    репозиторию открыть настройки.
    → раздел самобэкапа показывает метрику проверки по каждому источнику
    самобэкапа; карточка системного источника — ту же (ОВ6).

## Часть 7. Сбой сервера в консоли

31. `$DC stop server`, обновить обзор.
    → блок проверки — ошибка с повтором; остальные блоки обзора тоже
    показывают свои ошибки, страница не пустая. `$DC start server` и «Повтор»
    → данные вернулись.
