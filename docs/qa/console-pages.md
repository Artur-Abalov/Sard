# QA: страницы консоли этапа 1 (W2)

Сценарии: `docs/specs/web/console-pages.feature` (W2) и
`docs/specs/web/agent-enrollment.feature` (S2b, консоль). Поведение сервера —
`docs/specs/server/rest-api.feature` (S8b). Контракт — `web/src/api/openapi.json`.
Пометка `[ОВ…]`, `[Г…]` или `[П…]` у шага называет вопрос, пробел или
предложение из заголовка спецификации W2; до решения владельца такой шаг
выполняется по предложению specifier и его результат помечается в отчёте.

**Статус: черновик, не утверждён.**

Процедура из трёх частей:

- **Часть 1 — Vitest и статические проверки** (без браузера).
- **Часть 2 — путь нового пользователя** от пустой консоли до первого
  успешного бэкапа, против сервера и настоящего агента.
- **Часть 3 — страницы консоли**, дважды: на моках (`VITE_API_MOCKS=1`) и
  против сервера (`make up`). Результаты проходов совпадают, кроме отличий,
  отмеченных «(моки: …)».

Ожидаемый результат указан после «→» в каждом шаге. Любое расхождение — дефект.

Интервал опроса обозначен `$POLL` (предложение `[ОВ1]` — 3 с).

## Подготовка

Нужны: Docker, `curl`, `jq`, Chromium или Firefox, хост или контейнер для
`sard-agent` с доступом к `localhost:9090` (A2b, A5b). Команды — из корня
репозитория.

```bash
make down; make up
DC="docker compose -f deploy/docker-compose.yml --env-file deploy/.env"
API=http://localhost:8080/api/v1
PW=$(sed -n 's/^SARD_ADMIN_PASSWORD=//p' deploy/.env)
QA=$(mktemp -d)
curl -sS -X POST "$API/session" -H 'Content-Type: application/json' \
  -d "{\"password\":\"$PW\"}" -c "$QA/jar" -o /dev/null -w '%{http_code}\n'
api() { curl -sS -b "$QA/jar" "$@"; }   # api <curl args> <url>
```

→ `make up` завершается, вход — `204`.

В браузере: консоль `http://localhost:5173` (`cd web && npm run dev`), DevTools →
Network открыт, «Preserve log» включён, фильтр `api/v1`.

## Часть 1. Vitest и статические проверки

1. `cd web && npm test`
   → все тесты зелёные; среди имён тестов есть названия сценариев с тегом
   `@vitest` из `console-pages.feature`:
   `grep -o 'Сценарий[^:]*: .*' ../docs/specs/web/console-pages.feature` против
   `npm test -- --reporter=verbose` — каждое название `@vitest` найдено.
2. `cd web && npx tsc --noEmit && npx oxlint && npx prettier --check src`
   → без ошибок.
3. `jq -S '.' agent/plugins/files/schema.json` и configSchema плагина `files` из
   `web/src/mocks/fixtures.ts` (вывести тестом или `node`) → совпадают.
4. `grep -rnE "#[0-9a-fA-F]{3,8}\b|rgb\(|hsl\(" web/src --include=*.tsx --include=*.ts | grep -v theme.ts`
   → пусто (цвета только в `src/theme.ts`).
5. `grep -rnE "['\"](queued|running|succeeded|failed|lost|rejected)['\"]" web/src/pages web/src/*.tsx`
   → значения статусов встречаются только как ключи перевода и в функции опроса
   `[Г5]`, не как отображаемый текст.
6. `node -e` (или тест) по `src/locales/ru.json` и `en.json` → множества ключей
   совпадают; для каждого значения `RunStatus`, `StepStatus`, `StepPhase`,
   `EnrollmentTokenStatus`, `AgentStatus`, `LogLevel`, `ErrorCode`, `StepAction`,
   `RunTrigger` из `openapi.json` есть непустая строка в обоих.

## Часть 2. Путь нового пользователя (против сервера и агента)

Цель фичи: от пустой консоли до первого успешного бэкапа без документации.
Тестировщик пользуется только тем, что показывает консоль; на хосте — только
команды, которые консоль подсказала (`enroll`, `repo init`) и перезапуск службы
агента, о котором консоль говорит.

Сервер чистый: `make down; docker volume rm` томов базы (см. `deploy/`); `make up`.
Агент установлен на хосте (A2b), но не зарегистрирован; в его конфиге задан
репозиторий `qa` (local, каталог `/tmp/sard-qa-repo`), не инициализированный.

1. Войти, открыть `/` → обзор: агентов нет, запусков нет; блок агентов ведёт к
   выпуску токена.
2. Нажать «Выпустить токен», срок не заполнять, создать → окно с `token`,
   `enrollCommand`, кнопками копирования, предупреждением «показывается один
   раз», сроком через 24 ч `[Г6]`. В Network тело POST без `ttlSeconds`.
   Сервер запущен без `SARD_AGENT_ENDPOINT` → в окне предупреждение,
   называющее `SARD_AGENT_ENDPOINT`.
3. Скопировать команду кнопкой, выполнить на хосте, запустить службу агента
   → `[ОВ4]` окно в пределах 2×`$POLL` сообщает «Агент подключился» со ссылкой;
   в Network опрос `GET /enrollment-tokens/{id}` прекратился.
4. Перейти по ссылке → карточка агента: онлайн, версия, ОС, плагин `files`,
   репозиторий `qa` «не инициализирован» с командой `sard-agent repo init qa` и
   словами о перезапуске службы.
5. Выполнить подсказанную команду на хосте, перезапустить службу агента,
   обновить карточку → `qa` «инициализирован» с `repositoryId`.
6. На карточке агента — источников нет, кнопка создания источника → форма с
   выбранным агентом. Выбрать плагин `files`, репозиторий `qa`; при RU поля
   «Пути», «Исключения», «Не выходить за пределы файловой системы» с русскими
   описаниями и примерами. Имя `qa-etc`, путь `/etc`, сохранить
   → карточка источника `qa-etc`; снимков нет, кнопка «Запустить бэкап».
7. Нажать «Запустить бэкап» → `[П5]` карточка запуска: queued → running с фазой
   и объёмами, обновляется каждые `$POLL` → succeeded со снимком, объёмами и
   длительностью; лог шага дочитан, опрос прекратился (в Network нет новых
   запросов 3×`$POLL`).
8. Открыть карточку источника → снимок из шага 7 с `qa`, объёмами и временем.
9. Обзор → онлайн 1 из 1 `[Г1]`; последний запуск — «успешно».

→ Все шаги пройдены без документации и терминала, кроме шагов 3 и 5 на хосте.

## Часть 3. Страницы консоли

Выполняется дважды:

- **Моки:** `make down; cd web && VITE_API_MOCKS=1 npm run dev`; пароль `admin`.
  Данные — фикстуры `src/mocks/fixtures.ts` (агенты `db1` онлайн, `web2` офлайн,
  отозванный, дубликат, без Register; см. сценарий «Фикстуры моков покрывают
  состояния W2»). Запуски в моках не продвигаются и конфиг не проверяется `[Г9]`.
- **Сервер:** `make up; cd web && npm run dev`; данные готовятся агентом из
  части 2 и `curl` (ниже у шагов).

### Навигация и пустые состояния

1. Навигация на каждой странице → пять пунктов: обзор, агенты, токены,
   источники, запуски; текущий отмечен.
2. Сервер с чистой базой: открыть `/agents`, `/tokens`, `/sources`, `/runs`
   → у каждой пустое состояние с действием: агенты → выпуск токена; токены →
   создание токена; источники → выпуск токена (агентов нет); запуски → ссылка на
   источники. (Моки: пустые состояния — переопределением обработчиков в Vitest;
   в браузере на моках пропустить.)
3. Есть агент, нет источников → `/sources` ведёт к созданию источника.
4. `/runs?status=cancelled` → «ничего не подходит под фильтр» и сброс фильтров,
   а не пустое состояние раздела.
5. Создать 60 токенов (`for i in $(seq 60); do api -X POST -H 'Content-Type: application/json' -d '{}' $API/enrollment-tokens >/dev/null; done`),
   открыть `/tokens` → 50 строк и «Показать ещё»; нажать → 10 строк добавлены
   без повторов, кнопки больше нет; в Network второй запрос с `cursor`.
   (Моки: создать 60 токенов в консоли не нужно — достаточно `limit` в тесте
   пагинации мока; в браузере проверить на списке запусков, если в фикстурах
   больше одной страницы, иначе пропустить.)

    «неполный».

### Логи

56. Карточка с шагом → запрос логов `afterSeq=0&limit=500`; строки по порядку с
    временем, уровнем текстом и текстом.
57. Моки: `runningRun` (350 строк) — сервер: шаг с > 500 строк → «Показать ещё»
    → запрос с `afterSeq` = `nextAfterSeq`, строки добавлены без повторов.
58. Running-шаг → логи дочитываются каждые `$POLL` с последним `nextAfterSeq`;
    после завершения (сервер) — дочитаны до `hasMore false`, дальше запросов
    нет.
59. Моки: шаг с `truncated true` → пометка об усечении; последняя строка с
    прочерком вместо времени. Сервер: агент с логом > 16 МиБ — по QA S8b; то же.
60. Строка с `[REDACTED]` (моки: фикстура; сервер: источник с секретом,
    скрипт, печатающий его) → `[REDACTED]` как есть.
61. Строка `<img src=x onerror=alert(1)>` (моки: фикстура или переопределение)
    → текст показан буквально, alert не появляется.
62. Шаг queued → «строк пока нет».

### Снимки

63. Карточка источника со снимком → id снимка, репозиторий, всего, добавлено,
    время, ссылка на запуск; неполный — пометка с пояснением.
64. Источник без снимков → пояснение и «Запустить бэкап».
65. Заблокировать `GET …/snapshots` (DevTools) → карточка источника показана,
    блок снимков с ошибкой и повтором.
