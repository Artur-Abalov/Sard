# Токен регистрации агента — формат

Общий контракт сервера (S2a) и агента (A2a). Семантику регистрации — что
отклонять и какие сообщения видит пользователь — задают сценарии S2b/A2b.

## Строка

```
sard_<секрет>.<отпечаток>
```

| Часть | Правило |
|---|---|
| префикс | ровно `sard_` (строчные) |
| разделитель | ровно одна `.` во всей строке после префикса |
| секрет | 32 байта из CSPRNG, base64url (RFC 4648 §5) **без** паддинга — ровно 43 символа `[A-Za-z0-9_-]`, канонический: два младших бита последнего символа нулевые |
| отпечаток | SHA-256 от DER `SubjectPublicKeyInfo` корневого CA, как он записан в сертификате (ADR 0014), lowercase hex — ровно 64 символа `[0-9a-f]` |

Длина строки — 113 символов. Разбор строгий: любое нарушение — ошибка с
типом, нарушенное правило проверяется в порядке таблицы. В тексте ошибки нет
входной строки.

| Тип ошибки (сервер, `MalformedEnrollmentTokenException.Reason`) | Нарушение |
|---|---|
| `PREFIX` | строка не начинается с `sard_` |
| `SEPARATOR` | точек после префикса не ровно одна |
| `SECRET_LENGTH` | секрет не 43 символа (в том числе с `=`-паддингом) |
| `SECRET_ALPHABET` | в секрете символ вне base64url (`+`, `/` и т. п.) |
| `SECRET_ENCODING` | секрет не канонический (ненулевые хвостовые биты) |
| `FINGERPRINT_LENGTH` | отпечаток не 64 символа |
| `FINGERPRINT_ALPHABET` | отпечаток не lowercase hex |

В Go канонический разбор секрета — `base64.RawURLEncoding.Strict().DecodeString`;
отпечаток — `sha256.Sum256(cert.RawSubjectPublicKeyInfo)`.

## Хранение

- Сервер хранит только `token_hash = SHA-256(32 байта секрета)` — от байтов, не
  от строки и не от base64. Колонка `enrollment_tokens.token_hash BYTEA`,
  уникальна во всей базе.
- Секрет высокоэнтропийный (256 бит), поэтому медленный хэш (bcrypt, argon2)
  не нужен.
- Строка токена существует на сервере только в ответе на создание и больше
  нигде: ни в базе, ни в логах, ни в `toString`, ни в исключениях.

## Отпечаток

Отпечаток в токене — якорь доверия первого подключения: агент ещё не знает CA,
получает цепочку сервера по TLS, считает отпечаток корня из этой цепочки и
сравнивает с отпечатком из токена. Поэтому сервер отдаёт в рукопожатии
цепочку вместе с корневым сертификатом.

Проверка вне Sard:

```bash
python3 -c "import hashlib,base64; s=bytes(range(32)); \
print(base64.urlsafe_b64encode(s).rstrip(b'=').decode()); \
print(hashlib.sha256(b'sard-test-ca').hexdigest()); print(hashlib.sha256(s).hexdigest())"
```
