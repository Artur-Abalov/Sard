## A8b-2

### Где что лежит

- `hostsetup/sftp.go` — адрес `sftp:` (Р32). `hostsetup/sshhome.go` — `SSHHome`:
  домашний каталог из passwd (`User.Home`), `~/.ssh`, чтение и запись только
  через удерживаемые дескрипторы. `Dir` получил `CreateFile`, `OpenFile`, `Lstat`
  (O_PATH), `Rename`, `Remove`, `Sync`. `hostsetup` по-прежнему импортирует
  только `config` и `refusal`.
- `repoconnect/sftp.go` — `SFTP.Prepare`: порядок Р42 (файлы `~/.ssh` →
  сканирование → решение о ключе хоста → ключ SSH → `known_hosts` → `config` →
  проверка входа), классы отказов входа по stderr, `CheckClient` (Р36).
  `knownhosts.go` — разбор и запись `known_hosts` (хешированные записи, `[хост]:порт`,
  списки, шаблоны, отрицания). `sshconfig.go` — управляемый блок. `Bound.Within`
  — предел `--connect-timeout` для любого вызова; `Confirmation` — вопрос
  оператору с терминала с остановкой `--timeout`.
- `cmd/sard-agent/repo_add_sftp.go` — провод: адрес и флаги вида, поиск программ
  в `PATH` restic, запуск программ клиента (`sshRunner`: от пользователя службы,
  окружение `PATH`, `HOME`, `LC_ALL=C`), печать итога. Код выхода 5
  (`refusal.ClassTrust`).
- `repoinit.Target.Directory`: отказ доступа SFTP называет каталог.
- Документация: `05a-storage.md` (раздел SFTP заменён командой, таблица причин),
  `agent-host-setup.md`, `05-agents.md`, `deploy/agent/agent.example.yaml`,
  `test/e2e/README.md`, ADR 0051, строка в ADR 0050, дополнение Н24 в ADR 0047.

### Решения при реализации (в рамках спецификации)

- Каталог `~/.ssh` и домашний каталог создаются **лениво**, при первой записи,
  а не при открытии: сценарии отказов до записи (сканирование, подтверждение
  ключа хоста) требуют «файлы ssh не изменены».
- Проверка входа — `sftp -b /dev/null` с `-o BatchMode=yes -o
  StrictHostKeyChecking=yes -o ConnectTimeout=N -P порт`: параметры блока
  передаются и в командной строке, чтобы проверка не зависела от `config`.
- `known_hosts`: если последняя строка файла без перевода строки, перед новой
  строкой ставится перевод (строки не склеиваются); это единственное изменение
  прежнего содержимого.
- Шаблон имени хоста в `known_hosts`, подходящий и другим хостам (`*.example.com`),
  при замене ключа не удаляется (Н18 говорит о записях «этого хоста»).
- Подтверждение ключа читается с эхом (`LinePrompter.ReadLine`), в отличие от
  секретов.
- Закрытый ключ root не открывает: наличие и тип — `Lstat` через дескриптор
  `O_PATH|O_NOFOLLOW` (без чтения), ссылка видна как ссылка.

- Красный прогон видели: коды и классы причин (не компилировалось), адрес

## Для specifier

1. **QA, шаг 70, и раздел «Блокировки»:** `grep 'sudo -u' docs/operator/05a-storage.md`
   по QA должен быть пуст, но команда `unlock` в конце документа (исправленная
   A8b-1 на `/usr/libexec/sard/restic`) идёт `sudo -u sard-agent sh -c …`. Либо шаг 70
   разрешает эту строку, либо нужна команда `unlock` без `sudo -u`.
2. **Р40, лишние пробелы в ответе.** Принимается только строка ровно `yes`; терминал
   отдаёт строку без перевода, пробелы вокруг — отказ. Спецификация это подразумевает,
   но таблица «ответов» не называет `yes ` с пробелом.
3. **Р41 и порт.** Блок `Host <хост>` не различает порты одного хоста: два
   репозитория на разных портах одного хоста делят блок. Для ключа хоста порт
   различается (`[хост]:порт`), для параметров ssh — нет.
4. **Р45, повтор с отозванным ключом.** Повтор при готовых файлах и репозитории
   всё равно проверяет вход по ssh (сеть), прежде чем сказать `unchanged`;
   спецификация этого не запрещает, но «ничего не спрашивает» относится только к
   терминалу.
5. **Р43 и сообщение.** Добавлена приписка «ssh files … stay», когда после записи
   файлов `ssh` команда отказала; спецификация приписки не требует.
6. **Права `.pub`.** `ssh-keygen` пишет `id_ed25519.pub` с `0644`; Р38 говорит о
   `config` и `known_hosts` (0600) и не называет `.pub`. QA (шаг 60) ждёт `644`.
