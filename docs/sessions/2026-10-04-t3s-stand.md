# Сессия 2026-10-04: T3s — стенд e2e для обрывов (том CA, медленный плагин)

Ветка `claude/wizardly-maxwell-caeplt` (назначена окружением; в постановке —
`test/t3s-stand`). База — `main` @ `8e786fe` (T2b влит, ветка перемотана).

## Фаза 1 — исследование (код не менялся)

### Окружение
- Docker-демон в контейнере сессии не запущен (`/var/run/docker.sock` нет;
  `dockerd` установлен). Для фазы 2 его надо поднять вручную, как в T2b.
- `docs/t3-defects.md` (ограничения С1–С3) нет ни в `main`, ни в одной ветке
  `origin`; текст С1/С3 взят из постановки.

### Проверенные факты (file:line)
- **С1.** `SardEnvironment` (`test/e2e/.../SardEnvironment.kt:70-80`) запускает
  сервер без томов; CA создаётся при первом старте в `/var/lib/sard/pki`
  (`CA_CERT_PATH`, `:186`). В образе каталог есть, владелец `sard`, 0700
  (`deploy/server/Dockerfile:37-39`), так что именованный том Docker при
  первом монтировании наследует владельца и права. В продукте — том `sard-pki`
  (`deploy/docker-compose.yml:43`).
- PostgreSQL на стенде — `PostgreSQLContainer` без тома; при пересоздании
  только сервера база не теряется. Тома стенда уже есть: `volume()`
  (`SardEnvironment.kt:112-118`), удаляются в `stop()`.
- После пересоздания контейнера меняются проброшенные порты хоста;
  `httpBase`/`grpcPort` вычисляются при каждом обращении — подхватят новые.
  Агент внутри сети ходит по псевдониму `sard-server:9090` — он сохранится.
- Агент переподключается сам: экспоненциальный backoff 1 с … 1 мин с полным
  jitter (`agent/internal/transport/transport.go:66-69,160-170`).
- **С3.** Плагины агента — `plugins.Builtin` (`agent/plugins/builtin.go`),
  реестр уходит в Register через `app.Agent.Plugins`
  (`agent/cmd/sard-agent/main.go:139-141`); сервер хранит их в `agent_plugins`
  (`V202609281400__agent_register.sql:22`). SDK: `Dump{Filename}` выбирает поток,
  `Stream(ctx, h, cfg, d, w)` пишет в stdin restic, `Host.Progress(done,total)`
  (`agent/plugins/sdk/plugin.go`). Прогресс restic при потоке тоже идёт
  (`pluginhost/source.go:74-75`).
- Правило импортов (`agent/plugins/imports_test.go`): конкретный плагин
  импортирует только SDK, а его импортирует только пакет `plugins`.
- Тестовый плагин `agent/internal/pluginhost/testplugin` уже есть, но он для
  юнит-тестов pluginhost и в агент не регистрируется.
- Сборка агента для стенда: `make e2e-images` → `scripts/package-agent.sh`
  (тот же скрипт, что `make package`) → распакованный tar → `test/e2e/agent/Dockerfile`.
  Передать тег сборки сейчас нельзя.
- Ремарка: `Pending.kt` (`StreamBreakT3Pending`) описывает «длинный шаг» как
  «дерево файлов достаточно большое» — это и есть С3.

### Черновик решений (до ответов владельца)
1. **С1.** Тома для `/var/lib/sard/pki` сервера и данных PostgreSQL;
   `SardEnvironment.recreateServer()` — stop + start нового контейнера с теми
   же томами, env и псевдонимом; отпечаток CA читается до и после.
2. **С3.** Плагин `e2e-slow` в `agent/plugins/e2eslow` (только SDK, Apache-2.0
   не нужен — AGPL, как остальные встроенные). Пакет без тега (юнит-тесты,
   покрытие и мутации — в обычном гейте агента); тег `e2e` только на файле
   `agent/plugins/builtin_e2e.go`, который добавляет плагин в `Builtin`. Без тега
   плагин в бинарник не линкуется.
   Конфиг: `size` (байты), `rate` (байт/с), `chunk` (байты), `seed`; поток —
   детерминированный ГПСЧ от `seed`; `Verify` сверяет восстановленный файл.
   Прогресс — `Host.Progress(written, size)` после каждой порции.
3. `package-agent.sh` принимает `GO_TAGS` (только `e2e-images` задаёт `e2e`);
   проверка пакета — см. вопрос 4.

### Ответы владельца (фаза 1)
1. Ветка — назначенная окружением. 2. `t3-defects.md` передан файлом: С1/С3
   совпадают с постановкой, нового для стенда нет. 3. Тег только на файле
   регистрации — да. 4. Доказательство — (а) Go-тест и (б) проверка в
   `package-agent.sh`, без второго образа. 5. Пересоздаётся только сервер,
   PostgreSQL — в томе. 6. Длительность — `started_at`→`finished_at` шага на
   сервере, 24 МиБ при 1 МиБ/с, порции 64 КиБ. 7. FXs/FXa идут параллельно,
   делать сейчас; влить `main` — по команде владельца. 8. Пределов в схеме нет.

## Фаза 2 — реализация и проверка

### Что сделано
- **Плагин** `agent/plugins/e2eslow` (тест первым, `plugin_test.go`): `size`,
  `rate`, `chunk`, `seed`; поток — блоки SHA-256(seed ‖ i); после каждой порции
  `Progress(done, size)` и сон до `start + done/rate` через инъецируемые часы.
- **Регистрация за тегом**: `plugins/stand.go` (`!e2e`, пусто) /
  `plugins/stand_e2e.go` (`e2e`, `e2e-slow`); `Builtin` добавляет `stand(...)`.
  Тесты: `stand_test.go` (`!e2e`, реестр релиза — ровно четыре плагина) и
  `stand_e2e_test.go` (`e2e`, пять).
- **Сборка**: `scripts/package-agent.sh` принимает `GO_TAGS`, проверяет теги
  бинарника (`go version -m`) и отсутствие `plugins/e2eslow` в релизе;
  `make e2e-images` передаёт `GO_TAGS=e2e`. Гейт агента: шаг «e2e stand build»
  (vet, golangci-lint, тесты `./plugins/...` с тегом `e2e`).
- **Стенд**: тома для PKI сервера и данных PostgreSQL, `recreateServer()`.
- **e2e**: `ServerRecreateTest`, `SlowStreamTest`; `Pending.kt` (T3) ссылается на них.
- ADR 0036, `test/e2e/README.md`.

### Найдено на первом e2e-прогоне (проверено)
- Шаг `e2e-slow` висел в `running` с прогрессом 65536 из 25165824: агент 99% CPU,
  restic 63%. Дамп горутин (SIGQUIT агенту): `io.CopyN` → `os.File.ReadFrom` →
  `write(…, 0x20)` — запись в pipe по 32 байта (один блок SHA-256 за `Read`).
  Вне контейнера тот же путь через pluginhost с настоящим restic проходил за 2,7 с,
  в контейнере — ползёт. Исправление в плагине: порция собирается в буфер и
  пишется одним `Write`; тест `TestStreamWritesEachChunkInOneWrite`.
  Продуктовый код не менялся.
