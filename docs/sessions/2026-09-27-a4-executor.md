### Противоречия и неоднозначности контракта (не выбраны молча)

1. TIMED_OUT определён как «Exceeded RunStep.timeout», а scope вводит
   максимальный таймаут из опций для шага без таймаута. Предлагаю тоже
   TIMED_OUT, `message` уточняет, какой лимит сработал. Вопрос 3.
2. REJECTED означает «Not started», но невалидный конфиг и неизвестный секрет
   проверяет обработчик, то есть после ACCEPTED. Разрешение: обработчик
   обязан возвращать `ErrRejected` только до побочных эффектов; исполнитель
   этого не может проверить — это контракт интерфейса, записан в doc-комментарий.
3. Завершение агента: CANCELLED — это «Cancelled by CancelStep», поэтому шаги,
   прерванные остановкой агента или найденные незавершёнными после
   перезапуска, получают FAILED. Вопрос 4.

### Дизайн

#### Граница с транспортом

```go
// Sink receives everything the executor reports. A3 implements it over the
// Connect stream. Methods are called with the executor's lock held, in the
// order events happen; they must not block and must not call the executor.
type Sink interface {
	Progress(p *agentv1.StepProgress)
	Result(r *agentv1.StepResult)
	Log(commandID string, line *agentv1.LogLine)
}

func New(opts Options) (*Executor, error)       // loads the state dir
func (e *Executor) Submit(step *agentv1.RunStep) // never blocks
func (e *Executor) Cancel(commandID string)
func (e *Executor) Ack(commandID string) error
func (e *Executor) RunningIDs() []string          // for Hello
func (e *Executor) PendingResults() []*agentv1.StepResult
func (e *Executor) Close(ctx context.Context) error
```

`Sink` вызывается под мьютексом исполнителя: так порядок «ACCEPTED раньше
результата» и «результат после записи на диск» держится без отдельной
горутины-эмиттера. Цена: A3 должен буферизовать (канал/очередь), а не писать
в стрим синхронно. Отвергнуто: вызовы вне блокировки (гонка — CANCELLED
из очереди может обогнать ACCEPTED); горутина-эмиттер с неограниченной
очередью (больше кода, та же гарантия).

`Submit` без `command_id` ничего не делает, пишет предупреждение: ответить
некому.

#### Граница с плагинами

```go
// Handler runs steps of one plugin. A6 adapts sdk.Plugin to it.
type Handler interface {
	// Actions lists the actions this plugin supports.
	Actions() []agentv1.Action
	// Run executes the step. It returns a StepResult carrying only Output
	// (and optionally Message); the executor sets the other fields. Invalid
	// config or an unknown secret is reported as an error wrapping
	// ErrRejected, and only before any side effect.
	Run(ctx context.Context, step *agentv1.RunStep, r Reporter) (*agentv1.StepResult, error)
}

type Reporter interface {
	Progress(phase agentv1.StepPhase, bytesProcessed, bytesTotal uint64)
	Log(level agentv1.LogLevel, text string)
}

type Registry interface { Handler(plugin string) (Handler, bool) }

var ErrRejected = errors.New("step rejected")
```

Обработчик возвращает `*agentv1.StepResult`: другой способ вернуть значение
oneof без параллельной иерархии невозможен, так как `isStepResult_Output` не
экспортирован. Отвергнуто: своя структура `Output{Backup, Restore, …}` —
это параллельная иерархия.

#### Опции (значения по умолчанию)

| Поле | По умолчанию | Смысл |
|---|---|---|
| `Handlers Registry` | обязательно | реестр обработчиков |
| `Sink Sink` | обязательно | приёмник |
| `StateDir string` | обязательно | каталог состояния, 0700 |
| `Repositories []string` | пусто | известные `repository_name` |
| `MaxParallel int` | 1 | одновременно выполняемые шаги |
| `MaxQueue int` | 16 | ожидающие в очереди (без выполняющихся) |
| `MaxTimeout time.Duration` | 24h | таймаут шага без `RunStep.timeout` |
| `CancelGrace time.Duration` | 30s | ожидание обработчика после отмены (больше `restic.DefaultGrace` = 10s) |
| `ProgressInterval time.Duration` | 1s | не чаще одного прогресса на шаг |
| `Retention time.Duration` | 7 × 24h | сколько помнить подтверждённые `command_id` |
| `Clock Clock` | системные часы | `Now()` и `AfterFunc(d, f) Timer` |
| `Logger *slog.Logger` | discard | предупреждения исполнителя |

#### Состояния команды

```
          Submit (прошёл проверки, есть место)
  ───────────────► QUEUED ──(слот свободен)──► RUNNING ──(обработчик вернулся)──┐
                     │                           │                              │
                     │ Cancel / Close            │ Cancel / таймаут / Close      │
                     ▼                           ▼                              │
                  (результат)                 STOPPING ──(вернулся или истёк     │
                     │                           │        CancelGrace)          │
  Submit (провал     │                           ▼                              │
  проверок) ────────►└──────────────────────► FINISHED (результат на диске) ◄───┘
                                                 │ Ack
                                                 ▼
                                              ACKED (надгробие) ──(Retention)──► забыт
```

- QUEUED: записан `inflight/`, отправлен ACCEPTED.
- RUNNING/STOPPING: обработчик выполняется; `context.WithCancelCause`, причина —
  `errCancelled`, `errTimedOut` или `errShutdown`.
- FINISHED: `results/<key>.json` записан, результат отдан в `Sink`, ждёт Ack.
- ACKED: `results/` удалён, `acked/<key>.json` хранится `Retention`.

Дубликат `Submit`: QUEUED — повтор ACCEPTED; RUNNING/STOPPING — последний
отправленный прогресс (в обход ограничения частоты); FINISHED и ACKED —
повтор сохранённого результата. Обработчик в этих случаях не вызывается.

`Cancel`: QUEUED — CANCELLED без запуска, слот не нужен; RUNNING — отмена
context, переход в STOPPING; STOPPING, FINISHED, ACKED — повтор текущего
состояния (результат, если он есть); неизвестный id — игнорируется с
предупреждением.

Статус по возврату обработчика (по порядку):
1. паника → FAILED «plugin panicked: <значение>», стек — в `Logger`;
2. `err == nil` → SUCCEEDED (даже если отмена пришла, но шаг успел
   завершиться: это «настоящий результат»);
3. установлена причина отмены → CANCELLED / TIMED_OUT / FAILED (остановка агента);
4. `errors.Is(err, ErrRejected)` → REJECTED;
5. иначе FAILED с `err.Error()`.
`Output`, возвращённый вместе с ошибкой, сохраняется.

Обработчик не вернулся за `CancelGrace` после отмены → результат фиксируется
по причине отмены, пишется предупреждение, слот освобождается (иначе
зависший плагин навсегда останавливает агент — вопрос 2). Поздний возврат
такого обработчика и его вызовы репортёра отбрасываются.

`started_at` — момент запуска обработчика; у REJECTED до запуска и CANCELLED из
очереди не заполняется. `finished_at` — всегда.

#### Предварительные проверки (до ACCEPTED, → REJECTED)

1. `Handlers.Handler(plugin)` не найден.
2. `action` не входит в `Actions()` (UNSPECIFIED не входит никогда).
3. Для BACKUP/RESTORE/VERIFY `repository_name` пуст или не в
   `Repositories`; для RUN непустое имя тоже должно быть известно.
4. Очередь полна (`MaxQueue` ожидающих).
REJECTED сохраняется как любой результат и ждёт Ack: повтор того же
`command_id` получит тот же REJECTED, обработчик не вызывается.

#### Таймаут и частота прогресса

- Таймаут = `RunStep.timeout`, если он > 0; иначе `MaxTimeout`. Отсчёт — с
  запуска обработчика, не с постановки в очередь. Таймер — `Clock.AfterFunc`.
- Прогресс: пропускается, если фаза не сменилась и с прошлой отправки прошло
  меньше `ProgressInterval`. Смена фазы отправляется всегда. Подавленные
  значения не досылаются (результат всё равно придёт). Отвергнуто:
  досылка последнего значения по таймеру — лишний таймер на шаг ради
  промежуточной цифры. ACCEPTED/UNSPECIFIED от обработчика игнорируются.

#### Формат каталога состояния

```
<StateDir>/            0700
  inflight/<key>.json  принят, не завершён     {"version":1,"command_id":"…","accepted_at":"…"}
  results/<key>.json   завершён, ждёт Ack       {"version":1,"result":<protojson StepResult>}
  acked/<key>.json     подтверждён (надгробие)  {"version":1,"acked_at":"…","result":<…>}
```

- `<key>` = hex(SHA-256(command_id)): `command_id` приходит от сервера и может
  содержать `/` или `..`; сам id хранится внутри файла.
- Файлы 0600. Запись: `CreateTemp` в том же каталоге → write → `fsync` →
  `rename` → `fsync` каталога.
- Переходы и восстановление после сбоя между шагами:
  - принят: запись `inflight` до ACCEPTED; ошибка записи → FAILED «not
    started: cannot persist state», обработчик не вызывается — иначе после
    перезапуска возможен повторный запуск;
  - завершён: запись `results` → удаление `inflight`; найдены оба → `results`
    главнее, `inflight` удаляется;
  - Ack: запись `acked` → удаление `results`; найдены оба → `acked` главнее.
- При старте (`New`): `acked` старше `Retention` удаляются, остальные
  попадают в память для дедупликации; `results` → `PendingResults`;
  `inflight` без результата → FAILED «agent restarted while the step was
  queued or running» записывается в `results` (обработчик мог уже частично
  выполниться, повторять нельзя). Повреждённый или неизвестной версии файл не
  удаляется, пишется предупреждение.
- Надгробия с истёкшим `Retention` удаляются и при `Ack`.
- `PendingResults` отсортированы по `finished_at`, затем по `command_id`.
- Ошибка записи результата: результат всё равно уходит в `Sink` и остаётся в
  памяти как FINISHED, ошибка — в `Logger`.

#### RunningIDs и Close

- `RunningIDs` = QUEUED + RUNNING + STOPPING: сервер не должен ни помечать
  стоящие в очереди как потерянные, ни присылать их снова.
- `Close(ctx)`: новые `Submit` отклоняются молча; QUEUED → FAILED «agent is
  shutting down»; RUNNING → отмена с `errShutdown`; ждём обработчики до
  `ctx.Done()`, затем недождавшиеся фиксируются как FAILED. Возвращает
  `ctx.Err()`, если ждать пришлось дольше.
