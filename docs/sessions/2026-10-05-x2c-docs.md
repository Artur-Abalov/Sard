## AX: мелкие дыры агента (OQ-001, OQ-050, OQ-126, OQ-026)

Все четыре перепроверены по коду на `585a513`, все открыты.

### Решения владельца (2026-10-05)

1. **OQ-001.** `INVALID_ARGUMENT` на Register — окончательная ошибка (ADR 0025, «Повтор»). Агент выходит с отдельным кодом выхода. Юнит `sard-agent.service` получает `RestartPreventExitStatus` с этим кодом, и systemd больше не перезапускает агента. Правило действует для всех окончательных отказов Register: неверная конфигурация, отозванный сертификат, несовместимый протокол. Оператор правит причину и перезапускает службу сам.
2. **OQ-050.** Неподдерживаемый `crypto_provider` — агент не стартует: пишет ошибку с именем репозитория и выходит. Проверка делается при старте службы, а не в `config.Load`, чтобы `repo init` и `repo list` сохранили свою причину `CRYPTO_PROVIDER_UNSUPPORTED` (`repo-init.feature`, П6).
3. **OQ-026.** Шаблон токена строится по его алфавиту: `sard_[A-Za-z0-9_-]+(?:\.[0-9a-fA-F]*)?`. Знаки после токена (двоеточие, кавычка) не съедаются. Путь `/etc/sard_agent/x` по-прежнему вычищается: лучше вычистить лишнее, чем пропустить обрезанный токен.
4. **OQ-126.** Решение не требуется: путь из ошибки чтения секрета убирается так же, как в `stepsecrets`.

Процесс: specifier дописывает сценарии OQ-001 и OQ-050 в спецификации агента, дальше `/quick-fix` (coder → cleaner → architect). hardener не запускается.
