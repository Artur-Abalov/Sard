### Предложения для контрольной точки 1 (ждут решения владельца)

**Реестр.** GHCR (`ghcr.io/artur-abalov/sard-server`): бесплатно для
публичного репозитория, публикация `GITHUB_TOKEN`-ом без внешних секретов,
из РФ сейчас доступен; Docker Hub для пользователей из РФ ограничивался —
поэтому `postgres` тоже зеркалируется в GHCR по зафиксированному digest
(`ghcr.io/artur-abalov/sard-postgres:18-alpine`), и установка тянет всё из
одного реестра. Страховка — офлайн-архив в GitHub Release. Российский реестр
(Yandex CR и т. п.) — вторым зеркалом позже, если GHCR станет недоступен:
требует аккаунта и секретов в CI.

**HTTPS консоли и отдача SPA.** Одно решение закрывает обе дыры: обратный
прокси Caddy в compose — отдаёт собранную консоль (`try_files` → `index.html`),
проксирует `/api/*` на сервер, получает сертификат Let's Encrypt
автоматически либо берёт свой (`tls /certs/...`). Порт 9090 публикуется
сервером напрямую, 8080 наружу не публикуется. Чтобы вход за прокси работал
без изменения кода (OQ-031), сервер запускается с
`SERVER_FORWARD_HEADERS_STRATEGY=native`: Tomcat доверяет
`X-Forwarded-Proto` только от внутренних адресов (сеть compose), тогда
`isSecure` = true, `Origin` совпадает, cookie получает `Secure`. Это меняет
решение Р4 ADR 0021 конфигурацией, поэтому нужен новый ADR и согласие.
Альтернатива без доверия заголовкам — TLS на самом сервере
(`SERVER_SSL_*`, свой сертификат), но тогда консоль всё равно отдавать нечем.
