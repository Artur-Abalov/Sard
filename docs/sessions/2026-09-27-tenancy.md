# Сессия 2026-09-27: мультитенантность и схема БД

## Решения
- Схема мультитенантна с первого дня: общая схема, дискриминатор `tenant_id`, фильтрация Hibernate `@TenantId`. Открытое ядро прибито к `DEFAULT_TENANT_ID` (`00000000-0000-0000-0000-000000000001`). Подробно и целевая схема — ADR 0013.
- Шов по эскизу владельца: `TenantResolver` (`extension/`), `TenancyAutoConfiguration` с `@ConditionalOnMissingBean`, `HibernateTenantBridge` (`persistence/`), регистрируется через `HibernatePropertiesCustomizer`.
- Уточнения к эскизу: enterprise-стартер обязан объявить `@AutoConfiguration(before = [TenancyAutoConfiguration::class])`; таблица `tenants` с FK; составные FK `(tenant_id, id)` для будущих таблиц; `DEFAULT` в базе только для заполнения V2.
- Основа тенантности — инфраструктура без пользовательского поведения, через `/ship-feature` не проводилась (как каркас), но прошла `make gate M=server`.
- Остальные таблицы целевой схемы создаются миграциями своих фич.

## Ревью владельца схемы — правки ADR 0013
- Составные FK на всех связях между таблицами тенантов; правила «`tenant_id` → `tenants`», «`UNIQUE (tenant_id, id)`», «ссылки по паре» проверяет `TenantSchemaRulesTest` по каталогу PostgreSQL, с контрольным прогоном на плохих таблицах в откатываемой транзакции (без контроля проверка на пустой схеме доказывала бы только отсутствие ошибок в SQL).
- История (`runs`, `run_steps`, `snapshots`, `restore_verifications`) неизменна; `agents`, `sources`, `workflows`, `schedules` удаляются мягко, FK из истории без каскада и `SET NULL`; уникальность имён — частичным индексом по живым строкам.
- Метрика «последнее проверенное восстановление»: `restore_verifications.source_id` + частичный индекс; копия защищена составным FK `(tenant_id, snapshot_id, source_id)`.
- `run_steps`: `source_id`, `config` как отправлен, статусы `queued → dispatched → running → final` и `lost` для сверки на `Hello`; `CHECK` на все перечисления.
- `agent_certificates` отдельной таблицей; `snapshots.forgotten_at`, `repository_id NOT NULL`; `step_logs` секционирована по времени сервера, срок хранения глобальный; `schedules.misfire_policy` и выбор через `SKIP LOCKED`; `plugin_schemas` адресуется хешем.
- Отступление от предложения: `on_origin_host` не хранится (вычислим из неизменных колонок), вместо него `key_holders` — число хранителей ключа в момент проверки, которое потом не вычислить.
- Найдено: `BackupOutput` не несёт `repository_id` — аддитивное поле в proto на этапе «первый бэкап».
