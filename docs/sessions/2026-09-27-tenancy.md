# Сессия 2026-09-27: мультитенантность и схема БД

## Решения
- Схема мультитенантна с первого дня: общая схема, дискриминатор `tenant_id`, фильтрация Hibernate `@TenantId`. Открытое ядро прибито к `DEFAULT_TENANT_ID` (`00000000-0000-0000-0000-000000000001`). Подробно и целевая схема — ADR 0013.
- Шов по эскизу владельца: `TenantResolver` (`extension/`), `TenancyAutoConfiguration` с `@ConditionalOnMissingBean`, `HibernateTenantBridge` (`persistence/`), регистрируется через `HibernatePropertiesCustomizer`.
- Уточнения к эскизу: enterprise-стартер обязан объявить `@AutoConfiguration(before = [TenancyAutoConfiguration::class])`; таблица `tenants` с FK; составные FK `(tenant_id, id)` для будущих таблиц; `DEFAULT` в базе только для заполнения V2.
- Основа тенантности — инфраструктура без пользовательского поведения, через `/ship-feature` не проводилась (как каркас), но прошла `make gate M=server`.
- Остальные таблицы целевой схемы создаются миграциями своих фич.
