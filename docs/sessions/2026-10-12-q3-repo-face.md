## Черновик первого экрана README (на ревью)

```markdown
[Русская версия](README.ru.md)

# Sard

Sard is a backup console for the mixed infrastructure of small and
mid-sized businesses, built for the integrators and MSPs who look after it;
its aim is backups you have proven you can restore.

> Status: early development, pre-release. Restore from the console and
> automatic restore verification are not there yet; see below.

## What it does today

- Backs up files and directories, and PostgreSQL databases (`pg_dump` of a
  database in custom format plus the cluster's roles and tablespaces).
- Stores backups with [restic](https://restic.net) in S3-compatible storage,
  over SFTP or in a local directory; restic does deduplication and encryption.
- Runs backups on a cron schedule in a chosen time zone, with one catch-up
  run after downtime, or on demand from the console.
- Reports runs and missed schedules to Telegram.
- Installs agents from the server: deb, rpm and tar.gz for Linux amd64 and
  arm64, signed releases.

Not yet: restore from the console (restore is a manual `restic restore`,
see [docs/demo.md](docs/demo.md)), restore verification, self-backup of the
server, other sources (MySQL, network devices, 1C), several tenants.

## How it works

(существующая схема из README без изменений)

An agent runs on each host and dials out to the server over gRPC with
mutual TLS, so hosts open no inbound ports. Backup data goes from the agent
straight to storage, never through the server. Repositories, storage keys
and scripts are defined on the agent host and referenced by name only: the
server holds no storage keys ([ADR 0008](docs/adr/0008-crypto-provider.md)).
```

Дальше по плану: быстрый старт (блок Q1 дословно, с маркерами), документация,
лицензии кратко, сообщение об уязвимости, участие. Русская версия — тот же
состав.
