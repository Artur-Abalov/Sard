# Сессия 2026-09-27: S8a — контракт REST API этапа 1

Ветка: `claude/relaxed-davinci-utssgg` (в задаче названа `feat/s8a-openapi`, но среда сессии требует эту).

## Фаза 1 — исследование

### Проверено (файлы прочитаны)
- Источник истины OpenAPI — код сервера (springdoc), не файл спецификации.
  `server/build.gradle.kts:37` подключает `springdoc-openapi-starter-webmvc-api:3.1.1`.
  Документ выгружает тест `SardServerIntegrationTest.kt:110-120` (`GET /v3/api-docs`, без `servers`,
  пишет в `build/openapi/openapi.json`). Тест поднимает Testcontainers, поэтому нужен Docker.
  `make openapi` (`Makefile:81-86`) копирует файл в `web/src/api/openapi.json` и запускает `npm run gen:api`
  (`web/scripts/gen-api.mjs`, openapi-typescript), который пишет `src/api/schema.d.ts`.
- CI уже проверяет актуальность обоих файлов: job server — `cp` плюс `git diff --exit-code` для openapi.json
  (`.github/workflows/ci.yml:91-94`); job web — `gen:api` плюс `git diff --exit-code` для schema.d.ts.
- Линтера спецификации нет. `@redocly/openapi-core` есть в lock только как транзитивная зависимость openapi-typescript.
- REST на сервере — только `api/StatusController.kt`. Spring Security нет, сессий нет.
- Моки W1a: `web/src/mocks/http.ts:9` — `createOpenApiHttp<paths>()`; `handlers.ts`, `fixtures.ts`.
  Проверки типов лежат в `contract.typecheck.ts` (`@ts-expect-error`, проверяются только `tsc -b`).
  Vitest использует `msw/node` с `onUnhandledRequest: 'error'` (ADR 0016).
- Proto (`proto/sard/agent/v1/agent.proto`) определяет перечисления:
  - `StepPhase` (:192) — 6 значений;
  - `LogLevel` (:217) — 4;
  - `StepStatus` (:251) — 5;
  - `Action` (:329) — 4.
- В proto нет статуса запуска, триггера, статуса «онлайн» и `seq` у строк лога.
- ADR 0013 (:116-146):
  - `runs.status` принимает 5 значений, `runs.trigger` — 3;
  - `run_steps.status` — 9: 5 из proto плюс `queued`, `dispatched`, `running`, `lost`;
  - `phase` совпадает с proto 6/6, `action` — 4/4;
  - у `step_logs` есть `seq`, но нет CHECK для `level`.
- В миграциях этих таблиц ещё нет. Таблицы `runs`, `run_steps`, `sources`, `step_logs`, `snapshots` описаны только в ADR.
- В ADR 0013 `runs` ссылаются на `workflow_id`, а не на источник. В `sources` нет `repository_name`,
  хотя `RunStep.repository_name` для бэкапа обязателен (`agent.proto:344-369`).
- `features/W1b-admin-login.md` нет ни в рабочем дереве, ни в одной удалённой ветке (`git ls-tree` всех веток).
  D2 и D6 в репозитории не упоминаются.

### Полагаю (не проверено)
- Для спецификации-файла пришлось бы убрать или переделать CI-шаг экспорта: сервер выгружает только `/status`,
  поэтому `git diff` после `cp` затёр бы файл.
- springdoc выведет перечисления из Kotlin `enum class` как `enum` в схеме.

### Предложение
Контроллеры-заглушки на сервере: DTO, аннотации springdoc, ответ 501 problem+json. Сравнение с файлом
спецификации и вопросы — в отчёте владельцу. Ждём ревью.
