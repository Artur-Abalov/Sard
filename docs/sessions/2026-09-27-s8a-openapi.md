### Способ описания контракта без реализации — предложение
Контроллеры-заглушки на сервере с полными DTO и аннотациями springdoc,
тело каждого метода — 501 `not_implemented` (problem+json). Причины:
- один источник истины, как сейчас (ADR 0010, 0011): CI уже сверяет экспорт
  сервера с `openapi.json`, S8b меняет только тела методов;
- тест «перечисления совпадают с proto» — естественно в Kotlin: Java-enum
  proto уже на classpath сервера (`:proto-jvm`);
- спецификация-файл как источник истины перевернул бы ADR 0010 и потребовал
  бы в S8b либо генератора серверных интерфейсов (новая зависимость), либо
  теста «экспорт springdoc == файл» — двойная работа.
Минус: заглушки — серверный код под гейтом server (тесты на 501, мутации).

## Фаза 2 — спецификация, типы, проверки 1, 2, 4

### Решения и причины (подробно — ADR 0019)
- Контроллеры в `server/.../api` описывают все ресурсы; тело каждого — вызов порта (`SessionApi`, `AgentsApi`, `EnrollmentTokensApi`, `SourcesApi`, `RunsApi`), бины `Unimplemented*Api` отвечают 501 problem+json `not_implemented`. Первая версия бросала 501 прямо из контроллера — detekt `UnusedParameter` на всех параметрах; подавлять правило запрещено, порт — настоящий шов для S8b, у `override` detekt параметры не проверяет. Один бин на пять интерфейсов упёрся в `TooManyFunctions` — разделён, заодно W1b/S2b/S8b заменяют по одному.
- springdoc не выводит обязательность из nullability Kotlin (проверил на экспорте: `required` не было ни у одной схемы). Причина — swagger-core читает классы через Jackson 2, Kotlin-модуль есть только для Jackson 3 (`tools.jackson.module:jackson-module-kotlin` 3.1.5 в `runtimeClasspath`). `requireConstructorParameters` ставит `required` по параметрам первичного конструктора без значения по умолчанию. Swagger сам сортирует `required` по имени (`Schema.setRequired`).
- Перечисления — `@Schema(enumAsRef = true)` (без него springdoc встраивал enum в каждое свойство), значения — `@JsonProperty`.
- Метод с любой `@ApiResponse` терял неявный 200 (проверил экспортом: `GET /agents/{id}` — только 401 и 404). Добавлен явный `@ResponseStatus(OK)`, тест требует 2xx у каждой операции.
- `servers: [{url: "/"}]` вместо вырезания `servers` в экспорте; `/status` — `@SecurityRequirements` (пустое), иначе наследовал корневое требование и получал 401.
- `default` у `ttlSeconds` убран из схемы: openapi-typescript (`defaultNonNullable`) делал поле обязательным в TS.
- Линтер: `@redocly/openapi-core` 1.34.20 (та же версия, что уже стояла через openapi-typescript), `web/scripts/lint-api.mjs`, `web/redocly.yaml` (`recommended`), `npm run lint:api` входит в `npm run lint` → гейт web. Отключено `operation-4xx-response` — только `/status` без 4xx. **Вынесено на ревью.**
- Тест сериализации: каждый DTO, записанный мапером приложения (Jackson 3), сверяется со своей схемой в `/v3/api-docs` (имена, required, null, enum, uuid, date-time). Нужен, потому что схему строит Jackson 2. Попутно покрывает конструкторы и геттеры DTO: без него покрытие было 0.75 — DTO не создавались, а инструкции методов, заканчивающихся исключением, JaCoCo не засчитывает.

### Открытые вопросы
- Отключённое правило `operation-4xx-response` (см. выше).
- `?status=queued` в query: Spring конвертирует строку в enum через `valueOf` по имени константы (`QUEUED`), а в контракте значения строчные. Заглушки этого не видят (отвечают 501 до разбора?) — нет: разбор параметров идёт до вызова, запрос с `status=queued` получит 400. Решать в S8b конвертером по `@JsonProperty`.
