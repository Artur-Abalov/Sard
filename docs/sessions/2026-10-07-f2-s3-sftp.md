# Сессия 2026-10-07: бэкенды S3 и SFTP в e2e (F2)

Ветка `ccr-c87bbe0f-pxsnqo` (в задаче — `test/f2-s3-sftp`; решение владельца —
работать в назначенной), база — `main` @ `4f84861`.

## Решения владельца (до работы)

1. `ssh` для агента на стенде: если на живом хосте он не нужен — отдельный
   тестовый образ; иначе — зависимость живого пакета.
2. Пакет deb: `Depends` на клиент OpenSSH.
3. «Ограниченное время» отказа — не дольше таймаута шага; правки агента — не в F2,
   зависание — дефект в реестр (связать с OQ-137).
4. S3-хранилище стенда — на выбор исполнителя.
5. SFTP-сервер стенда — свой Dockerfile.
6. Документация — отдельная глава `docs/operator/`.
7. Примеры провайдеров (Yandex, VK Cloud, Selectel) не пишутся.
8. «Хранилище пропадает посреди бэкапа» — на `e2e-slow`.
9. Три прогона подряд — только для e2e-классов F2.
10. Ветка — назначенная.

## Фаза 1: выбор S3-хранилища, устройство SFTP

Пробы — руками, restic 0.19.1 из `.bin/restic`, контейнеры на этой машине.
Цифры времени — `time`, не оценки.

### S3: Garage v2.1.0

Полная цепочка `init → backup → restore → cmp` (3 МБ случайных данных) —
побайтово равна. Отказы:

| Случай | Сообщение restic | Время |
|---|---|---|
| ключ только на чтение, `backup` | `unable to create lock in backend: client.PutObject: Forbidden: Operation is not allowed for this key.` | 0,47 с |
| неверный секрет, `snapshots` | `Fatal: unable to open config file: Stat: Access Denied.` | 0,02 с |
| бакета нет, `snapshots` | `Is there a repository at the following location?` | 0,03 с |
| порт закрыт, `snapshots` | — (restic повторяет) | > 120 с, снят `timeout` |
| хранилище заморожено (`docker pause`), `snapshots` | — | > 120 с, снят `timeout` |

Замечание стенда: в `garage.toml` адреса `0.0.0.0`, не `[::]` — без IPv6 в
сети Docker Garage падает при старте (`netapp.rs:208`).

### SFTP: свой образ (Ubuntu 24.04 + openssh-server)

Полная цепочка — побайтово равна. Отказы:

| Случай | Сообщение | Время |
|---|---|---|
| ключа хоста нет в known_hosts | `subprocess ssh: Host key verification failed.` | 0,58 с |
| ключ пользователя не принят | `subprocess ssh: …: Permission denied (publickey).` | 0,59 с |
| каталог только на чтение, `init` | `MkdirAll …/keys: permission denied` | 0,80 с |
| каталога нет, `snapshots` | `Is there a repository at the following location?` | 0,68 с |

Факты, найденные пробой:

- **`ssh` нужен на живом хосте.** restic `sftp:` запускает внешний `ssh`
  (в образе агента `distroless/static` его нет: `exec: "ssh": executable file not found`).
  По решению 1 — `Depends: openssh-client` в пакете, а образ агента стенда
  получает клиент OpenSSH.
- **`HOME` агента не влияет на `ssh`.** Агент передаёт restic
  `HOME=<cache_dir>` (`agent/internal/restic/env.go:20`), но OpenSSH берёт
  домашний каталог из passwd (`ssh -v`: `load_hostkeys: fopen /root/.ssh/known_hosts`
  при `HOME=/c`). У пользователя службы это `/var/lib/sard-agent`
  (`deploy/agent/postinstall.sh:29`): ключ и `known_hosts` — в
  `/var/lib/sard-agent/.ssh/`.
- **Неизвестный ключ хоста отвергается** без терминала (под юнитом его нет) —
  за 0,6 с, с понятной причиной.
- Ubuntu: пользователь `backup` уже есть; учётная запись без пароля
  заблокирована, и sshd отвергает её ключ (`account is locked`) — пароль `*`.
- Сборка за прокси с подменой TLS: как в `deploy/server/Dockerfile`,
  необязательный секрет `build-ca`; apt читает его от `_apt`, поэтому
  `mode=0444`, источники — https.

### Сколько ждёт restic, когда хранилище недоступно

| Случай | Итог | Время |
|---|---|---|
| S3, порт закрыт, `snapshots` | `Fatal: unable to open config file: … connect: connection refused`, код 1 | 13 мин 52 с |
| S3, порт закрыт, `backup --retry-lock 5m` | то же, код 1 | 14 мин 23 с |
| S3, хранилище заморожено (`docker pause`), `snapshots` | не вышел, ни строки вывода; снят SIGKILL | > 25 мин |
| SFTP, порт закрыт | `ssh: connect to host sftp port 2200: Connection refused` | 0,49 с |
| SFTP, сервер заморожен (`docker pause`) | не вышел; SIGTERM от `timeout` restic принял («cleaning up»), но ждал закрытия сессии | > 16 мин, снят вручную |

Агент останавливает restic иначе, чем `timeout`: SIGTERM всей группе
(вместе с `ssh`), SIGKILL через 10 с (`agent/internal/restic/exec.go:67-68`).
Поэтому зависший restic агент снимет, но только по таймауту шага. Сервер
таймаут не передаёт (`DispatchParts.kt:41`), максимум агента — 24 ч
(`agent/internal/executor/executor.go:153`).

фиксирует текущее поведение. Garage и база Ubuntu приняты. ADR 0047 — принято.

## Фаза 2: полные цепочки

Сделано (`894ffdd`):

- Пакет: `Depends: openssh-client` (deb), `openssh-clients` (rpm).
  `package-agent.sh` проверяет это. Сначала красный — `make package` без
  правки `nfpm.yaml`: `Depends must be openssh-client`; потом зелёный. rpm
  проверяется только там, где есть `rpm` (CI); здесь его нет.
- Образ агента стенда: Ubuntu 24.04 + `openssh-client`, пользователь
  `sard-agent` (65532), домашний каталог `/var/lib/sard-agent`.
- Образ SFTP-сервера `test/e2e/sftp`. Собирается в `make e2e-agent-images`;
  переменные `E2E_SFTP_IMAGE`, `E2E_BUILD_FLAGS`.
- `GarageS3`, `SftpServer` — помощники стенда.
- `AgentHost`: `restore(env=…)`, `sshClient(knownHosts)` — `~/.ssh`,
  `known_hosts`, `ssh-keygen` от пользователя службы.
- `Chain` — общая часть `FullChainTest` (`ready`, `files`, `repository`) и
  новая `backupRestores`. Поведение `FullChainTest` не менялось: 4 из 4.
- `StorageChainTest`: S3 и SFTP — `repo init`, backend `s3`/`sftp` на сервере,
  бэкап через REST `succeeded`, снимок, `restic restore` — побайтово.

Проверка (`VERSION=f2local1`, образы собраны локально):

- `StorageChainTest` три раза подряд: 2/2, 2/2, 2/2 (47 с на прогон).
- `make e2e-test` целиком: exit 0, 56 тестов, 0 падений. Это проверка
  регрессий от смены базы образа агента.

Обходы этой среды (на CI не влияют):

## Фаза 3: отказы, блокировки, документация

### Пробы restic (до тестов)

Стенд проб: контейнеры Garage и `sard-sftp:e2e` в сети `f2`, клиент — restic
0.19.1 с `openssh-client`. Бэкап из stdin: 60 МиБ по 1 МиБ/с. С хранилищем
что-то делается на 8-й секунде.

| Проба | Итог | Время |
|---|---|---|
| A1: S3 остановлен на 8-й с, запущен на 40-й | `Save(…) operation successful after 3 retries`, снимок сохранён, код 0 | 63 с |
| A2: S3 вне сети (`docker network disconnect`) на 8-й с, не вернулся | `Save(…) returned error, retrying after …: lookup garage … no such host`, не вышел | > 20 мин, снят SIGKILL |
| A3: S3, имя не разрешается с начала | `Fatal: unable to open config file: … no such host`, код 1 | 14 мин 52 с |
| B1: SFTP остановлен на 8-й с, запущен на 40-й | `Fatal: unable to save snapshot: ssh command exited: exit status 255`, код 1 | 62 с (когда кончились данные) |
| B2: SFTP вне сети на 8-й с, без keepalive | ждал; на ~4-й мин я по ошибке вернул контейнер в сеть (проверка ниже), и бэкап завершился успешно | 269 с |
| B3: то же, `ServerAliveInterval 5`, `ServerAliveCountMax 3` в `~/.ssh/config` | `ssh command exited: exit status 255`, код 1 | 62 с |

Ошибка в пробах: чтобы проверить «Permission denied», я подключил `s1` к
сети во время B2 (`docker network connect` без `--alias`). B2 закончился не по
плану, а 20 прогонов той проверки упёрлись в разрешение имени и ничего не
показали. Проверка повторена с `--alias sftp`: 20 из 20 с «Permission denied».
Поведение B2 без keepalive в итоге доказано тестом (`StorageOutageTest`),
а не пробой.

Блокировки (restic напрямую):

- `restic check` берёт исключительную блокировку.
- Убитый `check` (`docker kill`) оставляет её: бэкап с `--retry-lock 20s`
  ждёт 20 с и пишет `repository is already locked exclusively by PID 1 on
  operator-pc`.
- Общие блокировки убитых бэкапов следующему бэкапу не мешают (1,4 с), но не
  дают выполнить `check`.
- `unlock` без `--remove-all` блокировки чужого хоста моложе 30 мин не
  снимает.

### Тесты

Новые классы (`test/e2e`):

- `StorageFailureTest` — 8 отказов;
- `StorageOutageTest` — 4 случая пропажи хранилища;
- `StorageLockTest` — 2 случая блокировок.

Описание — в `test/e2e/README.md`.

Помощники:

- `GarageS3.allow/deny`, `container`;
- `SftpServer.authorize/revoke` (набор ключей вместо перезаписи), `exec`,
  `container`;
- `AgentHost.launch` — команда оператора, которую тест прерывает;
- `Backups.logs`, `Backups.bytesProcessed`;
- `Await.during` — условие держится всё окно, опросом.

Что выяснилось по ходу:

- Первый прогон `StorageFailureTest` (8 случаев, причины печатались):
  - «бакета/каталога нет» был построен неверно: без `repo init` нет файла
    пароля, и шаг падал из-за него. Теперь файл пароля есть, нет
    бакета/каталога;
  - в сообщении шага причины нет у «только чтение» (S3, SFTP) и у всех
    отказов `ssh` — OQ-155;
  - «Permission denied (publickey)» не дошла даже в журнал в 1 из 3
    прогонов — OQ-155.
- `running` наступает до `restic cat`. Пропажа хранилища, устроенная по
  `running`, ударила по `cat`, а не по бэкапу. Теперь тесты ждут прогресс
  > 2 МиБ (`run_steps.bytes_processed`).
- Исключительная блокировка отказывает шагу сразу: `restic cat` до бэкапа без
  `--retry-lock` — OQ-156.

### Реестр

- OQ-154 — зависание на недоступном хранилище (связано с OQ-137);
- OQ-155 — причина не в сообщении или теряется;
- OQ-156 — `--retry-lock` не срабатывает;
- OQ-157 — `dpkg -i` и `Depends`.
