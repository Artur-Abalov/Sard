## Фаза 1.5 — инструменты качества и настройки Claude Code (добавлена владельцем)

Владелец потребовал: инструменты агентов (CRAP, сложность, мутационное тестирование) — до всей остальной работы; продуктовый код фаз 2–4 идёт через полную цепочку specifier → coder → cleaner → architect → hardener (не более 3 субагентов параллельно); конфигурация и инструменты — не через цепочку.

### Решения
- `tools/` — отдельный Go-модуль вне `go.work` (`GOWORK=off`): закрепляет версии buf, protoc-gen-go, protoc-gen-go-grpc, golangci-lint, go-mutesting через директиву `tool` и не влияет на граф зависимостей продуктовых модулей. `make tools` собирает всё в `.bin/`.
- `tools/cmd/crap` — своя утилита CRAP на stdlib (Go-профиль покрытия + цикломатика по AST в стиле gocyclo; JaCoCo XML со счётчиком COMPLEXITY). Написана заново, `crap.py` из исходного репозитория не копировался (код исходного репозитория вне области переноса).
- Пороги как в исходном проекте: покрытие ≥ 80%, CRAP ≤ 6, цикломатика ≤ 8, мутационный score ≥ 0.80. Определены один раз в `scripts/gate.sh`.
- Покрытие сервера — JaCoCo (встроен в Gradle, даёт COMPLEXITY для CRAP), а не Kover: на одну зависимость меньше.
- Мутационное тестирование Go — `avito-tech/go-mutesting` (MIT; релизных тегов нет, псевдоверсия v0.0.0-20251226130216-48d0401f00fb). gremlins отвергнут: последний релиз в мае 2024.
- detekt: 2.0.0-alpha.6 (решение владельца), при неудаче — 1.23.8.
- pitest отвергнут владельцем по опыту. Замена для Kotlin — открытый вопрос (см. ниже).
- Хуки: `scripts/claude/guard.sh`, `guard-edit.sh`, `on-edit.sh` написаны заново по идее исходных; хуки graphify не переносятся.

## Фаза 2 — корень, proto, агент, CLI

Владелец решил: каркас целиком (фазы 2–4) делается без цепочки агентов, но с `scripts/gate.sh` и исправлением всех его находок. Запущенный было specifier остановлен, файлов не оставил.

### Решения
- Лицензии: `LICENSE` — текст AGPL-3.0 в оформлении gnu.org (копия из github/choosealicense.com; gnu.org закрыт прокси), пословно сверен с SPDX `AGPL-3.0-only.txt` — различаются только `http`/`https`. Apache-2.0 — с apache.org (sha256 `cfc7749b…`).
- `agent.proto`: `AgentService.Register` (hostname, agent_version, plugins с JSON Schema → agent_id) и `Connect` (поток агент → сервер: `Heartbeat`, `StepResult`; сервер → агент: `RunStep`). SPDX-заголовок `.proto` переносится в сгенерированные файлы — `license-check` проходит и по ним.
- `replace` в `agent/go.mod` на `./plugins/sdk` и `../proto/gen/go`: модуль собирается и без `go.work` (CI, Docker, `go mod tidy`).
- `crypto.Provider` + `resticAES` (ADR 0008); `restic.New` принимает `crypto.Provider`.
- `plugins.Registry()` паникует при дубликате имён: список плагинов статический, ошибка — программистская и ловится контрактным тестом; иначе в `main` был бы недостижимый путь (его нашёл мутант).
- `main` агента получает `os.Hostname` как функцию — путь ошибки тестируется.
- Покрытие в `gate.sh` считается с `-coverpkg=<пакеты модуля>`: плагины покрываются контрактным тестом из пакета `plugins`. Вложенные модули в покрытие и в `crap` не попадают (исправлено в `crap`: пропуск каталогов со своим `go.mod`).
- Архитектурный тест `agent/plugins/sdk/imports_test.go`: SDK не зависит от AGPL-пакетов. Он нужен: по правилу `internal` Go пакет `agent/plugins/sdk` формально может импортировать `agent/internal/...`, так как лежит под `agent/`.

### Находки шлюза и исправления
- gocyclo > 8 в двух тестах агента — тесты разделены.
- Мутации агента 0.905 → 0.952: добавлены тесты «неизвестный флаг после --config», «ошибка hostname»; убран недостижимый путь ошибки реестра. Оставшиеся 2 выживших эквивалентны (`stop()` перед `os.Exit`; `panic` на недостижимом пути).
- Мутации CLI 0.692 → 1.0: у пакета `internal/commands` не было своих тестов (go-mutesting гоняет тесты только мутированного пакета); найден лишний `SetErr` — удалён.

## Фаза 3 — сервер (2026-09-27)

Владелец выбрал mutflow для мутационного тестирования Kotlin. Сессия перезапускалась: Docker-демон запущен заново, в окружении (не в репозитории) настроено зеркало `mirror.gcr.io` для Docker Hub.

### Решения
- См. ADR 0006 (mutflow) и ADR 0010 (стек сервера). Итоговые версии: Gradle 9.7.1 (последний патч 9.7), Spring Boot 4.1.1, Kotlin 2.4.20, JDK 25 (25.0.4), protobuf-gradle-plugin 0.10.0, grpc-java 1.83.1, grpc-kotlin 1.5.0, protobuf-java/protoc 4.35.1, springdoc 3.1.1, Flyway 12.4.0, Hibernate 7.4.5, Testcontainers 2.0.5, JaCoCo 0.8.15, detekt 2.0.0-alpha.6, Spotless 8.10.3 (ktlint 1.8.0), mutflow 1.5.0, PostgreSQL 18 (образ `postgres:18-alpine`).
- В `.proto` добавлены `java_package = "dev.sard.proto.agent.v1"` и `java_multiple_files`; Go-код не изменился (buf managed mode и так задаёт Java-опции в дескрипторе).
- `deploy/`: multi-stage Dockerfile, compose (PostgreSQL + сервер, healthcheck'и), `.env.example`, systemd-юнит и пример конфига агента.

### Что пробовал и отверг
- Генерация proto прямо в `server` вместе с mutflow → `Invalid state: INIT` на `generateMutatedMainProto`. Вынесено в `:proto-jvm`.
- `-Pkotlin.compiler.runViaBuildToolsApi=false` для обхода падения компиляции `proto-jvm` — не помогло; настоящая причина — BOM Spring подменял Kotlin на 2.3.x (исправлено `bomProperty`).
- Configuration cache Gradle — protobuf-gradle-plugin несовместим, выключен.

### Находки шлюза и исправления
- detekt: 4 строки > 120 символов в тестах — переформатированы.
- JaCoCo 0.72 < 0.80: не покрыты сущность `Agent` (добавлен round-trip через репозиторий — заодно проверяет соответствие маппинга миграции), неиспользуемый `ScheduledRun` (удалён), геттер логгера в companion (логгер вынесен в top-level).
- mutflow: `processMutatedMainResources` без зависимости от `bootBuildInfo` — зависимость добавлена.

### Проверено (команды запускались)
- `./scripts/gate.sh server` — PASSED: spotless, detekt, 15 тестов, покрытие ≥ 80% (JaCoCo), CRAP максимум 2.0, mutflow: `ExtensionRegistry` 4/4 убито, `StatusController` 0 мутаций (ограничение операторов, см. ADR 0006).
