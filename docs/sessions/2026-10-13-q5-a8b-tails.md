## OQ-162: откуда шаг и почему он ломается

- Шаги мастера строит сервер (проверил): `install/InstallCommands.kt:43-50`,
  `StepKind` в `install/InstallTypes.kt:34-45` и `api/InstallWire.kt` (провод
  `repo-init`), отдаёт `GET /api/v1/agent-install`. Web лишь рисует
  (`components/InstallSteps.tsx`, ключи `install.steps.<kind>.title|text`), тест
  `web/src/locales/install.test.ts` требует перевод на каждый `StepKind`.
- Шаг: `sudo -u sard-agent sard-agent repo init --generate-password main`
  (`InstallCommands.kt:17,49`). Пример конфига репозиториев не содержит
  (`deploy/agent/agent.example.yaml:24`, страж `agent/internal/config/example_test.go`),
  так что шаг падает с `REPOSITORY_UNKNOWN`.
- `scripts/test-console-install.sh:148-168` (`edit_repository`) вписывает
  `main` в `agent.yaml` руками — поэтому релизная проверка этот дефект не ловит.
- Общего построителя команды `repo add` нет ни в web, ни на сервере
  (по исследованию: `git grep "repo add|repoAdd|--provider"` по `web/src`,
  `server/src/main` пуст). F6 привязывает репозиторий через
  `PUT /api/v1/self-backup/repository`, команда самобэкапа есть только в
  `docs/operations/self-agent.md:13`. Блок «Добавить хранилище» — срез A8e
  (`docs/specs/agent/host-setup.feature:83-85`).
- `repo add` локального пути сам создаёт репозиторий, пароль, фрагмент agent.d
  и разрешение записи для службы (`docs/operations/agent-install.md:90`) — т. е.
  заменяет и `repo init`, и `edit_repository` целиком.

## Список замен (черновик к ревью)

1. **Сервер.** `asServiceUser` → `asRoot`/`agentCommand` = `sudo sard-agent …`.

   уже поддерживает регистрацию под sudo). `StepKind.REPO_INIT` → `REPO_ADD`

   имени пользователя sard-agent» → под sudo).
