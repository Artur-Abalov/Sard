## OQ-162: откуда шаг и почему он ломается

- Шаги мастера строит сервер (проверил): `install/InstallCommands.kt:43-50`,
  `StepKind` в `install/InstallTypes.kt:34-45` и `api/InstallWire.kt` (провод
  `repo-init`), отдаёт `GET /api/v1/agent-install`. Web лишь рисует
  (`components/InstallSteps.tsx`, ключи `install.steps.<kind>.title|text`), тест
  `web/src/locales/install.test.ts` требует перевод на каждый `StepKind`.
- Шаг: `sudo -u sard-agent sard-agent repo init --generate-password main`
  (`InstallCommands.kt:17,49`). Пример конфига репозиториев не содержит
  (`deploy/agent/agent.example.yaml:24`, страж `agent/internal/config/example_test.go`),
  так что шаг падает с `REPOSITORY_UNKNOWN`.
- `scripts/test-console-install.sh:148-168` (`edit_repository`) вписывает
  `main` в `agent.yaml` руками — поэтому релизная проверка этот дефект не ловит.
- Общего построителя команды `repo add` нет ни в web, ни на сервере
  (по исследованию: `git grep "repo add|repoAdd|--provider"` по `web/src`,
  `server/src/main` пуст). F6 привязывает репозиторий через
  `PUT /api/v1/self-backup/repository`, команда самобэкапа есть только в
  `docs/operations/self-agent.md:13`. Блок «Добавить хранилище» — срез A8e
  (`docs/specs/agent/host-setup.feature:83-85`).
- `repo add` локального пути сам создаёт репозиторий, пароль, фрагмент agent.d
  и разрешение записи для службы (`docs/operations/agent-install.md:90`) — т. е.
  заменяет и `repo init`, и `edit_repository` целиком.

## Список замен (черновик к ревью)

1. **Сервер.** `asServiceUser` → `asRoot`/`agentCommand` = `sudo sard-agent …`.
   `enrollCommand` = `sudo sard-agent enroll --server … --token …` (Р25 в A8a
   уже поддерживает регистрацию под sudo). `StepKind.REPO_INIT` → `REPO_ADD`
   (провод `repo-add`) с командой `repo add` (форма — вопрос 1). Серверный тест
   из OQ-162: шаги установки не ссылаются на репозиторий, который никто не
   создал. Описание OpenAPI `EnrollmentTokensController.kt:45`. Тесты: 8 мест.
2. **Web.** `npm run gen:api`; моки `mocks/api/install.ts:61-67`,
   `mocks/api/tokens.ts:64`, `mocks/contract.typecheck.ts:46`,
   `mocks/handlers.test.ts:372,492`, `install.test.ts:17,35`; i18n ru/en:
   `install.steps.repo-add`, текст `install.steps.enroll` («выполняйте от
   имени пользователя sard-agent» → под sudo).
3. **Скрипты.** `test-agent-install.sh:14-15,182,190` → `sudo sard-agent enroll`,
   `sudo sard-agent repo add main /srv/sard-repo/main`;
   `test-console-install.sh` — убрать `edit_repository`, шаги
   `enroll repo-add start`.
4. **Документы (живые).** demo.md:189,206-207 (обход OQ-162 убрать);
   plugins/postgresql.md:97 (`tee` → `sudo sard-agent secret set --stdin`);
   specs server/web (agent-enrollment, agent-install, ca-import, rest-api,
   web/agent-install) и qa (agent-enroll, agent-enrollment, agent-install,
   rest-api) — ожидаемая команда; open-questions.md OQ-162 → закрыт.
5. **Оставить с комментарием** (вопрос 3): demo.md:314 (`restic snapshots`/
   `restore`), operator/05a-storage.md:379 (`restic unlock`, исключение П18),
   qa/host-setup.md:70,99,104,239,465-466 (проверки отказа и атаки — `sudo -u`
   здесь и есть предмет теста), qa/postgresql-plugin.md:196-197 (`sudo -u nobody`),
   qa/repo-init.md:361-396 (ветка «запуск от пользователя службы» Р24).
6. **Не трогать.** docs/sessions, docs/adr (история); тесты-стражи отсутствия
   в agent и scripts; формулировки «`sudo -u` нет» в specs (host-setup.feature
   :2413,2513-2519) — они и есть требование.
7. **Проверка в CI.** `scripts/check-sudo-u.sh` по образцу

   меткой разрешения; цель `make check-sudo-u` в `lint`; шаг в `docs.yml` и в
   задаче `licenses` в `ci.yml` (`ci.yml` не запускается на изменения только
   документации). Тест скрипта: временная копия с внесённым `sudo -u` → exit 1.

## Вопросы владельцу и ответы

Ответ владельца на все шесть: «Я согласен с твоими решениями. Пока делай то
что есть». Решено:

1. Шаг мастера — готовая команда сервера для локального пути
   (`sudo sard-agent repo add main /srv/sard/main`); форма для s3/sftp — A8e.
2. Команда регистрации — `sudo sard-agent enroll` (риск агента до A8a принят:
   мастер ставит текущий пакет).
3. Исключения с пометкой: `demo.md` (`restic` до A8c), `05a-storage.md`
   (`restic unlock`, П18), QA-проверки отказа, чтения и атак.
4. Проверка в CI: всё, кроме истории; остальное — с пометкой `allow-sudo-u:`.
5. Спецификации и QA правятся; ADR и журналы — нет (кроме дополнения ADR 0050,
   см. ниже).
6. Ветка — назначенная сессии.

Вопрос «станет ли задача актуальнее после A8c, A8d»: нет. От A8c зависит одно
исключение (`demo.md`, `repo snapshots/restore`), A8d не связан; реальное
пересечение — с A8e (общий построитель команды).

## Фаза 2: что сделано

Конвейер `/quick-fix`: coder → cleaner → architect. Новых `.feature` нет —
поправлены сценарии существующих (решение Р4 в
`docs/specs/server/agent-install.feature`). `hardener` не запускался.

- **Сервер.** `agentCommand` (`enrollment/AgentEndpoint.kt`) собирает
  `sudo sard-agent …`; `StepKind.REPO_INIT` → `REPO_ADD` (провод `repo-add`);
  тесты: ни одна команда шагов не содержит `sudo -u`; шаги не ссылаются на
  репозиторий, которого никто не создал (OQ-162).
- **Web.** `openapi.json`/`schema.d.ts` перегенерированы (`make openapi`),
  моки, строки ru/en шага `repo-add` и `enroll`.
- **Скрипты.** `test-agent-install.sh` и `test-console-install.sh` — команды
  `sudo sard-agent`; ручная правка `agent.yaml` (`edit_repository`) удалена.
- **Проверка в CI.** `scripts/check-sudo-u.sh` и его тест
  `scripts/test-check-sudo-u.sh`: в `make lint`, задаче `licenses` в `ci.yml` и
  задаче `sudo-u` в `docs.yml`. Пропускаются только `docs/sessions` и
  `docs/adr`; ловит `sudo -u`, `-iu`, `-Hu`, `--user`; строка допустима с
  `allow-sudo-u: <причина>` на ней или строкой выше. Первая версия исключала
  целиком `docs/specs` и `docs/qa` — архитектор (F4) указал, что это расходится
  с согласованным, и регрессия команды консоли в них прошла бы; исправлено,
  23 строки помечены.
- **Документы.** ADR 0050 — дополнение «Команды консоли (Q5)»; OQ-162 закрыт;
  открыт OQ-201 (`RepoInitHint` сам собирает `sard-agent repo init` без
  `sudo` — нужно поле API, вне объёма quick-fix; находка архитектора F3).
  `docs/plugins/postgresql.md` — секрет через `sudo sard-agent secret set`.

Счёт `sudo -u` вместо ожидавшихся 13 — 107 строк; оставшиеся вне истории — с
пометкой.
