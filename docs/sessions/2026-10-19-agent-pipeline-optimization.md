### Базовый прогон `/quick-fix` (измерено)
Задача: `crap.Write` при пустом `rows` печатает заголовок и строку
`no functions measured`. Прогон на локальной ветке `throwaway/baseline-before`
(не публиковалась, удалена); тот же diff сохранён вне репозитория, повтор в фазе 4
идёт на свежей ветке от того же коммита `8891f5c`. Правка: +4 строки в `crap.go`,
+14 в `crap_test.go`.

Цифры из блока usage уведомления о завершении агента (`subagent_tokens`,
`tool_uses`, `duration_ms`):

|---|---|---|---|---|
| coder | 16 259 | 7 | 146 442 | `gate.sh tools fast` PASSED, покрытие 100.0%, `Write` CRAP 6.0 |
| cleaner | 12 998 | 2 | 123 194 | правок нет, gate PASSED |
| architect | 26 369 | 5 | 101 927 | `STRUCTURE ACCEPTED`, замечаний нет |
| **Итого** | **55 626** | **14** | **371 563** | |

Замечания по прогону:
- Результат вызова `Agent` для фоновых агентов usage не содержит; блок приходит
  только в уведомлении о завершении. Правило 4 в командах должно брать цифры оттуда.
- Новая ветка `len(rows) == 0` — формально «новое ветвление». Решено, что мутационного
  покрытия она не требует (одна проверка, тест на пустой ввод убивает мутант);
  `hardener` в `/quick-fix` не запускался. Architect рекомендовал hardener для
  `crap.go` — это его мнение, не вердикт шлюза.
- После правки `Write` стоит ровно на пороге CRAP 6.0 (CC 6, покрытие 100%).
  Это хорошая иллюстрация, почему cleaner должен работать только с файлами диффа.

Вторичный источник (по транскриптам `agent_transcript_path`, скрипт вне репозитория):
tool_uses 7 / 2 / 5 совпадают с блоком usage; длительности по меткам времени
транскрипта (17 / 10 / 38 с) **не совпадают** с `duration_ms` (146 / 123 / 102 с),
токены вывода в транскрипте занижены (запись идёт во время стриминга). Для отчёта
используется только блок usage.

### Дополнительная находка (не из исходного списка)
Локальный `origin/main` в облачной сессии был устаревшим (`928507d` вместо `8891f5c`).
Из-за этого `gate-changed.sh --dry-run` выбирал **все 8 модулей** на чистом дереве;
после `git fetch origin main` — ни одного. Если так бывает в каждой сессии, каждый
SubagentStop запускает полный fast-гейт всех модулей — вероятно, крупнейшая статья
времени. Не проверено, как часто это происходит. Чинится одной строкой
(`git fetch origin main` в `.claude/hooks/session-start.sh`, не защищённый файл, но вне
согласованного списка правок) или в патче `gate-changed.sh`. **Открытый вопрос владельцу.**
